Your own types

Your compiler will be built out of one kind of thing: a node, a small value that says what one step of a program does. Python has no node type, so in this lesson you make one. You'll also learn to tell two equal nodes from one node with two names, because week 1 depends on that difference.

Goal

Define a small node type, build a tree out of it, and tell == (equal) from is (the very same object).

A dict lets a typo through

In the start steps, every line of a program was a box in a picture. A compiler keeps each box as a value called a node. A node has three parts:

  • op: what the node does, like "add".
  • src (short for sources): the list of nodes it reads.
  • arg: one extra piece of data, such as the number in a constant. Most nodes have none.

A tuple could hold the three parts, but you just saw that line[1] hides its meaning. A dict gives each part a name. Here is one. Read it closely, because one key is spelled wrong:

node = {"op": "add", "scr": [], "arg": None}

Guess first. When does Python complain about "scr"?

A dict accepts any key you give it.

Later. The line runs with no complaint. The error is KeyError: 'src', and it shows up wherever the node is first read, which may be far from the mistake.

So a dict has two problems. Nothing checks its keys. And nothing says that this dict is a node: to Python it is a dict like any other.

The fix is to make a new type. A type is a kind of value: int, str and list are types. A type of your own has a name, and a fixed set of named parts called fields.

A class: a name and fixed fields

A class is the recipe for a new type. Each value made from the recipe is an object.

class Node:
    def __init__(self, op, src, arg):
        self.op = op
        self.src = src
        self.arg = arg
  1. Name the type. class Node: starts the recipe. Class names start with a capital letter by habit.
  2. Write the setup function. __init__ has two underscores on each side. Python runs it every time you make a Node, and its job is to fill in the fields.
  3. Fill each field. self is the new object. self.op = op stores the argument in a field called op.

To make a node, call the class like a function. To read a field, use a dot:

n = Node("const", [], 7)
print(n.arg)
7

You pass three arguments and __init__ has four parameters. The extra one is self, which Python fills in for you.

Now there are no keys to misspell when you build a node. And a misspelled field is caught where you read it, with a message that names the type: n.scr gives AttributeError: 'Node' object has no attribute 'scr'.

What does Node("add", []) do, with the class above?

__init__ asks for op, src and arg. Count what was passed.

TypeError: Node.__init__() missing 1 required positional argument: 'arg'. A node can't be built with a part missing, and the error is on the line with the mistake.

Every function inside a class takes self first. Leave it out and write def __init__(op, src, arg):. Python still passes the new object first, so there is one argument too many: TypeError: Node.__init__() takes 3 positional arguments but 4 were given. When an error counts one more argument than you wrote, look for a missing self.

A dataclass: the short way

The class works, but it has two rough edges. __init__ made you type every field name three times. And printing a node shows nothing useful:

print(n)
<__main__.Node object at 0x000001BD8E6A4310>

That is the class name and the object's address in memory. A dataclass fixes both. You list the fields, put @dataclass on the line above the class, and Python writes __init__ and a readable printout for you:

from dataclasses import dataclass

@dataclass
class Node:
    op: str
    src: list
    arg: int | None = None
print(Node("const", [], 7))
print(Node("add", []))
Node(op='const', src=[], arg=7)
Node(op='add', src=[], arg=None)
  • The first line loads dataclass from a module that comes with Python. P.6 explains imports. For now, copy the line.
  • : str is a type hint, like the ones on def lines. It says what kind of value belongs in the field. int | None means an int or None.
  • = None is a default. Leave arg out and it is None.

The hint says arg is an int or None. What does Node("const", [], "seven") do?

A hint is a note for the reader and for your editor.

It builds the node. Python does not check hints when it runs. Your editor reads them and can warn you.

Write the node type

Type it yourself. Make Node a dataclass with the fields op, src and arg, where arg may be left out.

Then write the helper lit(v). It returns the node for the number v: the op is "const", there are no sources and the arg is v. The name is short for literal, a number written straight into a program.

Writing the printout by hand with __repr__, for a class that is not a dataclass

To choose the printed text yourself, add a function called __repr__ to the class. It takes only self and returns a string. The name is short for representation.

class Book:
    def __init__(self, title, year):
        self.title = title
        self.year = year

    def __repr__(self):
        return f"Book({self.title!r}, {self.year})"
print(Book("Dune", 1965))
Book('Dune', 1965)

The !r inside the f-string means "show this value the way you would type it in code", so strings keep their quotes. A good __repr__ looks like the code that would build the object, which makes error messages easier to read.

A line that starts with @, like @dataclass, is a decorator: it takes the class or function below it and changes it.

Equal, or the very same object?

Python can ask two different questions about two values. a == b asks "are they equal?" and a is b asks "are they the very same object?" Try both on two nodes built the same way:

a = lit(2)
b = lit(2)
c = a

Guess first. What are a == b and a is b?

How many times did lit run? Each call builds a new object.

True and False. A dataclass's == compares the fields, and they match. But lit ran twice, so there are two objects.

Think of two printed copies of one book. They are equal: the same words on every page. They are not the same book: write in one and the other stays clean. == asks "same words?" and is asks "same book?"

a is c is True. c = a builds nothing. It is two names for one object, like the two names for one list in the warm up. Step through the picture.

The dataclass changed the first answer. With the hand-written class from earlier, a == b is False, because a plain class's == means the same as is. @dataclass writes an == that compares the fields. Writing @dataclass(eq=False) turns that off again, and you'll see week 1's node do that.

Why the course cares

== on a big tree compares every field of every node, all the way down. is takes one step. In week 1 you'll arrange things so that equal nodes are always the same object, and then is is all you need.

Equal, or the same node?

shared(n) should say whether a node's two sources are the very same object. square(lit(3)) puts one node in the list twice, so the answer is True. Node("mul", [lit(3), lit(3)]) holds two equal nodes, so the answer is False. The function asks the wrong question. Repair it.

Walk the tree to get its value

The tree holds (2 + 3) * 4, but the number 20 is nowhere in it. A function has to work it out by visiting the nodes.

Guess first. You are at the mul box at the bottom. What do you need before you can multiply?

One source of the mul is the add box, which is not a number yet.

The value of each source: 5 from the add and 4 from the leaf. The add needs its own sources first, in the same way.

That is the whole plan, and it fits in one function:

def value(n):
    if n.op == "const":
        return n.arg
    a = value(n.src[0])
    b = value(n.src[1])
    if n.op == "add":
        return a + b
    if n.op == "mul":
        return a * b
    raise ValueError(n.op)
  1. Answer a leaf. A const node is worth the number in its arg.
  2. Ask each source. value calls itself on the two sources. Each call gets a smaller tree, so the calls end at the leaves.
  3. Apply the op. By now a and b are plain numbers.
  4. Refuse the rest. raise stops the function with an error you choose, so a misspelled op is loud.

Step through it on your tree and watch the values arrive.

A function that calls itself is called recursion. The next lesson is all about it, and there you write such functions from scratch. Here you only extend one.

Methods, and fields that cannot change

Two more tools before you leave classes. In P.3 you called methods such as scores.append(100). Now you write one: a method is a function that lives inside a class and works on one object. And frozen=True makes a dataclass's fields read-only:

import math
from dataclasses import dataclass

@dataclass(frozen=True)
class Point:
    x: float
    y: float

    def length(self):
        return math.sqrt(self.x ** 2 + self.y ** 2)
p = Point(3, 4)
print(p.length())
p.x = 5
5.0
dataclasses.FrozenInstanceError: cannot assign to field 'x'

In p.length(), the object before the dot becomes self, so self.x is 3. math.sqrt takes a square root.

A value that can't change is immutable, like a string or a tuple. That makes it safe to share: no other name for the same object can change it behind your back. To "move" a frozen point you build a new one, Point(p.x + 1, p.y).

A frozen dataclass can also go in a set or be a dict key, as a tuple can. One that is not frozen can't.

With the frozen Point, what is len({Point(1, 2), Point(1, 2)})?

A set keeps one of each value. Are the two points equal?

1. The two points are equal, because a dataclass compares fields, and a set keeps only one of two equal values.

A frozen point with a distance

The starter has a Point dataclass with fields x and y. Make it frozen, and write the method distance(self, other): the straight-line distance between the two points, √((x₁ − x₂)² + (y₁ − y₂)²). Point(0, 0).distance(Point(3, 4)) is 5.0.

One hidden test puts two equal points in a set, which only works for a frozen dataclass.

How a dict files its keys, and why only values that cannot change may be keys

Dicts and sets find things fast because they don't search. Each key is turned into a number called its hash, and the hash says which drawer the key is filed in. To look a key up, Python computes its hash, opens that one drawer and checks with ==. A value that can be hashed is hashable.

Suppose you filed a list as a key and then appended to it. Its hash would change, but it would still sit in the old drawer, and a lookup would open the new drawer and find nothing. So the built-in types that can change (lists, dicts and sets) refuse to be keys, and so does a dataclass that is not frozen:

print({(1, 2): "a"})
print({[1, 2]: "a"})
{(1, 2): 'a'}
TypeError: unhashable type: 'list'

The set {lit(2)} stops the same way, with unhashable type: 'Node'.

A frozen dataclass is hashable. Its hash comes from its fields, so equal points land in the same drawer:

print(hash(Point(1, 2)) == hash(Point(1, 2)))
seen = {Point(0, 0): "start"}
print(seen[Point(0, 0)])
True
start

Frozen only goes one level deep. A frozen dataclass with a list field can still be changed through the list, and hashing it fails with unhashable type: 'list'. If a frozen class needs a sequence, use a tuple: srcs: tuple, not srcs: list.

A fixed list of choices

The node type still has one weak spot. Look at the op in this line:

bad = Node("ad", [lit(2), lit(3)])

Guess first. What does Python do on that line?

The op field holds a string. Which strings are allowed?

It builds the node. Any string is a good string. The mistake only shows later, when value(bad) stops with ValueError: ad.

It is the dict typo again, one level down. When a value must come from a short, fixed list of choices, use an enum (short for enumeration). It gives each choice a name:

from enum import Enum

class Op(Enum):
    CONST = 1
    ADD = 2
    MUL = 3

Now you write Op.ADD where you wrote "add", and compare with n.op == Op.ADD. A typo such as Op.AD is an AttributeError on the line where you typed it. The numbers only need to differ from each other. Op.ADD == 2 is False: an enum member equals only itself, so it can't be mixed up with a number.

One class per kind of node, and match

There is a second common way to build a tree, and P.5's exercises use it. In place of one Node type with an op field, you write one small class for each kind of node. Each class has exactly the fields it needs:

@dataclass(frozen=True)
class Num:
    value: int

@dataclass(frozen=True)
class Add:
    left: "Expr"
    right: "Expr"

@dataclass(frozen=True)
class Mul:
    left: "Expr"
    right: "Expr"

Expr = Num | Add | Mul

The last line names the idea "any of these three", so the hints can say Expr. Then (2 + 3) * 4 is Mul(Add(Num(2), Num(3)), Num(4)).

To work out a value you now ask which class a node is, and then read its fields. match does both at once:

def evaluate(e):
    match e:
        case Num(v):
            return v
        case Add(left, right):
            return evaluate(left) + evaluate(right)
        case Mul(left, right):
            return evaluate(left) * evaluate(right)
        case _:
            raise TypeError(f"not an expression: {e!r}")
  1. Try each case from the top. The first one that fits runs, and the others are skipped.
  2. Test the class and name the fields. case Num(v): reads "if e is a Num, call its first field v". case Add(left, right): names both fields, in the order the class lists them.
  3. Catch the rest. case _: fits anything. Raising there makes a forgotten case loud, and {e!r} puts the odd value in the message.

Which case runs first in the call evaluate(Mul(Add(Num(2), Num(3)), Num(4)))?

The cases test e itself, not what is inside it. What class is the outermost object?

The Mul case. The outermost object is a Mul. That case then calls evaluate on the Add and on Num(4), and those calls pick their own cases.

More on match: plain values, isinstance, quoted hints and the trap of missing parentheses

Plain values. A case can hold a plain value, and then match compares with it:

def describe(n):
    match n:
        case 0:
            return "zero"
        case 1:
            return "one"
        case _:
            return "many"

print(describe(1))
print(describe(7))
one
many

isinstance. isinstance(x, C) answers "is x an object of class C?" So isinstance(Num(1), Num) is True and isinstance(Num(1), Add) is False. You could write evaluate as if isinstance(e, Num): ... elif isinstance(e, Add): ... and read the fields with dots. A case Num(v): is called a class pattern, and it does the test and the reading together.

Quoted hints. The hints "Expr" are in quotes because Expr doesn't exist yet when Python reads those lines.

Parentheses after the class name. case Num: without parentheses doesn't test the class. A bare name in a pattern is a capture: it matches anything and stores it in a variable called Num. Python notices when cases follow it and stops with SyntaxError: name capture 'Num' makes remaining patterns unreachable. To match a class without naming its fields, write case Num():.

Two words you'll meet in week 1. Turning text such as (2 + 3) * 4 into a tree is called parsing. Walking the tree to get an answer is interpreting it.
