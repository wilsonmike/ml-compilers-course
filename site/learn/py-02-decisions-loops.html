Learn Python · Lesson 2

Decisions, loops and functions

So far your programs run every line once, top to bottom. In P.1 you filled in functions that were already started. This lesson adds three things: functions you write from the first line, if, which chooses which lines run, and a loop, which runs lines again. With those three you can write the first piece of your compiler.

Goal

Read and write a function that picks a calculation by name, and a loop that visits every item.

You'll use

Values, names, arithmetic and strings from P.1.

What is 10 % 3?

% gives what is left over after dividing.

3 fits into 10 three times, which makes 9, and 1 is left over. When n % 3 is 0, nothing is left over, so 3 divides n exactly. You'll need that below.

Name a calculation

A shop charges the price times the count, plus 5 for shipping. Here are three orders:

print(3 * 4 + 5)
print(2 * 10 + 5)
print(6 * 1 + 5)

Shipping goes up from 5 to 7. How many lines of that program do you have to edit?

Count the lines that contain + 5.

All 3. With 300 orders it would be 300 edits, and missing one gives a wrong bill.

The fix is to write the calculation once and give it a name. As in P.1, a function is a named piece of code that takes values in and hands one back.

def total(price, count):
    return price * count + 5

print(total(3, 4))
print(total(2, 10))
print(total(6, 1))

This prints 17, 25 and 11. Now shipping lives in one place.

The def line starts the function. It gives the name, total, and in parentheses the parameters: names for the values that will come in. The line ends with a colon. The lines under it are the body. They are indented, pushed right by 4 spaces, and that is how Python knows they belong to the function. return hands a value back.

Writing total(3, 4) is a call, and 3 and 4 are its arguments. It runs the body. You have been calling a function all along: print. Here is what one call does:

  1. Match the names. price points at 3 and count points at 4.
  2. Run the body. 3 × 4 + 5 is 17.
  3. Hand the value back. The call total(3, 4) becomes 17, so the line is now print(17).

The def alone runs nothing. It only stores the body under the name. The body runs each time you call.

With the total above, what is total(2, 3) + 1?

Work out the call first. It becomes one number.

total(2, 3) is 2 × 3 + 5, which is 11. The call stands for 11, and 11 + 1 is 12.

In the exercises on this page, the def line carries type hints, like price: int and -> int. They say what type goes in and what type comes back. Python ignores them when it runs, so read past them for now.

Names inside a function, for when a NameError surprises you

A name made inside a function is a local variable. It exists only while that call runs. The part of the code where a name can be seen is its scope. Parameters are local too.

def total_cost(price, count):
    subtotal = price * count
    return subtotal + 5

print(total_cost(3, 4))
print(subtotal)

This prints 17, then stops with NameError: name 'subtotal' is not defined. That is a good thing. Two functions can both use a name like count without stepping on each other.

A function can read a name made at the top level of the file, called a global. But if the function assigns to a name anywhere in its body, Python treats that name as local for the whole function, and this fails:

count = 0

def bump():
    count = count + 1

bump()
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

Python 3.10 words it local variable 'count' referenced before assignment. The fix is to pass the value in as a parameter and return the new one: count = bump(count).

Call a function with too few values and Python names the missing one: total_cost(3) gives TypeError: total_cost() missing 1 required positional argument: 'count'.

Type hints, the notes on a def line 
def area(width: int, height: int) -> int:
    return width * height

Read width: int as "width is an int" and -> int as "returns an int". A function that returns nothing is marked -> None. Python ignores them when it runs, so area("ab", 3) happily gives 'ababab'.

They are for you and your editor. They say what a function expects in a form you can read at a glance. VS Code uses them to show types when you hover over a name, and it can underline a call that passes the wrong kind of value once you set Python › Analysis: Type Checking Mode to basic in Settings.

One function calling another, step by step

When one function calls another, Python remembers where it was in the first, runs the second to its return, and comes back with the value. Each running call has its own set of local variables, called a frame.

def square(n):
    return n * n

def sum_squares(a, b):
    return square(a) + square(b)

print(sum_squares(2, 3))

To trace this on paper, write the call, then under it the parameters with their values. When the body calls another function, start a new entry below, indented. When that one returns, cross it out and write its value where the call was. The traceback from P.1 lists exactly these frames, outermost first, which is why it says "most recent call last".

return is not print

This function has no return. It prints instead. Predict before you read on.

What does this program print?

def double(x):
    print(x * 2)

y = double(5)
print(y)

The first 10 comes from the print inside the function. What did the call hand back for y to point at?

The body prints 10. Then it ends without a return, so the call hands back None, the value that means "nothing". y points at None, and the last line prints that.

This is the most common beginner mix-up, because on the screen both look the same. They are not:

  • print writes text on the screen for a person to read. The program gets nothing back.
  • return hands a value to the code that made the call. Nothing shows on the screen.

A function that reaches the end of its body without a return hands back None. So double(5) + 1 stops with TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'. Python tried to add None and 1.

The rule: print is for people, return is for code. A function that computes something should return it. The caller decides whether to print it.

Ask a yes or no question

total does the same math on every call. But apply has to add for "add" and do something else for another op. Before a function can choose, it has to ask a question.

A comparison asks a yes or no question about two values. Its answer is one of the two booleans from P.1: True or False.

comparisonasksexample
==are they equal?2 + 2 == 4 is True
!=are they different?2 != 3 is True
< and >less than? greater than?3 > 5 is False
<= and >=less or equal? greater or equal?5 >= 5 is True

Mind the two equals signs. One = points a name at a value. Two == ask whether two values are equal.

What is "add" == "Add"?

Strings are compared one character at a time. Is a the same character as A?

False. A capital letter is a different character, so the strings differ. An op name has to match exactly.

Joining questions with and, or and not, and what counts as true

and is true when both sides are. or is true when at least one side is. not flips true and false. With x = 7:

  • x > 0 and x < 10 is True
  • x < 0 or x > 5 is True
  • not x > 5 is False
  • 0 < x < 10 is True. This shortcut means 0 < x and x < 10.

Python also lets any value stand in for a boolean. This is called truthiness. Zero, the empty string "" and None count as false, and almost everything else counts as true. bool() shows which: bool(0), bool("") and bool(None) are False, and bool(42) and bool("0") are True. "0" is a string with one character in it, so it counts as true. When you mean "is this zero" or "is this None", say so with == 0 or is None.

Choose which lines run

Make a guess.

What does this print?

temp = 31
if temp > 30:
    print("hot")
elif temp > 15:
    print("mild")
else:
    print("cold")

31 is above 30 and also above 15. Does Python keep asking after it finds a yes?

Only hot. Python asks the questions from the top, runs the lines under the first one that is true, and skips the rest.

An if statement runs some lines only when a comparison is true. It has up to three kinds of part:

  • if asks the first question.
  • elif, short for "else if", asks another. Python only gets to it when everything above was false. You can have many, or none.
  • else asks nothing. It catches whatever is left. You can leave it out.

Each of these lines ends with a colon, and the lines that belong to it are indented, just like a function body. A line that is not indented is outside the if and runs every time.

Trace it with temp = 20:

  1. Ask the first question. 20 > 30 is False. Skip its lines.
  2. Ask the next. 20 > 15 is True. Print mild.
  3. Skip the rest. else is never looked at.

Because the first true question wins, the order of the questions matters. The next exercise has them in the wrong order.

Fizz, Buzz or the number

fizzbuzz(n) returns "FizzBuzz" when n is divisible by both 3 and 5, "Fizz" when only by 3, "Buzz" when only by 5, and otherwise the number as a string, like "7". The starter is nearly right, but it gets 15 wrong.

"Divisible by 3" is n % 3 == 0. Trace the starter with 15, then think about which question should be asked first.

Two errors and one silent mistake with if

A missing indent. If the line after if temp > 30: is not indented, Python stops before running anything with IndentationError: expected an indented block after 'if' statement on line 2. Indenting a line that has no colon above it gives IndentationError: unexpected indent.

One equals sign. if x = 5: is a SyntaxError, and Python says invalid syntax. Maybe you meant '==' or ':=' instead of '='?. You meant ==.

The indent Python can't catch. If a line that should be inside the if is not indented, it is outside, and it runs every time. That is not an error, so Python says nothing. When a program does something "always" that it should do "sometimes", check the indentation first.

Build a small apply

Put a function and an if together and you have the three lines from the top of this page:

def apply(op, a, b):
    if op == "add":
        return a + b

Now you can read it. apply takes an op's name and two numbers. Follow the call apply("add", 2, 3):

  1. Match the names. op is "add", a is 2, b is 3.
  2. Pick the op. op == "add" is True, so the indented line runs.
  3. Do the math. return a + b hands back 5.

A return ends the call at once. So a second op needs no elif. Put another if under the first, at the same indent. Python only reaches it when the first one did not return.

With only those three lines, what does apply("mul", 2, 3) hand back?

"mul" == "add" is False, so the return line is skipped. What does a function hand back when it runs out of lines?

No question matched, the body ended without a return, and the call handed back None. When you see a None you did not expect, look for the path through the function that has no return.

A small apply

Write apply(op, a, b) with three ops: "add" returns a + b, "sub" returns a - b, and "min" returns the smaller of the two. The starter returns 0 for everything.

For "min" you need a second question inside the branch. An if can sit inside another if: indent it 4 more spaces.

Do it for every item

Adding up 1 to 4 is easy to type: 1 + 2 + 3 + 4. Adding up 1 to 1000 that way is not. You want to say "do this line for every number" once. A loop runs the same lines again and again, and a for loop runs them once for each item of a sequence.

total = 0
for n in range(1, 5):
    total = total + n
print(total)

range(1, 5) gives the numbers 1, 2, 3, 4. It starts at the first number and stops before the second. With one number, range(5), it starts at 0 and gives 0, 1, 2, 3, 4.

Each pass of the loop does two things:

  1. Take the next item. n points at it.
  2. Run the body. That is the indented line. Then go back for the next item.

When the items run out, Python goes on to the first line after the body. Trace it, one row per pass:

Fill in the question marks. What does the program print?

Pass 3 turns 3 into 3 + 3. That is where pass 4 starts.

Pass 3 makes total 6. Pass 4 starts at 6 and makes it 10. There is no item 5, so the loop ends and print(total) shows 10.

A string is a sequence too. for ch in "abc": runs its body three times, with ch as "a", then "b", then "c".

Because the stop number is left out, it is easy to be one step short. That mistake is common enough to have a name: an off-by-one error. The next exercise has one.

More about range, plus break and continue

A third number in range is the step. Wrap a range in list() to see all its numbers at once. (Lists are P.3. For now, read [0, 1, 2] as "these numbers in this order".)

  • list(range(5)) is [0, 1, 2, 3, 4]
  • list(range(1, 5)) is [1, 2, 3, 4]
  • list(range(2, 10, 3)) is [2, 5, 8]
  • list(range(5, 0, -1)) is [5, 4, 3, 2, 1]
  • list(range(0)) is []

range(a, b) has b - a numbers in it. And range(len(word)) gives exactly the valid indexes of the string word.

Two words change a loop from inside. break leaves the loop at once. continue skips the rest of this pass and goes on to the next item.

for n in range(1, 10):
    if n % 2 == 0:
        continue
    if n > 7:
        break
    print(n)

This prints 1, 3, 5 and 7. Even numbers hit continue. At n = 9 the second question is true and break ends the loop, so 9 is never printed.

A loop with a decision inside

The three ideas fit inside each other. This function counts the even numbers from 1 to n. It is a function, with a loop in it, with an if in the loop. Each level is indented 4 more spaces.

def count_evens(n):
    count = 0
    for i in range(1, n + 1):
        if i % 2 == 0:
            count = count + 1
    return count

Read the indentation to see what belongs where. The if runs on every pass. The line under it runs only on passes where i is even. The return lines up with for, so it is after the loop and runs once, when every item has been seen.

What is count_evens(5)?

i goes 1, 2, 3, 4, 5. On which passes is i % 2 == 0 true?

Only 2 and 4 are even, so count goes up twice.

A return can also sit inside a loop. It ends the whole call at once, loop included. Use that when one item is enough to know the answer.

Is it prime?

Write is_prime(n). A prime is a whole number bigger than 1 that only 1 and itself divide exactly: 2, 3, 5, 7, 11 and so on. Return True or False. Numbers below 2, including 0 and negatives, are not prime.

Try every possible divisor with a for loop. As soon as one divides n, you know the answer. When can you say True?

Repeat until something changes

A for loop needs to know its items before it starts. Sometimes you don't know how many passes you need, only when to stop. A while loop keeps going as long as a comparison is true. This one counts how many times 10 can be halved before it reaches 1:

n = 10
steps = 0
while n > 1:
    n = n // 2
    steps = steps + 1
print(steps)

Before each pass, Python asks the question. If it is true, the body runs and Python comes back to ask again. If it is false, Python goes on to the line after the body.

// is whole-number division. How many whole times does 2 fit in 2?

2 // 2 is 1, and 1 > 1 is False, so the loop ends. The question was asked 4 times and the body ran 3 times. The last check is always the one that fails.

A loop that never ends

Take out the line n = n // 2 and n stays 10 forever, so n > 1 is always true and the program hangs. Every while loop needs a line in its body that will make its question false in the end. Use for when you are going through something, and while when you can't say in advance how many passes it takes.

Check yourself

What does 3 == 3.0 give?

== asks whether two values are equal, not whether they have the same type.

Is three the same number as three point zero?

An int and a float with the same value are equal, so it's True. Their types still differ: type(3) is int and type(3.0) is float.

A third number in range is the step: range(2, 11, 4) starts at 2 and adds 4 each time. Which numbers does it give? Write them as a list, like [1, 2, 3].

Start at 2, add 4 each time, and stop before you reach 11.

2, then 6, then 10. Is 14 below 11?

[2, 6, 10]. The next value, 14, is past the stop, and the stop itself is never included anyway.

How many times does the body of for i in range(1, 10): run?

range(a, b) includes a but not b.

The numbers are 1 to 9. How many is that?

9 times, for i from 1 to 9. range(a, b) has b - a numbers in it.
