Learn Python · Lesson 2

Decisions, loops and functions

So far your programs run every line once, top to bottom. This lesson adds the three things that make programs useful: choosing which lines run, running lines again, and wrapping lines up under a name so you can use them anywhere.

Comparisons and booleans

A comparison asks a yes or no question about two values. The answer is a boolean: True or False.

>>> 3 < 5
True
>>> 3 == 3.0
True
>>> "cat" == "Cat"
False
>>> 2 != 3
True
>>> 5 >= 5
True
>>> type(3 < 5)
<class 'bool'>

The operators are == (equal), != (not equal), <, >, <= and >=. Notice == has two equals signs. One = points a name at a value. Two == ask whether two values are equal. Strings compare letter by letter, and capitals are different letters, so "cat" == "Cat" is False.

You combine booleans with three words. and is true when both sides are. or is true when at least one side is. not flips true and false.

>>> x = 7
>>> x > 0 and x < 10
True
>>> x < 0 or x > 5
True
>>> not x > 5
False
>>> 0 < x < 10
True

The last line is a Python shortcut: 0 < x < 10 means 0 < x and x < 10, the way you'd write it in maths.

Python also lets any value stand in for a boolean. This is called truthiness. Zero, the empty string "" and None count as false, and almost everything else counts as true. bool() shows you which:

>>> bool(0)
False
>>> bool(42)
True
>>> bool("")
False
>>> bool("0")
True
>>> bool(None)
False

"0" is a string with one character in it, so it counts as true. When you mean "is this zero" or "is this None", it's clearer to say so with == or is None than to lean on truthiness.

if, elif and else

An if statement runs some lines only when a condition is true:

temp = 31
if temp > 30:
    print("hot")
elif temp > 15:
    print("mild")
else:
    print("cold")

This prints hot. Python checks the conditions from the top and runs the block under the first one that is true, then skips the rest. elif means "else if": it's only checked when everything above it was false. else has no condition and catches whatever is left. You can have any number of elif lines, and elif and else are both optional.

The order matters. With temp = 31, both temp > 30 and temp > 15 are true, but only hot is printed, because the first match wins.

Look at the shape. Each condition ends with a colon, and the lines that belong to it are indented, pushed right by 4 spaces. In Python the indentation is not decoration. It is the structure: it's how Python knows which lines are inside the if. VS Code inserts the 4 spaces for you after a colon.

temp = 31
if temp > 30:
print("hot")
  File "C:\Users\you\ind.py", line 3
    print("hot")
    ^
IndentationError: expected an indented block after 'if' statement on line 2

An IndentationError is a kind of SyntaxError, so nothing in the file runs. The opposite mistake, indenting a line that has no colon above it, gives IndentationError: unexpected indent.

The indent Python can't catch

The worst indentation mistake is not an error at all. If a line that should be inside the if is not indented, it is outside the if, and it runs every time. Python can't know what you meant. When a program does something "always" that it should do "sometimes", check the indentation first.

One equals sign

if x = 5: is a SyntaxError, and Python says so helpfully: invalid syntax. Maybe you meant '==' or ':=' instead of '='?. You meant ==.

Fizz, Buzz or the number

Write fizzbuzz(n). It returns "FizzBuzz" when n is divisible by both 3 and 5, "Fizz" when only by 3, "Buzz" when only by 5, and otherwise the number as a string, like "7". The starter is nearly right, and it gets 15 wrong.

while loops

A loop runs the same lines again and again. A while loop keeps going as long as its condition is true. This one adds up 1 + 2 + 3 + 4:

n = 1
total = 0
while n <= 4:
    total = total + n
    n = n + 1
print(total)

It prints 10. Each time round the loop is called an iteration. Before each iteration, Python checks the condition. If it's true, it runs the indented block and comes back to check again. If it's false, it skips to the first line after the block.

The best way to understand a loop is a trace table: one row per check of the condition, with the value of every variable at that moment. Writing one by hand is slow, and it is how you find nearly every loop bug.

checkntotaln <= 4?then
110Truetotal becomes 1, n becomes 2
221Truetotal becomes 3, n becomes 3
333Truetotal becomes 6, n becomes 4
446Truetotal becomes 10, n becomes 5
5510Falseleave the loop, print 10

The condition is checked 5 times, and the block runs 4 times. The last check is the one that fails. That one extra check is normal for every while loop.

A loop that never ends

Delete the line n = n + 1 and n stays 1 forever, so n <= 4 is always true. The program hangs. Press Ctrl+C in the terminal to stop it. Every while loop needs something inside it that moves it toward its condition being false.

for loops and range

Most loops count through something, and a for loop does the counting for you. It takes each item of a sequence in turn and points a name at it. A string is a sequence of characters:

>>> for ch in "abc":
...     print(ch)
...
a
b
c

The ... is the REPL's prompt for "the block is still going". Press Enter on an empty line to finish it.

To count, loop over a range. range(5) gives 0, 1, 2, 3, 4. range(start, stop) starts somewhere else, and a third number is the step. To see all the numbers of a range at once, wrap it in list(). (Lists are lesson 3. For now, read [0, 1, 2] as "these numbers in this order".)

>>> list(range(5))
[0, 1, 2, 3, 4]
>>> list(range(1, 5))
[1, 2, 3, 4]
>>> list(range(2, 10, 3))
[2, 5, 8]
>>> list(range(5, 0, -1))
[5, 4, 3, 2, 1]
>>> list(range(0))
[]

The stop number is never included. range(1, 5) stops before 5. This is the same rule as string indexes: range(len(word)) gives exactly the valid indexes of word. It also means range(a, b) has b - a numbers in it, which is easy to check.

The for version of the sum from above is shorter, and it can't forget to move n along:

total = 0
for n in range(1, 5):
    total = total + n
print(total)
Off by one

To add up 1 to 10, you need range(1, 11), not range(1, 10). Being one step short or one step long is so common that it has a name: an off-by-one error. When a loop's answer is a little wrong, check the first and the last value the loop sees.

Two words change a loop's flow from inside. break leaves the loop at once. continue skips the rest of this iteration and goes on to the next one.

>>> for n in range(1, 10):
...     if n % 2 == 0:
...         continue
...     if n > 7:
...         break
...     print(n)
...
1
3
5
7

Even numbers hit continue, so they're skipped. At n = 9, the second test is true and break ends the loop, so 9 is never printed. Use while when you don't know in advance how many iterations you need, and for when you are going through something.

Is it prime?

Write is_prime(n). A prime is a whole number bigger than 1 that only 1 and itself divide exactly: 2, 3, 5, 7, 11 and so on. Return True or False. Numbers below 2, including 0 and negatives, are not prime.

Try every possible divisor with a for loop. As soon as one divides n, you know the answer. When can you say True?

Functions

A function is a block of code with a name. You write it once with def, and then call it, by its name and brackets, as often as you like.

>>> def area(width, height):
...     return width * height
...
>>> area(3, 4)
12
>>> area(10, 2) + 1
21

The names in the def line, width and height, are the function's parameters. The values you pass in a call, 3 and 4, are the arguments. When you call area(3, 4), Python points width at 3 and height at 4, then runs the body. return ends the function and hands a value back to whoever called it. The call area(3, 4) then stands for that value, which is why area(10, 2) + 1 works.

Call it with the wrong number of arguments and Python tells you which one is missing:

>>> area(3)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: area() missing 1 required positional argument: 'height'

Defining a function doesn't run its body. The def only stores it under the name. The body runs each time the function is called. Keep functions small: one function, one job. A function you can describe in one short sentence is about the right size.

return is not print

This is the most common beginner bug in Python, and it's worth slowing down for. Here are two functions that look like they do the same thing:

>>> def double_print(x):
...     print(x * 2)
...
>>> def double(x):
...     return x * 2
...
>>> double_print(5)
10
>>> double(5)
10

In the REPL they look identical. But one prints 10 on the screen and the other returns 10 to the caller, and that's a big difference. Watch what each one gives back:

>>> y = double_print(5)
10
>>> y
>>> print(y)
None
>>> double_print(5) + 1
10
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
>>> double(5) + 1
11

A function that reaches the end of its body without a return returns None. So double_print(5) writes 10 on the screen for you to read, and gives None to the program. The line y shows nothing because the REPL doesn't echo None. The TypeError says the program tried to add None and 1.

The rule: print is for people, return is for code. A function that computes something should return it, and the caller decides whether to print it.

A path with no return

A function can return on some paths and fall off the end on others. sign below returns a string for 5, but for 0 neither if matches, the body ends, and the result is None. When you see an unexpected None, look for the path that has no return.

>>> def sign(n):
...     if n > 0:
...         return "positive"
...     if n < 0:
...         return "negative"
...
>>> sign(5)
'positive'
>>> print(sign(0))
None

Local variables and type hints

A variable made inside a function is a local variable. It exists only while that call is running, and the code outside can't see it. The region of code where a name can be seen is called its scope.

>>> def total_cost(price, count):
...     subtotal = price * count
...     return subtotal + 5
...
>>> total_cost(3, 4)
17
>>> subtotal
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
NameError: name 'subtotal' is not defined

Parameters are local too. This is a good thing. It means two functions can both use a name like count without stepping on each other, and you can understand a function by reading only the function. To get a value out, return it.

A function can read a variable made outside it at the top level of the file, called a global. But if the function assigns to a name anywhere in its body, Python treats that name as local for the whole function, and this fails:

count = 0

def bump():
    count = count + 1

bump()
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

That's the last line of the traceback (Python 3.10 words it local variable 'count' referenced before assignment). The fix is the same as before: pass the value in as a parameter, and return the new value. count = bump(count) is clearer than a function that quietly changes the world outside it.

You can add type hints to a function: notes saying what type each parameter should be and what it returns.

def area(width: int, height: int) -> int:
    return width * height

Read width: int as "width is an int" and -> int as "returns an int". A function that returns nothing is marked -> None. Python itself ignores hints when it runs:

>>> area("ab", 3)
'ababab'

So why write them? For you and your editor. They say what a function expects in a form you can read at a glance, and VS Code uses them to show types when you hover over a name. It can also underline a call that passes the wrong kind of value, once you open Settings, search for "type checking mode" and set Python › Analysis: Type Checking Mode to basic. The exercises in this course have hints in their starters for that reason.

Tracing a call by hand

When one function calls another, Python remembers where it was in the first, runs the second to its return, and comes back with the value. Each running call has its own set of local variables, called a frame. Step through this program to see the frames come and go:

def square(n):
    return n * n

def sum_squares(a, b):
    return square(a) + square(b)

print(sum_squares(2, 3))

To trace a call on paper, write the call, then under it the parameters with their values. When the body calls another function, start a new entry below, indented. When that one returns, cross it out and write its value where the call was. The traceback from lesson 1 lists exactly these frames, outermost first, which is why it says "most recent call last".

Check yourself

What does 3 == 3.0 give?

== asks whether two values are equal, not whether they have the same type.

Is three the same number as three point zero?

An int and a float with the same value are equal, so it's True. Their types still differ: type(3) is int and type(3.0) is float.

What does list(range(2, 11, 4)) give? Write it like the REPL would.

Start at 2, add 4 each time, and stop before you reach 11.

2, then 6, then 10. Is 14 below 11?

[2, 6, 10]. The next value, 14, is past the stop, and the stop itself is never included anyway.

How many times does the body of for i in range(1, 10): run?

range(a, b) includes a but not b.

The numbers are 1 to 9. How many is that?

9 times, for i from 1 to 9. range(a, b) has b - a numbers in it.

n goes 10, 5, 2, 1. How many times did the body run?

10 // 2 is 5, 5 // 2 is 2, 2 // 2 is 1, and then 1 > 1 is false. The body ran 3 times, so steps is 3.
