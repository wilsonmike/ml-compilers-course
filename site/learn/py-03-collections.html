Lists, dicts and sets

So far each name has pointed at one value. Real programs keep many values together. Here you learn Python's collections: the list, the dict, the set and the tuple. Two of them are things your compiler needs soon: a dict named env that remembers each answer, and a tuple used as a dict key.

Goal

Keep answers in a dict under their names, and know why a tuple can be a dict key when a list cannot.

You'll use

Names that point at values and string indexes from P.1. Functions, if and for loops from P.2.

Warm up

Two questions from the last two lessons, from memory. Pulling an idea back out of your head is what makes it stay.

It prints 3. Line 3 moves the name price to a new value. It does not touch count. Hold on to this. A list will seem to break the rule later on this page.

    total = total + n

Keep many values in order

You have three test scores. Three names, s1, s2 and s3, would work. Three hundred scores would not. You need one name for the whole row.

A list is a row of values in order. You write it in square brackets with commas between the values:

scores = [70, 85, 90]

A list is indexed the same way as a string. What is scores[1]?

What number does counting start from?

Counting starts at 0, so scores[0] is 70 and scores[1] is 85.

Here is what you can do with a list:

scores = [70, 85, 90]
print(len(scores))
print(scores[-1])
print(scores[0:2])
scores.append(100)
scores[0] = 75
print(scores)

It prints:

3
90
[70, 85]
[75, 85, 90, 100]
  • len(scores) is how many items there are.
  • scores[-1] is the last item. Negative indexes count from the end.
  • scores[0:2] is a slice, a piece of the list. It starts at index 0 and stops before index 2, the same rule as range.
  • scores.append(100) adds 100 to the end. append is a method: a function that belongs to a value, called with a dot after it.
  • scores[0] = 75 replaces the first item.

The last two lines change the list itself. A string can never change. A list can. That matters a lot later on this page.

Trap: append returns None. Methods that change a list in place, like append, return None. So fruits = fruits.append("fig") changes the list and then points fruits at None, losing the list. Call fruits.append("fig") on a line by itself.

Trap: don't change a list while looping over it. Removing items from a list inside a for loop over that same list makes the loop skip items, because everything after the removed one shifts down by one. Build a new list of the items you want to keep instead.

Build a list in a loop

A for loop can walk a list directly. Each time around, the loop name points at the next item. The most common thing to do with that is to build a second list as you go:

squares = []
for n in [1, 2, 3]:
    squares.append(n * n)
print(squares)

It prints [1, 4, 9]. The pattern has three steps:

  1. Start empty. [] is a list with nothing in it.
  2. Walk the items. for n in ... hands you one item at a time.
  3. Append what you want to keep. Each append makes the new list one item longer.

Your compiler's parser builds its list of lines this way.

Keep the big ones

over(nums, limit) should return a new list of the numbers in nums that are bigger than limit, in the same order. over([3, 9, 5, 12], 4) is [9, 5, 12]. The three steps are all here, but one line is wrong. Run it, look at what comes back, and repair that line.

Look a value up by its name

The calculator you build after these lessons runs programs like this one:

%a   = add 2 3
%out = mul %a 4

To run line 2 it has to find what a stands for. A list is no help. A list finds things by position, and you would have to remember which position was a's. You want to look things up by name.

A dict, short for dictionary, stores each value under a key. You write it in curly braces. This dict is named env, the name the calculator uses:

env = {}
env["a"] = 2 + 3
env["out"] = env["a"] * 4
print(env["out"])
print(env)

It prints:

20
{'a': 5, 'out': 20}
  1. Start empty. {} is a dict with nothing in it.
  2. Save under a key. env["a"] = 5 stores 5 under the key "a". If the key is already there, its value is replaced.
  3. Look up by key. env["a"] gives back the value stored under "a".

Nothing was ever saved under "b". What does print(env["b"]) do?

Python does not make up values. What would it have to invent here?

It stops with KeyError: 'b'. The last line of the error names the missing key.

That error is useful. In your calculator, a KeyError means the program used a name that no earlier line made. To ask first, write "b" in env, which is True or False.

Remember each answer

Here is a tiny calculator. Each line of its program is a list of three things, such as ["out", "a", 4]. That means "out is the value of a plus 4". env starts with one name in it, "start", which is 0. run returns env when every line is done.

The loop is written. Two places still say 0. Work out value by looking up earlier in env and adding n. Then save value under name.

Count with a dict

A dict is also how you count things: the key is the thing, and the value is how many you have seen. There is one snag. The first time you meet a word it is not in the dict yet, so counts[w] + 1 stops with a KeyError.

counts.get(w, 0) fixes that. It looks up w, and if the key is missing it gives you 0 and no error.

counts = {}
for w in ["the", "cat", "the"]:
    counts[w] = counts.get(w, 0) + 1
print(counts)

It prints {'the': 2, 'cat': 1}. Follow it one word at a time:

You can write a dict with entries already in it, each one key: value. get with no default returns None for a missing key. in checks the keys, not the values, which is why 85 in ages is False. del removes a key. A key appears at most once. A dict remembers the order its keys were first added, and prints them in that order. Looping over a dict gives you its keys.

A compiler keeps many tables like env: from a name to its value, from a name to its type, from a node to the code made for it. Each one is a dict.

Have I seen this before?

Sometimes all you need to know about a value is whether you have met it already. A set is a collection built for that one question. It keeps each value once and has no order.

seen = set()
seen.add("shop")
seen.add("park")
seen.add("shop")
print(len(seen))

What does that program print?

A set keeps each value once. What happens to the second "shop"?

It prints 2. Adding a value that is already in the set does nothing.

A set with values in it is written {"shop", "park"}. An empty set is set(), because {} already means an empty dict. add puts a value in, and in asks whether it is there. Here a set spots the places a walk comes back to:

seen = set()
for place in ["home", "shop", "park", "shop", "home"]:
    if place in seen:
        print("again:", place)
    else:
        seen.add(place)

It prints again: shop and then again: home. Given two values, print shows both with a space between.

A list can answer in too, but it checks every item one by one. A set jumps straight to the answer, even with a million items. In week 1 your compiler walks a graph in which the same box can be reached by many arrows. A set like seen lets it handle each box once.

Remove repeats, keep the order

Write dedupe(items), which returns a new list with each item once, in the order of its first appearance. dedupe([3, 1, 3, 2, 1]) is [3, 1, 2]. The starter turns the list into a set and back into a list. Run it to see why that isn't enough.

A set to remember what you've seen, and a list for the answer.

More about sets: writing one with values in it, and why the printed order moves around 
colors = {"red", "green", "red"}
print(len(colors))
print("blue" in colors)

Curly braces with single values, not key: value pairs, make a set. set(some_list) drops the repeats from a list. When Python prints a set of strings, the order can look random, and it can differ from one run to the next, so never rely on a set's order.

A dict is as fast at in as a set is. Both jump straight to where the key would be, so the check takes about the same time with ten items or ten million.

Two names, one list

This is the idea on this page that trips up almost everyone once. Guess before you read on.

a = [1, 2, 3]
b = a
b.append(4)
print(a)

The program never appends to a. What does it print?

Did b = a make a second list, or a second name?

It prints [1, 2, 3, 4]. b = a did not copy the list. It pointed a second name at the same list.

Draw it like the picture of a program in the start step: a box for each value and an arrow from each name to its box. There is one list box, with two arrows into it. Press Next to watch it happen.

Two names for one value is called aliasing. The warm up did not behave this way because price = 5 moved an arrow. b.append(4) moves no arrow. It changes the box, and every name pointing at that box sees the change.

When you want a separate list, ask for one. a.copy() makes a new list with the same items. The last two steps of the picture show it.

A function's parameter is one more name for the list you pass in. So a function that appends to its parameter changes the caller's list. When a list has the wrong contents and no line you can see changed it, look for a second name.

Give it its own copy

before_and_after(scores) should return two lists: the scores as they came in, and the scores with a bonus of 100 on the end. before_and_after([70, 80]) should be [[70, 80], [70, 80, 100]]. Right now the bonus shows up in both. Repair one line.

Go deeper: == and is, and aliasing through a function call

== asks "equal contents?" and is asks "the very same object?". A copy is equal to the original, but it is not the same object. list(a) copies a list as well.

Here is the function case in full. theirs and mine end up as two names for one list:

def add_bonus(scores):
    scores.append(100)
    return scores

mine = [70, 80]
theirs = add_bonus(mine)
print(theirs)

Functions that need a changed version should build a new list and return it, and leave their arguments alone. The difference between == and is comes back in P.4 and in week 1, where your compiler makes sure that two equal nodes are always the same object, so the fast is check is enough.

A list that cannot change

In week 1 your compiler asks "have I already built add 2 3?". That is a lookup, so it wants a dict. But the key is three things at once: the op and its two values. Try a list as the key:

built = {}
built[["add", 2, 3]] = 0

What happens when this runs?

A dict finds a key by its contents. What could happen to a list's contents after it is stored?

It stops with TypeError: unhashable type: 'list'. "Unhashable" means "cannot be used as a key".

A dict finds a key by its contents. If a key could change after it was stored, the dict could never find it again. A list can change, so Python refuses it.

A tuple is a list that cannot change. You write it with parentheses. Because it cannot change, it can be a key:

built = {}
built[("add", 2, 3)] = 0
print(("add", 2, 3) in built)
print(("add", 3, 2) in built)

It prints True and then False. Order counts, as it does in a list. You index a tuple like a list, and tuple(some_list) makes a tuple with the same items as a list.

You can also split a tuple into names in one line. This is called unpacking:

line = ("out", "mul", "a", 4)
name, op, x, y = line

Now name is "out" and y is 4. A for loop can unpack too. The calculator's loop starts for name, op, x, y in prog:. And env.items() gives a dict's entries as (key, value) tuples, so for name, value in env.items(): walks both.

Count the repeated lines

Write count_lines(lines). Each line is a list such as ["add", 2, 3]. Return a dict that maps each line, as a tuple, to how many times it appears. count_lines([["add", 2, 3], ["mul", 2, 3], ["add", 2, 3]]) is {('add', 2, 3): 2, ('mul', 2, 3): 1}.

The counting loop again, with a tuple as the key.

A value that can't change is called immutable. Ints, floats, strings and tuples are immutable. Lists, dicts and sets are mutable. Keys can be any immutable value: strings, ints, tuples. A tuple key is how you index by two things at once, like a grid square (row, column). A tuple that has a list inside it still can't be a key.

A tuple of one needs a trailing comma, (5,), because (5) is the number 5 in parentheses. Use a tuple for a small, fixed group of values that belong together, like a point's x and y.

Put things in order

You counted words. Which word won? To find out you need to sort. sorted() takes a collection and returns a new list in order. It leaves the original alone.

print(sorted([3, 1, 2]))
print(sorted([3, 1, 2], reverse=True))
print(sorted(["pear", "apple", "fig"], key=len))

It prints:

[1, 2, 3]
[3, 2, 1]
['fig', 'pear', 'apple']

reverse=True puts the biggest first. key= takes a function. sorted calls it on each item and sorts by what it returns, so key=len sorts words by length. Write len with no parentheses, because you are handing over the function, not calling it.

Tuples compare item by item: the first items decide, and the second items only break ties. So a key that returns a tuple sorts by one thing and then another. This sorts (word, count) pairs with the biggest count first and ties from A to Z:

def most_first(pair):
    return (-pair[1], pair[0])

counts = {"b": 2, "a": 2, "c": 5}
print(sorted(counts.items(), key=most_first))

It prints [('c', 5), ('a', 2), ('b', 2)]. The minus sign flips the order of the counts and leaves the words alone.

The most common word

Write most_common(words), which returns the most frequent word in a list as a (word, count) tuple. If two words tie, return the one that comes first alphabetically. For an empty list, return None. most_common(["b", "a", "b", "a"]) is ('a', 2). The starter's hint tuple[str, int] | None means "a tuple of a str and an int, or None".

A loop in one line

Building a list in a loop is so common that Python has a short form for it, called a comprehension. You will see it in other people's code, so learn to read it. Read the first line below as "the list of n * n for each n in [1, 2, 3]":

print([n * n for n in [1, 2, 3]])
print([w for w in ["a", "bb", "ccc"] if len(w) > 1])
print({w: len(w) for w in ["cat", "horse"]})

It prints:

[1, 4, 9]
['bb', 'ccc']
{'cat': 3, 'horse': 5}

The first line does the same as the squares loop earlier. An if at the end keeps only the items that pass. Curly braces with key: value build a dict. When a comprehension grows past one line, an ordinary loop is easier to read.

Swap keys and values

Write invert(d), which returns a new dict with each key and value swapped. invert({"a": 1, "b": 2}) is {1: 'a', 2: 'b'}. You can assume all the values are different and can be used as keys.

A loop over d.items() works. So does one dict comprehension.
