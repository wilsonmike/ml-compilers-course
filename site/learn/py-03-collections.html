Lists, dicts and sets

A shopping list, a phone book, a guest list. Most real data is a collection of values, not one value. Python has three collections you'll use constantly: the list keeps things in order, the dict looks things up by a key, and the set remembers what it has seen. Your compiler will lean on all three, and on the dict most of all.

Lists

A list is an ordered sequence of values, written in square brackets with commas between them. It indexes exactly like a string: from 0, with negative indexes counting from the end.

>>> fruits = ["apple", "pear", "kiwi", "fig"]
>>> fruits[0]
'apple'
>>> fruits[3]
'fig'
>>> fruits[-1]
'fig'
>>> fruits[-2]
'kiwi'
>>> len(fruits)
4
>>> fruits[4]
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
IndexError: list index out of range

A list of 4 items has indexes 0 to 3, so fruits[4] is one past the end. The last item is always fruits[len(fruits) - 1], which you can also write as fruits[-1].

A slice takes a piece of a list: fruits[start:stop] gives the items from start up to, but not including, stop. That's the same rule as range. Leave out start to begin at the front, and leave out stop to go to the end.

>>> fruits[1:3]
['pear', 'kiwi']
>>> fruits[:2]
['apple', 'pear']
>>> fruits[2:]
['kiwi', 'fig']

Unlike a string, a list can change after you make it. You can add to it, remove from it, and replace items. These changes use methods: functions that belong to a value, called with a dot after it. fruits.append("kiwi") means "append "kiwi" to this list".

>>> fruits = ["apple", "pear"]
>>> fruits.append("kiwi")
>>> fruits
['apple', 'pear', 'kiwi']
>>> fruits.pop()
'kiwi'
>>> fruits
['apple', 'pear']
>>> fruits.pop(0)
'apple'
>>> fruits[0] = "plum"
>>> fruits
['plum']
>>> "plum" in fruits
True
>>> "pear" in fruits
False

append adds to the end. pop() removes the last item and returns it, and pop(0) removes the first. x in fruits asks whether x is somewhere in the list, and gives a boolean. An empty list is [], and popping from it is an error: IndexError: pop from empty list.

append returns None

Methods that change a list in place, like append, return None. So fruits = fruits.append("fig") changes the list and then points fruits at None, losing the list. Call fruits.append("fig") on a line by itself.

Looping over a list

A for loop goes through a list item by item. Here it adds up some prices:

>>> total = 0
>>> for p in [3, 5, 2]:
...     total += p
...
>>> total
10

total += p is short for total = total + p. -= and *= work the same way.

Sometimes you need each item's position as well as the item. enumerate gives you both, as a pair you can split into two names. And zip walks two lists side by side, taking one item from each at a time:

>>> for i, fruit in enumerate(["apple", "pear", "kiwi"]):
...     print(i, fruit)
...
0 apple
1 pear
2 kiwi
>>> names = ["Ada", "Alan", "Grace"]
>>> ages = [36, 41, 85]
>>> for name, age in zip(names, ages):
...     print(name, age)
...
Ada 36
Alan 41
Grace 85

A very common pattern is building a new list in a loop. Start with an empty list, and append to it as you go:

>>> squares = []
>>> for n in range(5):
...     squares.append(n * n)
...
>>> squares
[0, 1, 4, 9, 16]
Don't change a list while looping over it

Removing items from a list inside a for loop over that same list makes the loop skip items, because everything after the removed one shifts down by one. Build a new list of the items you want to keep instead.

Two names, one list

In lesson 1 you saw that = points a name at a value. With numbers, that detail didn't matter. With lists, which can change in place, it matters a great deal:

>>> a = [1, 2, 3]
>>> b = a
>>> b.append(4)
>>> a
[1, 2, 3, 4]
>>> a is b
True

You changed b, and a changed too. b = a did not copy the list. It pointed a second name at the same list. Two names for one value is called aliasing. a is b asks "are these the very same object?", and the answer is True. Step through it:

To get a separate list, make a copy, with .copy() or list(a). A copy is equal to the original, with ==, but it is not the same object, so is says no:

>>> c = a.copy()
>>> c.append(5)
>>> a
[1, 2, 3, 4]
>>> c
[1, 2, 3, 4, 5]
>>> d = list(a)
>>> d == a
True
>>> d is a
False

The same thing happens when you pass a list to a function. The parameter is one more name for the caller's list, so a function that changes its argument changes the caller's list:

>>> def add_bonus(scores):
...     scores.append(100)
...     return scores
...
>>> mine = [70, 80]
>>> theirs = add_bonus(mine)
>>> theirs
[70, 80, 100]
>>> mine
[70, 80, 100]
The bug aliasing causes

You keep a list, hand it to some code, and later find it changed behind your back. When a list has the wrong contents and no line you can see changed it, look for a second name pointing at it. Functions that need a changed version should build a new list and return it, and leave their arguments alone.

== and is, again later

== asks "equal contents?" and is asks "same object?". This difference comes back in week 1, where your compiler makes sure that two equal nodes are always the same object, so the fast is check is enough.

Tuples

A tuple is like a list that can never change. It's written with round brackets. Use it for a small, fixed group of values that belong together, like a point's x and y.

>>> point = (3, 4)
>>> point[0]
3
>>> len(point)
2
>>> point[0] = 5
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: 'tuple' object does not support item assignment
>>> x, y = point
>>> x
3
>>> y
4

A value that can't change is called immutable. Ints, floats, strings and tuples are immutable. Lists, dicts and sets are mutable. x, y = point is called unpacking: it points x at the first item and y at the second. It's what for i, fruit in enumerate(...) was doing.

A tuple of one needs a trailing comma, (5,), because (5) is the number 5 in brackets. Why have tuples at all? Because a tuple can't change, Python can use it as a dict key, which you'll need in a moment. A list can't be a key.

Dicts

A dict, short for dictionary, maps keys to values, like a phone book maps names to numbers. You look a value up by its key instead of by its position.

>>> ages = {"Ada": 36, "Alan": 41}
>>> ages["Ada"]
36
>>> ages["Grace"]
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
KeyError: 'Grace'

Each entry is key: value. Square brackets look a key up, and a missing key is a KeyError, with the missing key on the last line. When a key might be missing, use get. It returns None for a missing key, or the default you give it:

>>> print(ages.get("Grace"))
None
>>> ages.get("Grace", 0)
0
>>> ages["Grace"] = 85
>>> ages["Ada"] = 37
>>> ages
{'Ada': 37, 'Alan': 41, 'Grace': 85}
>>> "Grace" in ages
True
>>> 85 in ages
False
>>> del ages["Alan"]
>>> ages
{'Ada': 37, 'Grace': 85}

Assigning to a key adds it if it's new and replaces the value if it's not. A key appears at most once. in checks the keys, not the values, which is why 85 in ages is False. del removes a key. A dict remembers the order its keys were first added, and prints them in that order.

Looping over a dict gives you its keys. To get keys and values together, loop over .items(), which gives (key, value) pairs:

>>> for name, age in ages.items():
...     print(name, age)
...
Ada 37
Grace 85

Keys can be any immutable value: strings, ints, tuples. A tuple key is how you index by two things at once, like a grid square (row, column). A list key fails with TypeError: unhashable type: 'list', where "unhashable" means "can't be used as a key".

Here is the dict pattern you will write more than any other: counting. "the cat saw the dog".split() cuts the text into a list of words, ['the', 'cat', 'saw', 'the', 'dog']. Then:

counts = {}
for w in words:
    counts[w] = counts.get(w, 0) + 1

For each word, counts.get(w, 0) is how many times you've seen it so far, 0 if never. Add 1 and store it back. Trace it:

stepwcounts.get(w, 0)counts afterwards
start{}
1'the'0{'the': 1}
2'cat'0{'the': 1, 'cat': 1}
3'saw'0{'the': 1, 'cat': 1, 'saw': 1}
4'the'1{'the': 2, 'cat': 1, 'saw': 1}
5'dog'0{'the': 2, 'cat': 1, 'saw': 1, 'dog': 1}

Step 4 is the interesting one: 'the' is already there, so get finds 1 and the count becomes 2. Writing counts[w] + 1 instead of counts.get(w, 0) + 1 would fail with KeyError: 'the' at step 1, because the first time you meet a word it isn't in the dict yet.

Count the words

Write count_words(text), which returns a dict from each word to how many times it appears. Treat capitals as the same word: count_words("The the THE") is {'the': 3}. Keep the words in the order they first appear. In the starter, dict[str, int] is a type hint for a dict with str keys and int values.

text.lower() gives the text in lowercase, and .split() cuts it into words at any run of spaces. Then the counting loop above.

Sets

A set is a collection with no repeats and no order. You use it for one question: "have I got this one?" Adding a value that's already there does nothing.

>>> colors = {"red", "green", "red"}
>>> len(colors)
2
>>> "red" in colors
True
>>> "blue" in colors
False
>>> nums = {3, 1, 3, 2}
>>> nums.add(5)
>>> len(nums)
4
>>> set([1, 2, 2, 1])
{1, 2}

set(some_list) drops the repeats from a list. An empty set is set(), because {} already means an empty dict. When Python prints a set of strings, the order can look random, and it can differ from one run to the next, so never rely on a set's order.

Sets and dicts are fast at in. For a list, x in items compares x with every item, one by one. A set or a dict jumps straight to where x would be, so the check takes about the same time with ten items or ten million. The classic use is a "visited" set, which remembers where you've already been:

path = ["home", "shop", "park", "shop", "home", "school"]
visited = set()
for place in path:
    if place in visited:
        print("again:", place)
    else:
        visited.add(place)
print(len(visited))
again: shop
again: home
4

In week 1 your compiler walks a graph of nodes in which the same node can be reached many times. A visited set is what makes it handle each node once instead of once per path.

Remove repeats, keep the order

Write dedupe(items), which returns a new list with each item once, in the order of its first appearance. dedupe([3, 1, 3, 2, 1]) is [3, 1, 2]. The starter uses list(set(items)). Run it to see why that isn't enough.

A set to remember what you've seen, and a list for the answer.

Sorting

sorted() takes a collection and returns a new list in order. It leaves the original alone. reverse=True sorts biggest first.

>>> sorted([3, 1, 2])
[1, 2, 3]
>>> sorted([3, 1, 2], reverse=True)
[3, 2, 1]
>>> sorted(["pear", "Apple", "fig"])
['Apple', 'fig', 'pear']

Strings sort by character codes, and every capital letter comes before every lowercase one, which is why 'Apple' is first. Lists also have a .sort() method that sorts in place and, like append, returns None. So nums = nums.sort() loses your list.

To sort by something other than the value itself, pass key= a function. sorted calls it on each item and sorts by what it returns. key=len sorts words by length:

>>> sorted(["pear", "apple", "fig"], key=len)
['fig', 'pear', 'apple']
>>> def by_count(pair):
...     return pair[1]
...
>>> counts = {"the": 2, "cat": 1, "dog": 3}
>>> sorted(counts.items(), key=by_count, reverse=True)
[('dog', 3), ('the', 2), ('cat', 1)]

Notice key=len and key=by_count have no brackets after the function's name. You're handing sorted the function itself, for it to call, not calling it yourself. Lesson 5 says more about passing functions around like this. You'll also see the short form key=lambda pair: pair[1], which makes the same small function without a def.

Tuples compare item by item: the first items decide, and only if they're equal do the second items count. So a key that returns a tuple sorts by one thing, then breaks ties with another. Negating a number flips its order. Together, that gives "biggest count first, ties A to Z":

>>> (1, "b") < (2, "a")
True
>>> (1, "a") < (1, "b")
True
>>> def most_first(pair):
...     return (-pair[1], pair[0])
...
>>> sorted({"b": 2, "a": 2, "c": 5}.items(), key=most_first)
[('c', 5), ('a', 2), ('b', 2)]

The most common word

Write most_common(words), which returns the most frequent word in a list as a (word, count) tuple. If two words tie, return the one that comes first alphabetically. For an empty list, return None. most_common(["b", "a", "b", "a"]) is ('a', 2). The starter's hint tuple[str, int] | None means "a tuple of a str and an int, or None".

Count with a dict, then sort its items with a tuple key and take the first.

Comprehensions

Building a list in a loop is so common that Python has a one-line form for it, called a list comprehension. Read it as "the list of n * n for each n in range(5)":

>>> [n * n for n in range(5)]
[0, 1, 4, 9, 16]
>>> [w for w in ["a", "bb", "ccc"] if len(w) > 1]
['bb', 'ccc']
>>> {w: len(w) for w in ["cat", "horse"]}
{'cat': 3, 'horse': 5}
>>> {n % 3 for n in range(10)}
{0, 1, 2}

The first line does the same as the squares loop earlier. An if at the end keeps only the items that pass. Curly brackets with key: value make a dict comprehension, and curly brackets with a single value make a set. Comprehensions are good for short, simple transformations. When one grows past a line, or needs several ifs, an ordinary loop is easier to read.

Swap keys and values

Write invert(d), which returns a new dict with each key and value swapped. invert({"a": 1, "b": 2}) is {1: 'a', 2: 'b'}. You can assume all the values are different and can be used as keys.

One dict comprehension over d.items().

Why a compiler uses dicts everywhere

A compiler keeps a lot of tables: from a name to its value, from a name to its type, from a node to the code made for it. Each of those is a dict. Week 1 starts with programs like this, where each line names a result:

%a = add 2 3
%b = mul %a 4

To work out %b, your compiler needs to know what %a stands for. A dict from the name to the value is exactly that table:

>>> values = {}
>>> values["%a"] = 2 + 3
>>> values["%b"] = values["%a"] * 4
>>> values
{'%a': 5, '%b': 20}

A KeyError: '%c' here would mean the program used a name it never defined, which is something your compiler must report. The visited set from the walk, the counting pattern, the tuple key and the difference between == and is all come back in week 1, on graphs instead of words.
