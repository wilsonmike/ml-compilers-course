Learn OCaml · Lesson 5

Arrays, tables and mutation

Until now nothing you made in OCaml could change after you made it. This lesson gives you the parts that can: a box you can refill, loops, arrays and hash tables. Your first interpreter keeps its answers in a hash table, and your week 1 compiler uses one so it never builds the same node twice.

Goal

Count things, remember things by name, and tell "equal" from "the very same one".

You'll use

Functions and fun from O.2, lists, match and option from O.3, and records from O.4.

Warm up

Two questions from earlier lessons, from memory. Pulling an idea back out of your head is what makes it stay.

What is the value of match Some 3 with Some n -> n + 1 | None -> 0?

Which branch fits Some 3, and what is n in it?

Some 3 fits the first branch with n as 3, so the answer is 4. You will use this exact shape to count words.

After these two lines, what is n.op?

let n = { id = 0; op = "x"; src = [] }
let m = { n with op = "y" }

{ n with op = "y" } builds a new record that copies n except for op.

m is a new record. n is left alone, so n.op is still "x". Nothing you have made so far can change.

A job that needs change

Here is a job: count how many times each word appears in a list. By hand you would keep a tally sheet. You see "the", so you add one to the number next to "the". That means changing a number you already wrote down.

Nothing you have made in OCaml so far can do that. Try to count with what you know:

let hits = 0
let result = List.map (fun w -> hits + 1) ["the"; "cat"; "the"]

What is result?

Does hits + 1 change hits, or only compute a number?

hits is 0 on every line, forever. hits + 1 computes 1 three times and changes nothing.

To mutate a value means to change it in place, after it was made. The count needs that: one number that goes up each time. OCaml lets you do it, and it keeps every change easy to spot. A change always uses its own operator, := or <-.

Why OCaml prefers values that don't change, for when you wonder which style to use

If a value can't change, you can hand it to any function without worrying what that function does to it. When you read let total = 5, you know total is 5 on every later line. There is nothing to trace.

But some jobs really are about change: counting things as you see them, filling in a table of results, reading a file line by line. Forcing those into the no-change style makes the code longer and slower, not clearer.

A good rule for the course: write functions that take values and return new values, and use mutation inside a function when it makes that function simpler. Your week 1 compiler does exactly that. Its expression trees never change, and a hash table on the side remembers which nodes it has already built.

A box you can refill: ref

You need a number that can go up. A ref is a box that holds one value, and you can swap that value for another later. Three pieces work the box:

  • ref 0 makes a box holding 0.
  • !count reads what is in the box.
  • count := 5 puts 5 in the box.
# let count = ref 0;;
val count : int ref = {contents = 0}
# count := !count + 1;;
- : unit = ()
# !count;;
- : int = 1

Read count := !count + 1 in three moves:

  1. Read the box. !count is 0.
  2. Do the math. 0 + 1 is 1.
  3. Put it back. := stores 1 in the same box.

The name count always means the same box. Only what is inside changes. Adding 1 has a short form, incr count.

A change gives back (), called unit, which means "nothing worth returning". To do one step and then another, put a semicolon between them: a; b means "do a, then the answer is b".

() also stands in as the parameter of a function that needs no input. let fresh () = ref 0 is called as fresh (), and each call makes a new box.

What is the value of this?

let count = ref 10 in
count := !count + 5;
count := !count * 2;
!count

Follow the box. What is in it after the first change?

The box starts at 10. The first change puts 15 in it. The second reads 15 and puts 30 in it. The last line reads 30.

The box is not the number

count + 1 fails with This expression has type "int ref" but an expression was expected of type "int". A box can't be added to a number. You need what is inside it: !count + 1. If an error says int ref where you expected int, you forgot a !.

What a ref really is, and what the semicolon warns about, for when an error mentions them

The type int ref reads "a box holding an int". utop prints it as {contents = 0} because a ref is a record with one field, contents, which is marked as changeable. Your own records can have changeable fields too, written mutable. Lesson 0.6 has an example with a bank balance. decr count subtracts 1, the way incr adds 1.

In a; b the result of a is thrown away, so it should be unit. If it isn't, you probably made a mistake, and OCaml says so:

# let x = 5; 6;;
Line 1, characters 8-9:
1 | let x = 5; 6;;
            ^
Warning 10 [non-unit-statement]: this expression should have type unit.

val x : int = 6

The 5 was computed and thrown away. Inside a list the semicolon means something else. It separates elements: [1; 2; 3]. Outside square brackets it means "then".

Repeat with a counter: for and while

To add up 1, 2, 3 and 4 into a box you could write four changes. For 1,000 numbers you need a way to say "do this again". A for loop runs its body once for each number in a range, both ends included:

let total = ref 0 in
for i = 1 to 4 do
  total := !total + i
done;
!total

What is the value of that code?

The body runs four times, with i as 1, 2, 3 and 4.

1 + 2 + 3 + 4 is 10. The table below shows each trip through the body.

i!total before!total after
101
213
336
4610

The loop variable i is not a ref. You can read it but not change it. The loop itself returns unit, so the work it does has to land in a box.

A while loop is for when you don't know the number of trips ahead of time. It runs its body again and again while a condition is true. Something must change or it would never stop, so its condition almost always reads a ref:

let n = ref 20 in
while !n > 1 do
  n := !n / 2
done;
!n

How many times does the body of that while loop run? Dividing ints drops the remainder, so 5 / 2 is 2.

Write down what is in n after each trip: 10, then…

The box goes 20, 10, 5, 2, 1. That is four changes. Then !n > 1 is false and the loop stops.

To repeat over a list and not a range of numbers, use List.iter f items. It calls f on each item in order, as List.map does, but it builds no list and returns unit. To count down, write for i = 3 downto 1.

Many boxes in a row: arrays

One score needs one ref. A thousand scores would need a thousand names. A list holds many values, but it can't change, and finding its 500th item means stepping past the first 499.

An array is a fixed-size row of boxes, called slots, numbered from 0. You can read or change any slot directly.

# let a = Array.make 3 0;;
val a : int array = [|0; 0; 0|]
# a.(0) <- 7;;
- : unit = ()
# a.(0);;
- : int = 7
# Array.length a;;
- : int = 3
  1. Make it. Array.make 3 0 makes 3 slots, each holding 0. You can also write one out: [| 4; 5; 6 |]. The bars tell it apart from a list.
  2. Change a slot. a.(0) <- 7 puts 7 in slot 0.
  3. Read a slot. a.(0) is now 7.

Start again from let a = Array.make 3 0. What is a after a.(0) <- 7; a.(2) <- a.(0) + 1?

Slots are numbered from 0. Which slot is a.(2)?

Slot 0 gets 7. Slot 2 is the third and last slot, and it gets 7 + 1. Slot 1 was never touched.

An array of length 3 has slots 0, 1 and 2. There is no slot 3. Asking for a.(3) stops the program with Invalid_argument "index out of bounds". The last slot is always a.(Array.length a - 1).

Sum an array with a for loop

Write sum : int array -> int using a for loop over the indexes and the total ref from the starter. sum [| 1; 2; 3 |] is 6, and an empty array sums to 0.

The loop goes from 0 to Array.length a - 1. Inside it, total := !total + a.(i).

Arrays without an index: map, iter and to_list, for when a loop feels like too much

Array.map and Array.iter work like List.map and List.iter. Array.map makes a new array, and Array.iter runs a function on each element for its effect:

# let b = [| 1; 2; 3 |];;
val b : int array = [|1; 2; 3|]
# Array.map (fun x -> x * 10) b;;
- : int array = [|10; 20; 30|]
# Array.iter (fun x -> Printf.printf "%d\n" x) b;;
1
2
3
- : unit = ()
# Array.to_list b;;
- : int list = [1; 2; 3]

OCaml checks every index. That is much better than what C does, which is to read whatever happens to be next in memory.

Look things up by name: Hashtbl

An array finds things by number. An interpreter needs to find them by name: line 1 of a program saves its answer as a, and line 2 asks for a. A hash table stores pairs of a key (what you look up by) and a value (what you get back). OCaml's is called Hashtbl. Here is a tiny env, a place that keeps answers under names:

# let env : (string, int) Hashtbl.t = Hashtbl.create 16;;
val env : (string, int) Hashtbl.t = <abstr>
# Hashtbl.replace env "a" 5;;
- : unit = ()
# Hashtbl.replace env "out" 20;;
- : unit = ()
# Hashtbl.find env "a";;
- : int = 5
  1. Make the table. Hashtbl.create 16 makes an empty one. The 16 is a first guess at its size. The type reads "a table from strings to ints".
  2. Save. Hashtbl.replace env "a" 5 sets the value for "a" to 5, replacing any old one.
  3. Look up. Hashtbl.find env "a" gives back 5.

Nothing was ever saved under "b". What does Hashtbl.find env "b" do?

The type says find returns an int. Is there an honest int to return?

find must return an int and has none to give, so it raises Not_found. Returning 0 would hide the mistake.

When a missing key is normal, ask with Hashtbl.find_opt. It returns an option, so you handle both cases with match: Hashtbl.find_opt env "b" is None and Hashtbl.find_opt env "a" is Some 5.

One trap: Hashtbl.add does not replace. It puts the new value in front and keeps the old one hidden behind it. Use replace unless you are sure the key is new.

Where you'll use this

In Build the thing that runs it, your run function keeps each line's answer in a Hashtbl named env, exactly like this one, and remembers the last answer in a ref.

Save answers and look them up

final_value lines name saves each (name, value) pair in env, in order, then returns the value saved under name. A later pair with the same name wins. Two things are wrong in the starter. It saves 0 for every name. And it stops with Not_found when the name was never saved, where it should return 0.

More Hashtbl: the add trap in full, visiting every pair and why the order is odd

utop prints <abstr> instead of the contents because a table's insides are hidden. A table finds a value in about the same time however big it is. Inside a function you can leave the type off and OCaml works it out.

  • Hashtbl.replace t k v sets the value for key k to v, replacing any old one.
  • Hashtbl.find t k returns the value, or raises Not_found if the key isn't there.
  • Hashtbl.find_opt t k returns an option instead.
  • Hashtbl.mem t k answers "is this key in the table?".
  • Hashtbl.length t counts the pairs.
  • Hashtbl.iter f t calls f key value for every pair.
# let ages : (string, int) Hashtbl.t = Hashtbl.create 16;;
val ages : (string, int) Hashtbl.t = <abstr>
# Hashtbl.replace ages "ann" 32;;
- : unit = ()
# Hashtbl.replace ages "bob" 27;;
- : unit = ()
# Hashtbl.iter (fun name age -> Printf.printf "%s is %d\n" name age) ages;;
bob is 27
ann is 32
- : unit = ()

The pairs came out in neither the order you added them nor alphabetical order. A hash table keeps its own order, and you shouldn't rely on it. If you need sorted output, take the pairs out and sort them.

Here is Hashtbl.add stacking values:

# let ages : (string, int) Hashtbl.t = Hashtbl.create 16;;
val ages : (string, int) Hashtbl.t = <abstr>
# Hashtbl.add ages "ann" 31;;
- : unit = ()
# Hashtbl.add ages "ann" 32;;
- : unit = ()
# Hashtbl.find ages "ann";;
- : int = 32
# Hashtbl.length ages;;
- : int = 2
# Hashtbl.remove ages "ann";;
- : unit = ()
# Hashtbl.find ages "ann";;
- : int = 31

find sees the newest value, so everything looks fine at first. But the length is 2, and after remove the old 31 comes back. If you then list the table, "ann" shows up twice.

Count the words

Now the job from the start. The table is the tally sheet: the key is a word and the value is its count so far. For each word, take three moves:

  1. Look up the count so far. None means the word is new, so the count is 0.
  2. Add 1. That is the new count.
  3. Save the new count. replace writes over the old one.
let count_words words =
  let t = Hashtbl.create 16 in
  List.iter
    (fun w ->
      let n = match Hashtbl.find_opt t w with Some n -> n | None -> 0 in
      Hashtbl.replace t w (n + 1))
    words;
  t

Step through five words and guess each row before you press next:

To get the counts out as a list, Hashtbl.fold visits every pair and builds up a result, the way List.fold_left does. The table's order is its own, so sort the list afterward. List.sort compare puts pairs in order by their first part, the word:

# let t = count_words ["the"; "cat"; "saw"; "the"; "hat"];;
val t : (string, int) Hashtbl.t = <abstr>
# List.sort compare (Hashtbl.fold (fun w n acc -> (w, n) :: acc) t []);;
- : (string * int) list = [("cat", 1); ("hat", 1); ("saw", 1); ("the", 2)]

Strings sort by their character codes, and every capital letter comes before every small letter.

Count words with a hash table

Write word_counts : string list -> (string * int) list. It returns each distinct word once, with how many times it appears, sorted alphabetically. word_counts ["the"; "cat"; "the"] is [("cat", 1); ("the", 2)].

Count with find_opt and replace, get the pairs with Hashtbl.fold, then List.sort compare.

compare and sorting in full, for when you need a different order

compare a b answers "which comes first?" with a number: negative if a is smaller, 0 if they're equal, positive if a is bigger. It works on ints, strings, lists, tuples, almost anything.

# compare 3 7;;
- : int = -1
# compare 7 3;;
- : int = 1
# compare 5 5;;
- : int = 0
# compare "pear" "apple";;
- : int = 1

List.sort takes a function shaped like compare and a list, and returns a new sorted list. Pass compare itself for the normal order. For the reverse order, pass a function that swaps its arguments:

# List.sort compare [3; 1; 2];;
- : int list = [1; 2; 3]
# List.sort (fun a b -> compare b a) [3; 1; 2];;
- : int list = [3; 2; 1]
# List.sort compare ["pear"; "apple"; "Apple"];;
- : string list = ["Apple"; "apple"; "pear"]
# List.sort compare [("b", 2); ("a", 5); ("a", 1)];;
- : (string * int) list = [("a", 1); ("a", 5); ("b", 2)]

Strings compare letter by letter, so "Apple" sorts before "apple". Pairs compare by their first part, and only look at the second part when the first parts are equal. The type of count_words is 'a list -> ('a, int) Hashtbl.t: it works for a list of anything, because a hash table can use any value as a key.

Build a long string: Buffer

Your compiler will print whole programs as text, one small piece at a time. You know ^ joins two strings. But strings can't change, so every ^ makes a brand new string and copies both halves into it. In a loop that copying adds up fast.

A Buffer is a growable string made for this job. You add pieces to the end, and when you're done, Buffer.contents gives you the finished string:

# let b = Buffer.create 16;;
val b : Buffer.t = <abstr>
# Buffer.add_string b "a";;
- : unit = ()
# Buffer.add_string b ", ";;
- : unit = ()
# Buffer.add_string b "b";;
- : unit = ()
# Buffer.contents b;;
- : string = "a, b"

To turn numbers into text, Printf.sprintf fills the holes in a template. %d is a hole for an int and %.2f is a hole for a float shown with two digits after the point. Printf.sprintf "%d apples cost %.2f" 3 1.5 is "3 apples cost 1.50".

Join strings with a Buffer

Write join : string -> string list -> string, which puts sep between the parts. join ", " ["a"; "b"; "c"] is "a, b, c". An empty list gives "", and there is no separator at either end. The starter adds the parts but forgets the separator.

The separator goes before every part except the first. List.iteri works like List.iter, but your function gets two arguments, the index (starting at 0) and the part: List.iteri (fun i p -> ...) parts.

How slow ^ in a loop gets, and every Printf code, for when you print your compiler's output 
# let s = ref "";;
val s : string ref = {contents = ""}
# for i = 1 to 4 do s := !s ^ string_of_int i done;;
- : unit = ()
# !s;;
- : string = "1234"

That works, but the fourth trip copies "123" again to make "1234". Adding 1,000 one-letter pieces copies 1 + 2 + 3 + ... + 1000 letters, about half a million, to build a string of 1,000. Doubling the pieces makes it four times slower. A Buffer keeps spare room so it rarely has to copy. Buffer.add_char b '!' adds a single character.

Here is a Buffer in a loop that puts a comma between numbers. The separator goes before every piece except the first:

# let buf = Buffer.create 16 in
  for i = 1 to 5 do
    if i > 1 then Buffer.add_string buf ", ";
    Buffer.add_string buf (string_of_int i)
  done;
  Buffer.contents buf;;
- : string = "1, 2, 3, 4, 5"

Equal, or the very same one

Once values can change, a new question matters. Are these two things that look alike, or one thing with two names? Build two records the same way, reading the id from a box. The type is the node record from O.4:

# type node = { id : int; op : string; src : node list };;
type node = { id : int; op : string; src : node list; }
# let next = ref 0;;
val next : int ref = {contents = 0}
# let a = { id = !next; op = "x"; src = [] };;
val a : node = {id = 0; op = "x"; src = []}
# let b = { id = !next; op = "x"; src = [] };;
val b : node = {id = 0; op = "x"; src = []}
# let c = a;;
val c : node = {id = 0; op = "x"; src = []}

OCaml has two ways to compare. = asks "do these have the same contents?". == asks "are these the very same one in the computer's memory?".

What are a = b and a == b?

How many records did those lines build? Each { ... } builds one.

The contents match, so a = b is true. But two records were built, one for each { ... }, so a == b is false.

let c = a builds nothing. It gives a second name to the record a already names, so a == c is true. A copy such as { a with op = "x" } is a new record: equal to a, but not the same one.

Why have both? = compares every piece of both values, so on two big trees it takes a long time. == is one step however big the values are. For everyday comparisons use =.

!= is not "not equal"

Each one has its own "not": <> is the opposite of =, and != is the opposite of ==. Coming from other languages you'll reach for != and get surprises. Use <>.

When == can surprise you: values you write out by hand

Type let a = [1; 2; 3] and let b = [1; 2; 3] into utop and a == b is false, because each line is built on its own. A compiled program may store two identical constant lists only once, and then a == b is true. The same goes for a record whose fields are all written out as constants.

So don't use == to tell apart values you wrote out by hand. That is why the example above reads its id from a box: a value built while the program runs is only the same as another when your code makes it the same. Arrays are always safe here. An array can be changed, so OCaml never shares one behind your back, and [|1; 2|] != [|1; 2|] is always true.

Find it or make it

Put a table, a counter and == together and you get the trick that opens week 1. Suppose a program asks for the node "x" in ten places. Building ten equal records wastes memory, and comparing them needs the slow =. So build each node once and hand the same one back every time:

  1. Look in the table. Is there already a node for this op?
  2. Found. Return the stored node itself, not a copy.
  3. Not found. Build it, give it the next number from the counter, move the counter on, save it and return it.

Now two nodes with equal contents are always the very same node, so == is enough to compare them.

Hand back the very same node

make tbl next op should follow the three steps above. Asking for the same op twice must give the very same node (==), and new nodes must get the ids 0, 1, 2 and so on. Two lines of the starter are wrong: one returns a copy, and one step is missing so every node gets the same id.

Where you'll use this

This is called hash consing, and you build the real one in lesson 1.1. There the key is a pair, (op, list of source ids), the counter is a ref and the test is ==. A pair works as a key because a Hashtbl compares keys by their contents. Its starter makes two local names in one let, joined by and: let tbl = Hashtbl.create 64 and next = ref 0 in.

Check yourself

What is the value of let c = ref 5 in c := !c * 2; !c?

What is in the box after c := !c * 2?

The ; runs the change first, then the whole expression is the value of !c.

The box starts at 5. c := !c * 2 puts 10 in it. Then !c reads 10, and that's the value of the whole expression.

let a = [| 4; 5; 6 |]. What does a.(3) do?

What number does the first slot have?

Three slots, numbered from 0. What's the last one?

The slots are 0, 1 and 2, so a.(3) is past the end. OCaml checks every index and raises Invalid_argument "index out of bounds". The last element is a.(Array.length a - 1), which is 6.

You run Hashtbl.add t "kiwi" 1 and then Hashtbl.add t "kiwi" 2 on an empty table. What are Hashtbl.find t "kiwi" and Hashtbl.length t?

Does add remove the old value?

add puts the new value in front of the old one. Which one does find see?

find sees the newest value, 2. But add kept the old one hidden behind it, so the table holds two bindings and the length is 2. With replace the answer would be 2 and 1.

What string does Printf.sprintf "%.2f" 2.0 return?

%.2f means a float with exactly two digits after the point.

"2.00". The .2 asks for two digits after the point, and the float 2.0 has none to show, so they're zeros.

What are [|1; 2|] <> [|1; 2|] and [|1; 2|] != [|1; 2|]?

<> is the opposite of =. != is the opposite of ==.

The two arrays have the same contents. Are they the same array in memory?

The contents are equal, so <> is false. But each [| |] makes a new array (an array can be changed, so OCaml never shares one behind your back), so they aren't the same value in memory, and != is true. That's why != is a trap for "not equal".

What is List.sort compare ["b"; "C"; "a"]?

Strings compare by character codes. Where do capital letters fall?

Every capital letter comes before every small letter. Answer in OCaml list syntax.

["C"; "a"; "b"]. Capital letters have smaller character codes than small letters, so "C" comes first, even though C is after a and b in the alphabet.
