Learn OCaml · Lesson 5

Arrays, tables and mutation

Until now nothing you made in OCaml could change after you made it. This lesson covers the parts that can: boxes you can refill, loops, arrays, and hash tables. It also covers building strings, printing numbers neatly, and the difference between two values being equal and being the same value, which week 1 depends on.

Why OCaml prefers values that don't change

To mutate a value means to change it in place, after it was made. In lesson O.4 you never did that. { p with x = 10 } made a new record and left p alone. OCaml leans this way on purpose, and the reason is simple to state: if a value can't change, you can hand it to any function without worrying what that function does to it. When you read let total = 5, you know total is 5 on every later line. There is nothing to trace.

But some jobs really are about change. Counting things as you see them, filling in a table of results, reading a file line by line. Forcing those into the no-change style makes the code longer and slower, not clearer. So OCaml gives you mutation too, and it makes it visible: every place that changes something uses a special operator you can spot, like := or <-.

A good rule for the course: write functions that take values and return new values, and use mutation inside a function when it makes that function simpler. Your week 1 compiler does exactly that. Its expression trees never change, and a hash table on the side remembers which nodes it has already built.

A box you can refill: ref

A ref is a box that holds one value, and you can swap that value for another later. ref 0 makes a box holding 0. ! reads what's in the box. := puts a new value in.

# let counter = ref 0;;
val counter : int ref = {contents = 0}
# counter := !counter + 1;;
- : unit = ()
# !counter;;
- : int = 1
# incr counter;;
- : unit = ()
# !counter;;
- : int = 2

Read counter := !counter + 1 from the right: take what's in the box (!counter, which is 0), add 1, and put the result back in the box. The name counter always means the same box. Only what's inside it changes. incr counter is a shortcut for adding 1, and decr subtracts 1.

The type int ref reads "a box holding an int". utop prints it as {contents = 0} because a ref really is a record with one field, contents, which is marked as changeable. Records can have changeable fields too, written mutable. Lesson 0.6 has an example with a bank balance.

The box is not the number

counter + 1 fails with Error: This expression has type "int ref" but an expression was expected of type "int". A box can't be added to a number. You need what's inside it: !counter + 1. If you see int ref where you expected int in an error, you've forgotten a !.

Doing things in order: unit, ; and loops

Look at what counter := !counter + 1 returned: - : unit = (). As in lesson O.1, unit is a type with exactly one value, written (). It means "nothing interesting to return". Functions that do something, instead of computing something, return unit. Printing is the usual example:

# print_string "hi";;
hi- : unit = ()
# print_endline "one"; print_endline "two";;
one
two
- : unit = ()

The first line printed hi, and then utop printed the result, unit, right after it on the same line because print_string doesn't end the line. print_endline does.

You met the semicolon in lesson O.2. a; b means "do a, throw away its result, then do b, and the whole thing is b's value". It is how you put steps in order. Because a's result is thrown away, it should be unit. If it isn't, you probably made a mistake, and OCaml says so:

# let x = 5; 6;;
Line 1, characters 8-9:
1 | let x = 5; 6;;
            ^
Warning 10 [non-unit-statement]: this expression should have type unit.

val x : int = 6

The 5 was computed and thrown away. Inside a list the semicolon means something else, it separates elements: [1; 2; 3]. Outside brackets it means "then".

for and while

A for loop runs its body once for each number in a range, both ends included. A while loop runs its body again and again while a condition is true. Both are written do ... done, and both return unit.

# for i = 1 to 3 do print_int i; print_newline () done;;
1
2
3
- : unit = ()
# let total = ref 0;;
val total : int ref = {contents = 0}
# for i = 1 to 4 do total := !total + i done;;
- : unit = ()
# !total;;
- : int = 10

The loop variable i is not a ref. You can read it but not change it. Here is the second loop, one row per trip through the body:

i!total before!total after
101
213
336
4610

A while loop needs something to change, or it would never stop, so its condition almost always reads a ref. This one halves a number until it reaches 1:

# let n = ref 20;;
val n : int ref = {contents = 20}
# while !n > 1 do n := !n / 2; Printf.printf "%d\n" !n done;;
10
5
2
1
- : unit = ()

5 / 2 is 2 because int division drops the remainder. Printf.printf "%d\n" prints an int and a newline, as in lesson O.1. There is more on formats below. To count down instead of up, write for i = 3 downto 1.

Arrays: a row of boxes

A list is good for going through things in order, but finding its 500th element means stepping past the first 499. An array is a fixed-size row of slots, numbered from 0, and you can read or change any slot directly.

# let a = Array.make 3 0;;
val a : int array = [|0; 0; 0|]
# a.(0) <- 7;;
- : unit = ()
# a;;
- : int array = [|7; 0; 0|]
# a.(1);;
- : int = 0
# Array.length a;;
- : int = 3

Array.make 3 0 makes an array of 3 slots, each holding 0. Arrays are written with bars inside the brackets, [|7; 0; 0|], so you can tell them from lists. a.(1) reads slot 1, and a.(0) <- 7 puts 7 in slot 0. Note the dot before the parentheses. The arrow <- is the "change this slot" operator.

An array of length 3 has slots 0, 1 and 2. There is no slot 3:

# a.(3);;
Exception: Invalid_argument "index out of bounds".

This is the most common array bug: a loop that runs one step too far. The last valid index is always Array.length a - 1. OCaml checks every index and stops the program with this exception, which is much better than reading whatever happens to be next in memory, which is what C does.

You don't always need an index. Array.map and Array.iter work like their List cousins from lesson O.3. Array.map makes a new array, and Array.iter runs a function on each element for its effect:

# let b = [| 1; 2; 3 |];;
val b : int array = [|1; 2; 3|]
# Array.map (fun x -> x * 10) b;;
- : int array = [|10; 20; 30|]
# Array.iter (fun x -> Printf.printf "%d\n" x) b;;
1
2
3
- : unit = ()
# Array.to_list b;;
- : int list = [1; 2; 3]

Sum an array with a for loop

Write sum : int array -> int using a for loop over the indexes and the total ref from the starter. sum [| 1; 2; 3 |] is 6, and an empty array sums to 0.

The loop goes from 0 to Array.length a - 1. Inside it, total := !total + a.(i).

Hash tables: look things up by name

An array finds things by number. Often you want to find them by something else: a person's age by their name, a word's count by the word. A hash table stores pairs of a key (what you look up by) and a value (what you get back), and finds the value for a key in about the same time however big the table is. OCaml's is called Hashtbl. It is mutable: you add to the same table as you go.

# let ages : (string, int) Hashtbl.t = Hashtbl.create 16;;
val ages : (string, int) Hashtbl.t = <abstr>
# Hashtbl.replace ages "ann" 31;;
- : unit = ()
# Hashtbl.replace ages "ann" 32;;
- : unit = ()
# Hashtbl.length ages;;
- : int = 1
# Hashtbl.find ages "bob";;
Exception: Not_found.
# Hashtbl.find_opt ages "bob";;
- : int option = None
# Hashtbl.find_opt ages "ann";;
- : int option = Some 32
# Hashtbl.mem ages "ann";;
- : bool = true

The type (string, int) Hashtbl.t reads "a hash table from strings to ints". The 16 in Hashtbl.create 16 is a first guess at the size. The table grows by itself, so any small number is fine. utop prints <abstr> instead of the contents because a table's insides are hidden.

  • Hashtbl.replace t k v sets the value for key k to v, replacing any old one. That's why the length is still 1.
  • Hashtbl.find t k returns the value, or raises Not_found if the key isn't there.
  • Hashtbl.find_opt t k returns an option instead. Use this one when a missing key is normal.
  • Hashtbl.mem t k answers "is this key in the table?".
  • Hashtbl.iter f t calls f key value for every pair.
# Hashtbl.replace ages "bob" 27;;
- : unit = ()
# Hashtbl.iter (fun name age -> Printf.printf "%s is %d\n" name age) ages;;
bob is 27
ann is 32
- : unit = ()

The pairs came out in neither the order you added them nor alphabetical order. A hash table keeps its own order, and you shouldn't rely on it. If you need sorted output, take the pairs out and sort them, as in the exercise below.

Hashtbl.add doesn't replace

There is also Hashtbl.add, and it looks like the obvious name to use. But add doesn't replace the old value. It puts the new one in front and keeps the old one hidden behind it. Watch:

# let ages : (string, int) Hashtbl.t = Hashtbl.create 16;;
val ages : (string, int) Hashtbl.t = <abstr>
# Hashtbl.add ages "ann" 31;;
- : unit = ()
# Hashtbl.add ages "ann" 32;;
- : unit = ()
# Hashtbl.find ages "ann";;
- : int = 32
# Hashtbl.length ages;;
- : int = 2
# Hashtbl.remove ages "ann";;
- : unit = ()
# Hashtbl.find ages "ann";;
- : int = 31

find sees the newest value, so everything looks fine at first. But the length is 2, and after remove the old 31 comes back. If you then list the table, "ann" shows up twice. Use replace unless you want this stacking on purpose.

Counting words, step by step

Counting is the job hash tables are best at. For each word: look up its count so far (none means 0), add 1, and store the new count.

# let count_words words =
    let t = Hashtbl.create 16 in
    List.iter
      (fun w ->
        let n = match Hashtbl.find_opt t w with Some n -> n | None -> 0 in
        Hashtbl.replace t w (n + 1))
      words;
    t;;
val count_words : 'a list -> ('a, int) Hashtbl.t = <fun>
# let t = count_words ["the"; "cat"; "saw"; "the"; "hat"];;
val t : (string, int) Hashtbl.t = <abstr>
# Hashtbl.find t "the";;
- : int = 2
# Hashtbl.find t "cat";;
- : int = 1

The type says 'a list: this works for a list of anything, not only strings, because a hash table can use any value as a key. Step through the five words and watch the table fill:

To get the counts out, Hashtbl.fold visits every pair and builds up a result, the same way List.fold_left does. Sorting the list afterwards gives an order you can rely on:

# Hashtbl.fold (fun w n acc -> (w, n) :: acc) t [];;
- : (string * int) list = [("cat", 1); ("saw", 1); ("the", 2); ("hat", 1)]
# List.sort compare (Hashtbl.fold (fun w n acc -> (w, n) :: acc) t []);;
- : (string * int) list = [("cat", 1); ("hat", 1); ("saw", 1); ("the", 2)]
In week 1

Your compiler keeps a hash table whose keys describe nodes ("an add of these two inputs") and whose values are the nodes themselves. Before it builds a node, it looks in the table. If an equal node is already there, it returns that one instead of making a copy. It is this same find-or-add pattern.

Count words with a hash table

Write word_counts : string list -> (string * int) list. It returns each distinct word once, with how many times it appears, sorted alphabetically. word_counts ["the"; "cat"; "the"] is [("cat", 1); ("the", 2)].

Count with find_opt and replace, get the pairs with Hashtbl.fold, then List.sort compare.

Building strings: Buffer and Printf

You know ^ joins two strings. In a loop it's tempting to grow a string with it:

# let s = ref "";;
val s : string ref = {contents = ""}
# for i = 1 to 4 do s := !s ^ string_of_int i done;;
- : unit = ()
# !s;;
- : string = "1234"

That works, but it is slow for long strings. OCaml strings can't change, so every ^ makes a brand new string and copies both halves into it. The fourth trip copies "123" again to make "1234". Adding 1,000 one-letter pieces copies 1 + 2 + 3 + ... + 1000 letters, about half a million, to build a string of 1,000. Doubling the pieces makes it four times slower.

A Buffer is a growable string made for this. You add pieces to the end, and it keeps spare room so it rarely has to copy. When you're done, Buffer.contents gives you the finished string:

# let b = Buffer.create 16;;
val b : Buffer.t = <abstr>
# Buffer.add_string b "1";;
- : unit = ()
# Buffer.add_string b ", 2";;
- : unit = ()
# Buffer.add_char b '!';;
- : unit = ()
# Buffer.contents b;;
- : string = "1, 2!"

Here it is in a loop that puts a comma between numbers. The trick is to add the separator before every piece except the first:

# let buf = Buffer.create 16 in
  for i = 1 to 5 do
    if i > 1 then Buffer.add_string buf ", ";
    Buffer.add_string buf (string_of_int i)
  done;
  Buffer.contents buf;;
- : string = "1, 2, 3, 4, 5"

Printf: numbers into text

Printf.sprintf builds a string from a format: a template where each % code is a hole for a value. Printf.printf takes the same format and prints the result instead of returning it.

# Printf.sprintf "%s is %d years old" "Ann" 31;;
- : string = "Ann is 31 years old"
# Printf.sprintf "%f" 3.14159;;
- : string = "3.141590"
# Printf.sprintf "%.2f" 3.14159;;
- : string = "3.14"
CodeFills inExample
%dan intPrintf.sprintf "%d" 42 is "42"
%sa stringPrintf.sprintf "[%s]" "hi" is "[hi]"
%fa float, 6 digits after the point"3.141590"
%.2fa float, 2 digits after the point, rounded"3.14"
\na newline (not a hole)Printf.printf "done\n"

OCaml checks the format against the values. Give %d a float and it is a type error before the program runs:

# Printf.sprintf "%d" 2.5;;
Line 1, characters 20-23:
1 | Printf.sprintf "%d" 2.5;;
                        ^^^
Error: This expression has type "float" but an expression was expected of type
         "int"

Join strings with a Buffer

Write join : string -> string list -> string, which puts sep between the parts. join ", " ["a"; "b"; "c"] is "a, b, c". An empty list gives "", and there is no separator at either end. The starter adds the parts but forgets the separator.

The separator goes before every part except the first. List.iteri works like List.iter, but your function gets two arguments, the index (starting at 0) and the part: List.iteri (fun i p -> ...) parts.

Equal, the same, and in order

Is [1; 2; 3] equal to [1; 2; 3]? It depends on what you mean, and OCaml has an operator for each meaning.

# let a = [1; 2; 3];;
val a : int list = [1; 2; 3]
# let b = [1; 2; 3];;
val b : int list = [1; 2; 3]
# let c = a;;
val c : int list = [1; 2; 3]
# a = b;;
- : bool = true
# a == b;;
- : bool = false
# a == c;;
- : bool = true

= is structural equality: "do these have the same contents?". It walks through both values piece by piece and compares everything. a and b hold the same numbers, so a = b is true.

== is physical equality: "are these the very same value in the computer's memory?". a and b were built separately, so there are two lists in memory that happen to look alike. let c = a doesn't copy anything. It gives a second name to the list a already names. So a == c is true.

One caution. Each line you type into utop is built on its own, which is why a == b is false here. A compiled program may store two identical constant lists only once, and then a == b is true. So don't use == to tell apart values you wrote out by hand. Values built while the program runs, like your compiler's nodes, are only the same when your code makes them the same.

Why have both? Because they cost different amounts. == compares two memory addresses, one step however big the values are. = has to look at everything inside, so comparing two trees with a million nodes takes a million steps.

Why the course cares

In week 1 your compiler uses hash consing: before building a node, it checks the hash table from the last section, and if an equal node exists it returns that one. The result is that two nodes with equal contents are always the very same value in memory. Then asking "are these two expressions equal?" needs only ==, one step, instead of walking two whole trees with =.

!= is not "not equal"

Each equality has its own "not": <> is the opposite of =, and != is the opposite of ==. Coming from other languages you'll reach for !=, and get surprises. [|1; 2|] <> [|1; 2|] is false (same contents), but [|1; 2|] != [|1; 2|] is true (two separate arrays). For everyday comparisons use = and <>.

compare and sorting

compare a b answers "which comes first?" with a number: negative if a is smaller, 0 if they're equal, positive if a is bigger. It works on ints, strings, lists, tuples, almost anything.

# compare 3 7;;
- : int = -1
# compare 7 3;;
- : int = 1
# compare 5 5;;
- : int = 0
# compare "pear" "apple";;
- : int = 1

List.sort takes a function shaped like compare and a list, and returns a new sorted list. Pass compare itself for the normal order. For the reverse order, pass a function that swaps its arguments:

# List.sort compare [3; 1; 2];;
- : int list = [1; 2; 3]
# List.sort (fun a b -> compare b a) [3; 1; 2];;
- : int list = [3; 2; 1]
# List.sort compare ["pear"; "apple"; "Apple"];;
- : string list = ["Apple"; "apple"; "pear"]
# List.sort compare [("b", 2); ("a", 5); ("a", 1)];;
- : (string * int) list = [("a", 1); ("a", 5); ("b", 2)]

Two things to notice. Strings compare letter by letter by their character codes, and every capital letter comes before every small letter, so "Apple" sorts before "apple". And pairs compare by their first part, and only look at the second part when the first parts are equal. That's why sorting the word counts earlier put them in alphabetical order.

  • Count things with a Hashtbl, using replace and find_opt, and avoid the add trap.
  • Build long strings with a Buffer and format numbers with Printf.sprintf.
  • Tell = from ==, and sort with List.sort compare.

Check yourself

What is the value of let c = ref 5 in c := !c * 2; !c?

What is in the box after c := !c * 2?

The ; runs the change first, then the whole expression is the value of !c.

The box starts at 5. c := !c * 2 puts 10 in it. Then !c reads 10, and that's the value of the whole expression.

let a = [| 4; 5; 6 |]. What does a.(3) do?

What number does the first slot have?

Three slots, numbered from 0. What's the last one?

The slots are 0, 1 and 2, so a.(3) is past the end. OCaml checks every index and raises Invalid_argument "index out of bounds". The last element is a.(Array.length a - 1), which is 6.

You run Hashtbl.add t "kiwi" 1 and then Hashtbl.add t "kiwi" 2 on an empty table. What are Hashtbl.find t "kiwi" and Hashtbl.length t?

Does add remove the old value?

add puts the new value in front of the old one. Which one does find see?

find sees the newest value, 2. But add kept the old one hidden behind it, so the table holds two bindings and the length is 2. With replace the answer would be 2 and 1.

What string does Printf.sprintf "%.2f" 2.0 return?

%.2f means a float with exactly two digits after the point.

Missing digits are filled with zeros.

"2.00". The .2 asks for two digits after the point, and the float 2.0 has none to show, so they're zeros.

What are [|1; 2|] <> [|1; 2|] and [|1; 2|] != [|1; 2|]?

<> is the opposite of =. != is the opposite of ==.

The two arrays have the same contents. Are they the same array in memory?

The contents are equal, so <> is false. But each [| |] makes a new array (an array can be changed, so OCaml never shares one behind your back), so they aren't the same value in memory, and != is true. That's why != is a trap for "not equal".

What is List.sort compare ["b"; "C"; "a"]?

Strings compare by character codes. Where do capital letters fall?

Every capital letter comes before every small letter. Answer in OCaml list syntax.

["C"; "a"; "b"]. Capital letters have smaller character codes than small letters, so "C" comes first, even though C is after a and b in the alphabet.
