Recursion and functions as values

This lesson has two targets. First, you will write a function that calls itself to walk a tree of any depth. Your compiler does that all through week 1. Second, you will write a function that makes and returns another function with a private dict inside. The first exercise of week 1 asks for exactly that.

Base case and step

Here is the function that made those five calls:

def evaluate(e):
    match e:
        case Num(v):
            return v
        case Add(left, right):
            return evaluate(left) + evaluate(right)
        case Mul(left, right):
            return evaluate(left) * evaluate(right)
        case _:
            raise TypeError(f"not an expression: {e!r}")

A function that calls itself, like this one or P.4's value, is recursive. Every recursive function has two parts:

  • The base case answers without calling itself. Here that is the Num case.
  • The step calls itself on something smaller and combines the answers. Here that is the Add and Mul cases, and "smaller" means a child box.

The function never asks how deep the tree is. Each call looks at one box and hands the boxes it reads to new calls. Every call moves one level closer to a leaf, so the calls must end.

The same shape answers other questions. To count the boxes in a tree:

  1. Answer the leaf. A Num is one box: return 1.
  2. Ask the children. count_nodes(left) and count_nodes(right).
  3. Combine. This box, plus both answers.
def count_nodes(e):
    match e:
        case Num(v):
            return 1
        case Add(left, right):
            return 1 + count_nodes(left) + count_nodes(right)
        case Mul(left, right):
            return 1 + count_nodes(left) + count_nodes(right)
        case _:
            raise TypeError(f"not an expression: {e!r}")

Where the waiting calls wait

In the trace, call 1 had to wait for call 3, which had to wait for call 5. Python keeps track with a frame for each call: a small record of that call's variables and the place to carry on from. The frames sit in a pile called the call stack. A call adds a frame on the end. A return removes it. Only the newest frame runs, and the others wait. Step through it:

Both the Add frame and the Mul frame have a variable called left. They don't clash, because each frame holds its own.

How deep is the tree?

Write depth(e): the number of nodes on the longest path from the node e to a leaf. A lone Num has depth 1. Add(Num(2), Mul(Num(3), Num(4))) has depth 3: Add, then Mul, then a Num. The starter has the classes. Keep them as they are.

A node is one level, plus the deeper of its two children. max(a, b) gives the larger of two numbers.

One case for two classes: the or-pattern, for when the repeated case bothers you

The Add and Mul cases of count_nodes are the same line twice. case Add(left, right) | Mul(left, right): is an or-pattern: it matches either class, and both sides name their fields the same way, so one case covers both.

def leaf_sum(e):
    match e:
        case Num(v):
            return v
        case Add(left, right) | Mul(left, right):
            return leaf_sum(left) + leaf_sum(right)
        case _:
            raise TypeError(f"not an expression: {e!r}")

Most tree functions you'll ever write have this shape: a case for the leaves, a case that calls itself on the children and combines the results, and a case _: that raises.

The same shape on numbers and lists

Recursion fits anything that holds a smaller copy of itself. A number holds a shorter number: 1234 is 123 with a 4 on the end. A list can hold lists. In both exercises, find the base case first.

A loop could do the same countdown. Recursion earns its keep on problems that contain smaller copies of themselves, like trees, where a loop gets awkward.

The factorial of n, written n!, is 1 * 2 * 3 * ... * n. So 3! is 6, and 0! is 1 by agreement. The key fact is that n! is n times (n − 1)!. That's a smaller copy of the same problem, so it turns straight into code:

def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)

print(factorial(3))

When the calls never stop

This function prints n and calls itself with n - 1. It has no base case.

def countdown(n):
    print(n)
    countdown(n - 1)

What does countdown(3) do?

Nothing in the function checks for 0. But every call adds a frame to the stack. Can the stack grow forever?

It prints 3, 2, 1, 0, -1, -2 and on. Each call adds a frame, and Python allows about 1000 frames. Then it stops the program.

The last line of the error is:

RecursionError: maximum recursion depth exceeded

Frames take memory. To stop a runaway function from using it all, Python limits how many frames can be on the stack at once. This recursion limit is 1000 by default.

When you see RecursionError, the first suspect is a base case that is missing or never reached. Check that every call really gets closer to it.

A tree too deep for the call stack

The second cause is sneakier: the function is correct, and the input is deep. Here is a tree that is a long chain, 1 + (1 + (1 + ...)), 5000 levels deep:

chain = Num(1)
for i in range(5000):
    chain = Add(Num(1), chain)

A correct recursive leaf_sum(chain) raises RecursionError. It needs about 5000 frames, one per level, and Python allows 1000.

The sturdy fix is to keep your own stack. The call stack holds "boxes still to do". You can hold them yourself in a list, which is limited only by your computer's memory:

def leaf_sum(e):
    stack = [e]
    total = 0
    while stack:
        node = stack.pop()
        match node:
            case Num(v):
                total += v
            case Add(left, right) | Mul(left, right):
                stack.append(left)
                stack.append(right)
            case _:
                raise TypeError(f"not an expression: {node!r}")
    return total
  1. Start with the whole tree. stack = [e].
  2. Take one box off. stack.pop() removes and returns the last item. while stack: keeps going until the list is empty.
  3. Deal with it. A leaf adds to total: total += v is short for total = total + v. Any other box puts its children on the list for later. The | means "either of these two classes".

Now leaf_sum(chain) returns 5001.

The same work, many times

The Fibonacci numbers start 0, 1, and each one after is the sum of the two before: 0, 1, 1, 2, 3, 5, 8. As code, with two base cases:

def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(20) is 6765. How many calls to fib does it take to get there?

fib(20) calls fib(19) and fib(18). What does fib(19) call?

21,891 calls. fib(19) calls fib(18) again, and both of those call fib(17), and so on. fib(3) alone is worked out 2,584 times.

The same input always gives the same answer, so work each one out once and remember it. A dict that remembers answers is called a cache. The key is the input, and the value is the answer.

memo = {}

def fib(n):
    if n in memo:
        return memo[n]
    if n < 2:
        return n
    answer = fib(n - 1) + fib(n - 2)
    memo[n] = answer
    return answer
  1. Look first. If the answer is in the dict, return it. No more calls.
  2. Do the work once. Otherwise work it out the slow way.
  3. Store before returning. The next call with the same n finds it.

Now fib(20) takes 39 calls, not 21,891. Week 1 uses this move twice: once so the same node is never built twice, and once so a walk never visits the same node twice.

You stand on the top left square of a grid and may step only right or down. paths(r, c) counts the ways to reach the square r rows down and c columns across: the ways to reach the square above it plus the ways to reach the square to its left. Without a cache, the count grows by about 1.6 times for each step of n. Remembering results like this is called memoization.

functools.cache is a decorator that does the same job: it keeps a dict from arguments to results, and a repeated call returns the stored result without running the function. This version counts how often the body runs, in a variable outside the function (global calls lets the function change that variable):

from functools import cache

calls = 0

@cache
def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20))
print(calls)
6765
21

Each n from 0 to 20 runs once, so the body runs 21 times. The arguments become dict keys, so they must be hashable: a frozen dataclass works, a list doesn't. Lesson 0.7 explains when a plain dict you manage yourself is the better memo.

A function is a value

Now the second target. Read this small program and predict.

def shout(s):
    return s.upper() + "!"

yell = shout
print(yell("hi"))

What does it print?

yell = shout has no parentheses, so nothing is called on that line. What does yell hold afterwards?

yell holds the same function as shout, so yell("hi") runs it.

In Python a function is a value, like a number or a string. def makes a function and stores it in a variable. Without parentheses, shout is the function itself. With them, shout("hi") calls it.

So you can pass a function to another function, which calls it for you:

def apply_twice(f, x):
    return f(f(x))

print(apply_twice(shout, "hi"))

It prints HI!!.

You saw this in P.3: sorted calls its key= function on every item and sorts by what comes back. sorted(["pear", "fig", "banana"], key=len) is ['fig', 'pear', 'banana'].

When the function you need is tiny, a lambda writes it in place. lambda w: -len(w) is a function that takes w and returns -len(w), with no def and no return.

With apply_twice from above, what is apply_twice(double, 3)?

    return n * 2

It works out double(double(3)). Do the inner call first.

double(3) is 6, and double(6) is 12. apply_twice doesn't care which function it gets.

A function that makes a function

In lesson 1.1 you will write create(), a function that returns another function, make, which remembers things in a dict that nothing else can touch. Here is that shape in three small steps, with a counter that counts how often it has seen each word.

  1. Put a function inside a function. count is defined inside tally, so it can use tally's variable seen. not in is the opposite of in. 
    def tally():
    seen = {}
    def count(word):
        if word not in seen:
            seen[word] = 0
        seen[word] = seen[word] + 1
        return seen[word]
    count("a")
    return count("a")
    tally() returns 2. Call tally() again and it is 2 again, because each call runs seen = {} and starts with a fresh dict.
  2. Return the inner function. Don't call count. Hand it back, without parentheses. 
    def make_counter():
    seen = {}
    def count(word):
        if word not in seen:
            seen[word] = 0
        seen[word] = seen[word] + 1
        return seen[word]
    return count
  3. Call what came back, twice. 
    c = make_counter()
c("a")
c("a")

By the last line, make_counter has already returned. What does the second c("a") return?

seen = {} is a line of make_counter, not of count. How many times did make_counter run?

2. make_counter ran once, so there is one dict. The returned count still holds on to it, and Python keeps a value alive for as long as something can reach it.

A function bundled with the outer variables it uses is called a closure. c is a closure: the function count plus its own seen.

Two counters, two dicts

Every call to make_counter() runs its body again. So it makes a new dict and a new count that holds that dict:

c = make_counter()
d = make_counter()
print(c("a"))
print(c("a"))
print(d("a"))

It prints 1, 2 and 1: counting with c doesn't move d. And no other code can reach either dict: the name seen exists only inside make_counter. That is what "private" means here.

Lesson 1.1's create() is this same shape. create plays make_counter, make plays count, and the dict holds nodes.

A function with a private table

Write create(). It returns a function make(name) that gives every name a number. A name it has not seen gets the next number: 0, then 1, then 2. A name it has seen gets the same number as before. So make("x"), make("y"), make("x") return 0, 1, 0. Two create() calls must not share numbers.

len(d) is how many keys a dict holds, which is also the next unused number.

nonlocal: for when the inner function assigns to an outer variable and you get UnboundLocalError

The counter above changes a dict, which needs nothing special. Assigning to an outer variable with = or += is different:

def make_ticker():
    count = 0
    def next_number():
        nonlocal count
        count += 1
        return count
    return next_number

t = make_ticker()
print(t())
print(t())
1
2

nonlocal count says "the count I change here is the outer one". Without it, count += 1 would make Python treat count as a new variable belonging to next_number, and the first call would fail with UnboundLocalError: cannot access local variable 'count' where it is not associated with a value. You only need nonlocal to assign to an outer variable. Reading it, or changing a dict it names, works without.
