Learn OCaml · Lesson 2

Functions and types

A function is a value that takes input and gives back a result. In OCaml you'll write dozens of small ones, call them without brackets, pass them to each other, and let OCaml work out their types for you. This lesson shows how all of that reads.

Your first function

You define a function with the same let you used for values. The difference is that the name is followed by one or more parameters: names for the inputs.

# let double x = x * 2;;
val double : int -> int = <fun>
# double 21;;
- : int = 42

let double x = x * 2 reads "double of x is x * 2". The part after = is the body, the expression that gives the result. There is no return keyword: the value of the body is the result.

To call it, write the function name, a space, then the argument: double 21. No brackets. With two parameters, you write both arguments after the name, separated by spaces, not commas:

# let add a b = a + b;;
val add : int -> int -> int = <fun>
# add 3 4;;
- : int = 7

Why no brackets and commas? Calling functions is the most common thing you do in OCaml, so it gets the lightest possible syntax. A space means "apply this function to this". Brackets are still used, but only for grouping, the way they are in maths:

# double 3 + 1;;
- : int = 7
# double (3 + 1);;
- : int = 8

Calling a function grabs its argument before any operator gets a turn. So double 3 + 1 is (double 3) + 1, which is 7. If you want to double 4, put brackets around 3 + 1.

Negative arguments need brackets

For the same reason, double -7 reads as double minus 7, which is nonsense: you can't subtract a number from a function. Write double (-7).

# let abs_val n = if n < 0 then -n else n;;
val abs_val : int -> int = <fun>
# abs_val -7;;
Line 1, characters 0-7:
1 | abs_val -7;;
    ^^^^^^^
Error: This expression has type "int -> int"
       but an expression was expected of type "int"
# abs_val (-7);;
- : int = 7

Use the recipe from lesson O.1. The marked piece is abs_val itself, and it has type int -> int (a function). The place, the left side of a minus sign, expects an int. OCaml read your - as subtraction.

f (3, 4) is not f 3 4

If you come from another language, you'll write add (3, 4) sooner or later. In OCaml, (3, 4) is a single value, a pair of two numbers (pairs are called tuples, see lesson O.3). So add (3, 4) passes one pair where an int was expected.

# add (3, 4);;
Line 1, characters 4-10:
1 | add (3, 4);;
        ^^^^^^
Error: This expression has type "'a * 'b"
       but an expression was expected of type "int"

The marks are under (3, 4). Its type 'a * 'b means "a pair of something and something" (the 'a notation is explained further down). add wanted an int there. Fix: add 3 4.

Reading arrow types

Look at what utop said about the functions above:

val double : int -> int = <fun>
val add : int -> int -> int = <fun>

The value is shown as <fun> because a function can't be printed. Its type is the useful part. An arrow -> means "takes ... and gives ...":

TypeRead it as
int -> inttakes an int, gives an int
int -> int -> inttakes an int, then another int, gives an int
string -> stringtakes a string, gives a string
string -> int -> unittakes a string, then an int, gives unit (it probably prints something)
int -> booltakes an int, answers yes or no

The rule: the last type is the result, every type before it is an input, in order. You'll often know what a library function does from its type alone. String.length : string -> int can hardly do anything except measure a string.

Local names with let ... in

Inside a function you often want a name for a step along the way. let ... in makes a name that exists only in the expression after in:

# let price_with_tax p =
    let tax = p * 8 / 100 in
    p + tax;;
val price_with_tax : int -> int = <fun>
# price_with_tax 250;;
- : int = 270
# tax;;
Line 1, characters 0-3:
1 | tax;;
    ^^^
Error: Unbound value "tax"
Hint: Did you mean "max" or "tan"?

Read let tax = p * 8 / 100 in p + tax as "let tax be 8 percent of p in the expression p + tax". Once that expression is done, tax is gone. Outside the function there is no tax, and OCaml says so: "Unbound value" means "I don't know this name". (Its guesses, max and tan, are real functions with similar spellings.)

You can chain several, one per line. Each name can use the ones before it:

let hypotenuse a b =
  let a2 = a *. a in
  let b2 = b *. b in
  sqrt (a2 +. b2)

hypotenuse 3.0 4.0 is 5.. Keeping helper names local means they can't clash with names elsewhere, and a reader knows they matter only here.

if is an expression

In OCaml, if doesn't "do one thing or the other". It has a value: the value of whichever branch was chosen.

# let describe_temp t = if t < 10 then "cold" else if t < 25 then "mild" else "hot";;
val describe_temp : int -> string = <fun>
# describe_temp 18;;
- : string = "mild"
# let is_even n = n mod 2 = 0;;
val is_even : int -> bool = <fun>

The whole if ... then ... else ... is the function body, and its value is the result. You can chain else if as many times as you like. Notice is_even doesn't need an if at all: n mod 2 = 0 is already a bool.

Because an if has a value, that value needs one type. So both branches must have the same type:

# if 3 > 2 then "yes" else 0;;
Line 1, characters 25-26:
1 | if 3 > 2 then "yes" else 0;;
                             ^
Error: This expression has type "int" but an expression was expected of type
         "string"

OCaml saw the then branch first, a string, so it expected the else branch to be a string as well. This is the same rule that made the if without else fail in lesson O.1: the missing branch is (), so the other one must be unit too.

Recursion with let rec

A recursive function is one that calls itself. That sounds circular, but it works as long as each call is on a smaller problem and there is a smallest problem you answer directly. Here is factorial: 4! is 4 × 3 × 2 × 1.

# let rec factorial n = if n <= 1 then 1 else n * factorial (n - 1);;
val factorial : int -> int = <fun>
# factorial 4;;
- : int = 24

Read it as two cases. The base case: if n is 1 or less, the answer is 1. The recursive case: otherwise, the answer is n times the factorial of one less. Each call makes n smaller, so it must reach the base case. Step through factorial 4. Each call waits for the one it made, like a stack of plates.

The same thing as a trace table, one row per call. Read the "waits for" column top to bottom, then the "returns" column bottom to top.

CallnBase case?Waits forReturns
factorial 44no4 * factorial 34 × 6 = 24
factorial 33no3 * factorial 23 × 2 = 6
factorial 22no2 * factorial 12 × 1 = 2
factorial 11yesnothing1

Why the extra word rec? Normally a let name can't be used inside its own definition. That is what makes shadowing safe: in let x = x + 1, the x on the right is the old x. rec says "this name refers to itself". Forget it and OCaml tells you, with a very direct hint. (This uses a new name, fact. If you reused factorial, the factorial you already defined would be found and there would be no error.)

# let fact n = if n <= 1 then 1 else n * fact (n - 1);;
Line 1, characters 39-43:
1 | let fact n = if n <= 1 then 1 else n * fact (n - 1);;
                                           ^^^^
Error: Unbound value "fact"
Hint: If this is a recursive definition,
you should add the "rec" keyword on line 1

One more, to practise reading. sum_to n adds up 1 + 2 + ... + n:

# let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1);;
val sum_to : int -> int = <fun>
# sum_to 4;;
- : int = 10
CallnWaits forReturns
sum_to 444 + sum_to 34 + 6 = 10
sum_to 333 + sum_to 23 + 3 = 6
sum_to 222 + sum_to 12 + 1 = 3
sum_to 111 + sum_to 01 + 0 = 1
sum_to 00nothing (base case)0
A recursion that never shrinks

If the recursive call doesn't move toward the base case, for example sum_to n instead of sum_to (n - 1), the calls never end. Your program hangs, or stops with "Stack overflow". Before you run a recursive function, check two things: there is a base case, and every call gets closer to it.

Power with let rec

Write power base exp: base multiplied by itself exp times, for exp of 0 or more. power 2 10 is 1024 and power 5 0 is 1.

Base case: anything to the power 0 is 1. Then say it as a sentence, the way factorial does.

Count the digits

Write count_digits n for n of 0 or more: how many digits n has when written out. count_digits 12345 is 5, and count_digits 0 is 1.

What is 12345 / 10? How many digits does it have?

Types OCaml works out for you

You haven't written a single type yet, but every reply has had one. OCaml looks at how you use each name and works the types out. This is called type inference. In let double x = x * 2, x is used with *, which takes ints, so x must be an int, and so must the result.

You can still write types yourself, after a colon. It changes nothing when they match what OCaml inferred, and it helps when you want to be sure, or when you are reading an error and want OCaml to check your belief:

# let add (x : int) (y : int) : int = x + y;;
val add : int -> int -> int = <fun>

Sometimes nothing in the body pins a type down. The simplest case is a function that gives back its argument unchanged:

# let id x = x;;
val id : 'a -> 'a = <fun>
# id 5;;
- : int = 5
# id "hi";;
- : string = "hi"

'a (say "alpha") is a type variable. It stands for "any type". 'a -> 'a reads "takes a value of any type, gives back a value of that same type". Use it with an int and 'a is int for that call. Use it with a string and 'a is string. A function like this is called generic (or polymorphic): it works for many types because it never looks inside its argument.

You'll meet 'a constantly in library functions:

# List.length;;
- : 'a list -> int = <fun>
# let max_of a b = if a > b then a else b;;
val max_of : 'a -> 'a -> 'a = <fun>
# max_of 3 9;;
- : int = 9
# max_of "apple" "pear";;
- : string = "pear"

List.length counts the elements of a list of anything, so its type says "a list of any type, gives an int" (lists are lesson O.3). max_of works on any type as long as both arguments have the same type, because they share the one 'a. When you see 'a and 'b in one type, they may be different types.

Functions are values

A function is a value like 5 or "hi". You can make one without a name, give it to another function, or get one back.

Functions without names

fun x -> x * 2 is a function with no name, called an anonymous function. Read the arrow as "goes to": "x goes to x times 2".

# fun x -> x * 2;;
- : int -> int = <fun>
# (fun x -> x * 2) 21;;
- : int = 42

In fact let double x = x * 2 is a shorter way to write let double = fun x -> x * 2. Both give the same val double : int -> int. A named function is a value with a name.

Passing a function to a function

# let apply_to_5 f = f 5;;
val apply_to_5 : (int -> 'a) -> 'a = <fun>
# apply_to_5 double;;
- : int = 10
# apply_to_5 (fun x -> x * x);;
- : int = 25
# apply_to_5 string_of_int;;
- : string = "5"

Read the type slowly. The brackets in (int -> 'a) -> 'a group one input: "takes a function from int to anything, gives back that anything". Pass double and you get an int, pass string_of_int and you get a string.

Why care? Because it lets you write the "walk over everything" part once and pass in the "what to do with each one" part. Lesson O.3 does exactly that with lists, and in the course your compiler walks a whole tree of operations the same way.

Apply a function twice

Write apply_twice f x, which calls f on x, then calls f again on that result. apply_twice (fun x -> x + 3) 10 is 16.

Brackets are for grouping. What do you want to pass to the outer f?

Giving a function some of its arguments

Here is something that surprises everyone. Give add only one argument:

# let add_ten = add 10;;
val add_ten : int -> int = <fun>
# add_ten 5;;
- : int = 15

No error. add 10 is a new function that is still waiting for the second number. This is called partial application. It explains the arrow types: int -> int -> int really means int -> (int -> int), "takes an int and gives back a function that takes an int". add 3 4 gives add the 3, gets a function back, and gives that function the 4.

You won't need this often at first. Know it for two reasons. It is why calls have no commas: each space hands over one more argument. And it is why forgetting an argument gives a strange type error instead of a "missing argument" message. If OCaml says something has type int -> int where you expected int, you left an argument out.

The pipe |>

Nested calls read inside out. To find out how many digits 42 has, you might write:

# String.length (string_of_int (double 21));;
- : int = 2
# 21 |> double |> string_of_int |> String.length;;
- : int = 2

The second line does the same thing. x |> f means f x: "send x into f". A chain of them reads left to right, in the order things happen: start with 21, double it, turn it into a string, measure it. When you have three or more steps, the pipe is usually easier to read. With one step, double 21 is fine.

Printing, unit and ;

Some functions don't need any input. They still take one argument, the value (), because every OCaml function takes something:

# let say_hi () = print_endline "hi";;
val say_hi : unit -> unit = <fun>
# say_hi ();;
hi
- : unit = ()
# say_hi;;
- : unit -> unit = <fun>

unit -> unit: takes nothing interesting, gives nothing interesting. It is there for what it does, which is print. The last line is a common slip: say_hi without () doesn't call it, it only names the function, so nothing is printed.

To do several things in a row, put ; between them. a; b means "do a, throw its () away, then do b, and the value of the whole thing is b":

# let report name score =
    print_string name;
    print_string ": ";
    print_int score;
    print_newline ();;
val report : string -> int -> unit = <fun>
# report "Ada" 90;;
Ada: 90
- : unit = ()

print_string prints without a new line, print_int prints an int, and print_newline () ends the line. Note there is no ; after the last step: ; goes between steps, not after each one. The last step can also give a real value:

# let shout s =
    print_endline (String.uppercase_ascii s);
    String.length s;;
val shout : string -> int = <fun>
# shout "hey";;
HEY
- : int = 3
Only unit belongs before a ;

The value before a ; is thrown away. If it isn't (), you probably made a mistake, and OCaml warns you.

# let next x = x + 1; x;;
Line 1, characters 13-18:
1 | let next x = x + 1; x;;
                 ^^^^^
Warning 10 [non-unit-statement]: this expression should have type unit.

val next : int -> int = <fun>

This is a warning, not an error: the definition still happened. x + 1 was computed and thrown away, and next 5 is 5, not 6. In a dune project (lesson O.6) this warning stops the build, which is what you want.

What you can do now

  • Define functions with let and call them with spaces: add 3 4, using brackets only to group.
  • Read arrow types: the last type is the result, the ones before are inputs.
  • Make local names with let ... in.
  • Use if ... then ... else as an expression whose branches share one type.
  • Write recursive functions with let rec, with a base case, and trace them with a table.
  • Read 'a as "any type, the same each time it appears".
  • Write anonymous functions with fun, pass functions to functions, and recognise partial application.
  • Chain calls with |>, and sequence printing steps with ;.

Check yourself

With let double x = x * 2, what is double 3 + 1?

Does the function call happen before or after the +?

It is (double 3) + 1.

A function call grabs its argument first, so it is (double 3) + 1, which is 6 + 1 = 7. double (3 + 1) would be 8.

A function has type string -> int -> bool. What does it give back?

Which position in an arrow type is the result?

The last type is the result. This function takes a string, then an int, and answers true or false.

Why does add (3, 4) give a type error when add is let add a b = a + b?

What type does OCaml say (3, 4) has?

Brackets are fine for grouping. What does the comma do?

The comma makes a pair, so (3, 4) is a single argument. OCaml shows its type as 'a * 'b, a pair of two things, and add wanted an int there. Call it as add 3 4.

With let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1), what is sum_to 4?

Write it out: 4 + sum_to 3, and keep going until you reach the base case.

4 + 3 + 2 + 1 + 0.

The calls go down to sum_to 0, which is 0, and then the additions happen on the way back: 1, 3, 6, 10.

utop says val swap : 'a * 'b -> 'b * 'a. What does swap (1, "one") give?

Here 'a is int and 'b is string. Substitute them into the result type.

Are 'a and 'b allowed to be different types?

The result type is 'b * 'a, here string * int, so the pair comes back swapped: ("one", 1). Two different type variables may stand for two different types.

With let add a b = a + b, what is add 10?

What does int -> int -> int look like with brackets added?

int -> int -> int is int -> (int -> int). Giving one int gives back a function waiting for the other. This is partial application.

What is "hello" |> String.uppercase_ascii |> String.length?

Read the pipe left to right. What does the first step turn "hello" into?

Does uppercasing change how many letters a word has?

It is String.length (String.uppercase_ascii "hello"). "HELLO" still has 5 letters, so the answer is 5.
