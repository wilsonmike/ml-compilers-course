Learn OCaml · Lesson 2

Functions and types

A function is a calculation with a name, so you can use it again with different numbers. In this lesson you'll write small functions, make them choose between two results and make one call itself. You'll finish with a function that builds another function. Your compiler is made of pieces like these.

Goal

Write functions that take numbers, choose with if, call themselves and build other functions.

Where this goes

Two places later in the course need this lesson. In Build the thing that runs it you write apply op a b, a function with three inputs that picks one of several results. In lesson 1.1 you write a function that builds and returns another function. The last two screens here get you ready for that one.

Values and their types, let, arithmetic with + and +., and how to read a type error. All of it is in O.1, which also gets OCaml and the exercise runner working on your machine.

Warm up

Two questions from O.1, from memory. Pulling an idea back out of your head is what makes it stay.

What number does the second reply show?

# let price = 4;;
# price * 3;;

The first line gives the value 4 a name. The second line uses the name.

price is 4, and 4 * 3 is 12. The reply is - : int = 12.

Which line is a type error?

One of the two plus signs works only on whole numbers.

+ adds two int values. Numbers with a decimal point are float values, and they need +. with a dot.

Name a calculation to use it again

Say you need the double of 21, then of 8, then of 150. You could type 21 * 2, 8 * 2 and 150 * 2. The calculation is the same each time and only the number changes. A function is a calculation with a name and a gap for the part that changes.

# let double x = x * 2;;
val double : int -> int = <fun>
# double 21;;
- : int = 42

This is the let from O.1 with one new thing: a second name, x, after the function's name. x is a parameter, a name for the input. The part after = is the body, the expression that gives the result. There is no return word. The value of the body is the result.

To call a function means to use it. Write its name, a space, then the input, which is called the argument. Here is what OCaml does with double 21:

  1. Find the function. double has the parameter x and the body x * 2.
  2. Fill in the parameter. For this call, x is 21.
  3. Work out the body. 21 * 2 is 42. That is the value of the call.

In the first reply, <fun> means "a function", because a function can't be printed. The part with the arrow is its type. You'll read it a few screens from now.

A function can have more than one parameter. Write them one after another, and call it with the arguments in the same order, with spaces between them:

# let add a b = a + b;;
val add : int -> int -> int = <fun>
# add 3 4;;
- : int = 7

Hours and minutes

Write minutes h m: how many minutes there are in h hours and m minutes. minutes 1 30 is 90. The body is 0 right now.

Calls come before arithmetic

In school math you write f(2 + 3), and the parentheses show where the input stops. An OCaml call has no parentheses. So where does the argument stop? Predict before you read on.

With let double x = x * 2, what is double 2 + 3?

Either the call happens first or the + does. Work out both and pick one.

A call takes only the one value right next to it. So this is (double 2) + 3, which is 4 + 3 = 7. To get 10, write double (2 + 3).

A space after a function's name means "call it on the next value". That happens before +, * or any other operator gets a turn. Parentheses do not make the call. They only group, the way they do in arithmetic.

# double 2 + 3;;
- : int = 7
# double (2 + 3);;
- : int = 10

The habit to build: when an argument is more than a single name or number, put parentheses around it. That covers a sum, as in double (2 + 3). It covers another call, as in double (double 3). And it covers a negative number, as in double (-7), because double -7 reads as "double minus 7".

No commas either

add (3, 4) is not add 3 4. In OCaml a comma glues two values into one value called a pair (lesson O.3). So add (3, 4) hands add one argument of the wrong type, and you get a type error.

Double the sum

double_sum a b should add a and b, then double the total. double_sum 1 2 should be 6. Right now it gives 4. Repair the body.

The error messages these two slips give, for when you meet one 
# double -7;;
Line 1, characters 0-6:
1 | double -7;;
    ^^^^^^
Error: This expression has type "int -> int"
       but an expression was expected of type "int"
# double (-7);;
- : int = -14

Use the recipe from O.1. The marked piece is double itself, and it has type int -> int, a function. The place it sits in, the left side of a minus sign, expects an int. OCaml read your - as subtraction, and you can't subtract a number from a function.

# add (3, 4);;
Line 1, characters 4-10:
1 | add (3, 4);;
        ^^^^^^
Error: This expression has type "'a * 'b"
       but an expression was expected of type "int"

The marks are under (3, 4). Its type 'a * 'b means "a pair of something and something". add wanted an int there. The repair is add 3 4.

Choose between two results

A shop charges 5 for shipping, and nothing when the order is 50 or more. That is one function with two possible results, so it has to ask a question. In OCaml the question is a bool, a value that is true or false, such as total >= 50.

# let shipping total = if total >= 50 then 0 else 5;;
val shipping : int -> int = <fun>
# shipping 20;;
- : int = 5
# shipping 80;;
- : int = 0

Read it as: if the question is true, the value is the then part. If not, the value is the else part. Now a prediction.

What is 1 + (if 3 > 2 then 10 else 20)?

Work out the part in parentheses first. Is 3 greater than 2?

3 > 2 is true, so the if has the value 10, and 1 + 10 is 11. An if can sit anywhere a number can, because it is a value.

So if is an expression, the word from O.1 for a piece of code that has a value. It does not "do one thing or the other". It is one value or the other. Two rules follow from that:

  1. Write both parts. The if needs a value whichever way the question goes, so give it a then and an else.
  2. Give both parts the same type. The whole if has one type. if 3 > 2 then "yes" else 0 is a type error, because one part is a string and the other is an int.

For more than two results, put another if in the else part:

# let describe_temp t = if t < 10 then "cold" else if t < 25 then "mild" else "hot";;
val describe_temp : int -> string = <fun>
# describe_temp 18;;
- : string = "mild"

The bigger of two

Write bigger a b, which gives the larger of two ints. bigger 3 9 is 9. Right now it always gives a. You will write this again as the max op of your calculator.

The error for parts with different types, and an if with no else, for when you meet them 
# if 3 > 2 then "yes" else 0;;
Line 1, characters 25-26:
1 | if 3 > 2 then "yes" else 0;;
                             ^
Error: This expression has type "int" but an expression was expected of type
         "string"

OCaml saw the then part first, a string, so it expected the else part to be a string as well.

You may leave out else in one case. OCaml then uses () for the missing part, so the then part must have type unit too. () is the value that code gives back when it does something, such as printing or changing a value, and has no answer to return. Lesson O.5 is where you first need it.

A question is already a bool, so a function that answers yes or no needs no if: let is_even n = n mod 2 = 0 has type int -> bool.

Read the type OCaml prints

Each time you defined a function, the reply had a type with an arrow in it, like val double : int -> int. You never typed that. OCaml worked it out from the body. Try to do the same.

You type let is_big n = n > 100;;. Which type does the toplevel print for is_big?

What type is n, if it can be compared with 100? What type is the answer to a question?

n is compared with 100, so it is an int. The body n > 100 is a question, so the result is a bool. The reply is val is_big : int -> bool = <fun>.

Read an arrow as "takes this, gives that". The input is on the left and the result is on the right.

TypeRead it as
int -> inttakes an int, gives an int
int -> booltakes an int, answers true or false
int -> stringtakes an int, gives a string
int -> int -> inttakes an int, then another int, gives an int

The rule: the last type is the result, and every type before it is an input, in order. That is why add, with two parameters, has two arrows.

You may write the types yourself, after a colon. Exercise starters often do: let add (a : int) (b : int) : int = a + b is the same add, with each parameter's type and then the result's type spelled out.

Type a function's name alone and the toplevel shows its type. This one comes with OCaml:

# String.length;;
- : string -> int = <fun>

It takes a string and gives an int: the length you used in O.1.

Which type fits describe_temp from the last screen, which turns 18 into "mild"?

How many inputs does it take? What type is "mild"?

One input, an int, and the result is a string. The input goes on the left of the arrow.

Writing types yourself, and types with 'a in them, for when a reply shows a letter with a tick mark

OCaml looks at how you use each name and works the types out. This is called type inference. In let double x = x * 2, x is used with *, which takes ints, so x must be an int, and so must the result.

You can still write types yourself, after a colon. It changes nothing when they match what OCaml inferred. It helps when you are reading an error and want OCaml to check what you believe:

# let add (x : int) (y : int) : int = x + y;;
val add : int -> int -> int = <fun>

Sometimes nothing in the body pins a type down. The simplest case is a function that gives back its argument unchanged:

# let id x = x;;
val id : 'a -> 'a = <fun>
# id 5;;
- : int = 5
# id "hi";;
- : string = "hi"

'a (say "alpha") is a type variable. It stands for "any type". 'a -> 'a reads "takes a value of any type, gives back a value of that same type". Use it with an int and 'a is int for that call. Use it with a string and 'a is string. A function like this is called generic (or polymorphic): it works for many types because it never looks inside its argument.

# let max_of a b = if a > b then a else b;;
val max_of : 'a -> 'a -> 'a = <fun>
# max_of 3 9;;
- : int = 9
# max_of "apple" "pear";;
- : string = "pear"

max_of works on any type as long as both arguments have the same type, because they share the one 'a. When you see 'a and 'b in one type, they may be different types.

A function that calls itself

You want sum_to n, which adds the whole numbers from 1 up to n. sum_to 4 is 4 + 3 + 2 + 1. For 4 you can type that out. For any n you can't, because you don't know how many numbers to type.

Here is the way in. sum_to 4 is 4 plus everything below it, and "everything below it" is sum_to 3. So a big sum can ask for a smaller sum. The asking has to stop somewhere: sum_to 0 is 0, with nothing left to add.

Follow sum_to 3 by hand, one call per row. Read the "needs" column from top to bottom. Then read the "gives" column from bottom to top.

CallNeedsGives
sum_to 33 + sum_to 23 + 3 = 6
sum_to 22 + sum_to 12 + 1 = 3
sum_to 11 + sum_to 01 + 0 = 1
sum_to 0nothing0

Two more rows go on top of the table: sum_to 4, then sum_to 5 above it. What does sum_to 5 give?

sum_to 4 needs 4 + sum_to 3, and the table says what sum_to 3 gives.

sum_to 4 gives 4 + 6 = 10. sum_to 5 needs 5 + sum_to 4, and 5 + 10 is 15. You did not have to redo the smaller sums.

The table turns into code almost word for word:

# let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1);;
val sum_to : int -> int = <fun>
# sum_to 4;;
- : int = 10

A function that calls itself is called recursive. It has two parts, and now they get names:

  1. The base case. The smallest input, answered at once with no further call. Here: when n is 0, the answer is 0.
  2. The step. Every other input, answered with a call on a smaller number. Here: n + sum_to (n - 1).

The word rec after let tells OCaml that the function may use its own name in its body.

Calls wait, then answers come back

Here is a second recursive function. The factorial of 4 is 4 × 3 × 2 × 1. Base case: for 1 or less, the answer is 1. Step: n times the factorial of one less.

# let rec factorial n = if n <= 1 then 1 else n * factorial (n - 1);;
val factorial : int -> int = <fun>
# factorial 4;;
- : int = 24

Step through factorial 4. Each call waits for the call it made, like plates in a pile. Before each click, say which call comes next or which answer comes back.

A recursion that never shrinks

If the step doesn't move toward the base case, for example sum_to n where it should say sum_to (n - 1), the calls never end. Your program hangs, or stops with "Stack overflow". Before you run a recursive function, check two things: there is a base case, and every call gets closer to it.

Power with let rec

Repair power base exp: base multiplied by itself exp times, for exp of 0 or more. power 2 10 is 1024 and power 5 0 is 1. The base case is written. The step is wrong.

Anything to the power 0 is 1. Then say the step as a sentence, the way factorial does.

Count the digits

Write count_digits n for n of 0 or more: how many digits n has when written out. count_digits 12345 is 5, and count_digits 0 is 1.

What is 12345 / 10? How many digits does it have?

Why rec is a separate word, and the error when you forget it

Normally a let name can't be used inside its own definition. That is what makes it safe to reuse a name: in let x = x + 1, the x on the right is the old x. rec says "this name refers to itself". Forget it and OCaml tells you, with a very direct hint. (This uses a new name, fact. If you reused factorial, the factorial you already defined would be found and there would be no error.)

# let fact n = if n <= 1 then 1 else n * fact (n - 1);;
Line 1, characters 39-43:
1 | let fact n = if n <= 1 then 1 else n * fact (n - 1);;
                                           ^^^^
Error: Unbound value "fact"
Hint: If this is a recursive definition,
you should add the "rec" keyword on line 1

A name that lives inside a function

The last screens build up to a function that returns a function, in three small pieces. This is the first. Inside a body you often want a name for a step along the way. let ... in makes one:

# let price_with_tax p =
    let tax = p * 8 / 100 in
    p + tax;;
val price_with_tax : int -> int = <fun>
# price_with_tax 200;;
- : int = 216

Read the body as "let tax be 8 percent of p, in the expression p + tax". For 200, tax is 16 and the result is 216.

Right after that, you type tax;; at the toplevel. What happens?

Where does the name tax exist? Look at what comes after in.

The reply is Error: Unbound value "tax", which means "I don't know this name". tax exists only in the expression after in.

A name made with let ... in is local: it can be used only in the expression after in. Each call of price_with_tax makes its own fresh tax, uses it and lets it go. Nothing outside the function can see it or clash with it.

So a function can keep private names. Hold on to that for two screens.

Several local names in a row, for longer bodies

You can chain several, one per line. Each name can use the ones before it:

let hypotenuse a b =
  let a2 = a *. a in
  let b2 = b *. b in
  sqrt (a2 +. b2)

hypotenuse 3.0 4.0 is 5.. Keeping helper names local means they can't clash with names elsewhere, and a reader knows they matter only here.

A function is a value too

Every reply for a function said <fun> in the spot where a value goes. That is because a function is a value, like 5 or "hi". You can write one without giving it a name:

# fun x -> x * 2;;
- : int -> int = <fun>
# (fun x -> x * 2) 21;;
- : int = 42

Read fun x -> x * 2 as "a function that takes x and gives x * 2". The second line calls it on 21 right away. In fact let double x = x * 2 is a short way to write let double = fun x -> x * 2. A named function is a function value with a name.

A value can be handed to a function, so a function can be handed to a function. Here f is a parameter that holds a function:

# let apply_to_5 f = f 5;;
val apply_to_5 : (int -> 'a) -> 'a = <fun>
# apply_to_5 double;;
- : int = 10
# apply_to_5 (fun x -> x * x);;
- : int = 25

In the type, the parentheses group one input: a function that takes an int. The 'a stands for "whatever type that function gives". Lesson O.3 uses this idea to do one thing to every item of a list.

What is apply_to_5 (fun x -> x + 1)?

The body of apply_to_5 is f 5. Here f is the function you passed in.

f 5 with f filled in is (fun x -> x + 1) 5, which is 6.

Apply a function twice

Write apply_twice f x, which calls f on x, then calls f again on that result. apply_twice (fun x -> x + 3) 10 is 16. Right now it calls f once.

Parentheses are for grouping. What do you want to pass to the outer f?

A function that builds a function

You need a function that adds 5, one that adds 100 and one that adds 3. You could write each by hand. Or you could write one function that builds them. Its body is a fun, so its result is a function:

# let make_adder n = fun x -> x + n;;
val make_adder : int -> int -> int = <fun>
# let add5 = make_adder 5;;
val add5 : int -> int = <fun>
  1. Call the builder. make_adder 5 fills in n with 5.
  2. Work out the body. The body is fun x -> x + n. Its value is a function, one that still knows n is 5.
  3. Name the result. add5 is that function. Its type is int -> int, so you can call it.

Now call the result twice.

You type add5 10;; and then add5 1;;. What are the two answers?

add5 is fun x -> x + n with n fixed at 5. What is x in each call?

Each call gets a fresh x and the same n. So the answers are 10 + 5 and 1 + 5. The function remembers the 5 it was built with. It does not remember earlier calls.

The builder can be called again, and each result keeps its own n. After let add100 = make_adder 100, add100 1 is 101 and add5 1 is still 6. A function that remembers names from the place it was built has a name of its own: a closure.

Repair make_adder

This make_adder returns a function, but that function forgets n and gives back x unchanged. Repair it so (make_adder 5) 10 is 15.

Build once, use many times

Now put the last two pieces together: a local name, then a fun that uses it.

# let make_taxer percent =
    let keep = 100 + percent in
    fun price -> price * keep / 100;;
val make_taxer : int -> int -> int = <fun>
# let with_vat = make_taxer 20;;
val with_vat : int -> int = <fun>
# with_vat 50;;
- : int = 60

make_taxer 20 works out keep once, as 120. Then it returns a function that can still see keep, though nothing else can. Every later call of with_vat uses that same 120.

What is with_vat 200?

with_vat is fun price -> price * keep / 100, and keep is 120.

200 * 120 is 24000, and 24000 / 100 is 240. keep was worked out when with_vat was built, not now.

This shape is the one lesson 1.1 needs. There, a function makes a private table once and returns a function that looks things up in it on every call. You now know both halves.

One more thing to notice. The toplevel printed int -> int -> int for make_adder, the same type as add. That is no accident. To OCaml, a function with two parameters is a function that takes the first one and gives back a function waiting for the second. So add 10, with one argument missing, is not an error. It is a function that adds 10.

Build a limiter

Write make_limiter top. It returns a function that takes an int x and gives x back, unless x is more than top. Then it gives top. So (make_limiter 10) 7 is 7 and (make_limiter 10) 25 is 10. The function it returns gives 0 for now.

Giving a function only some of its arguments (partial application), for when a type error shows an arrow you did not expect

Give add only one argument:

# let add_ten = add 10;;
val add_ten : int -> int = <fun>
# add_ten 5;;
- : int = 15

No error. add 10 is a new function that is still waiting for the second number. This is called partial application. It explains the arrow types: int -> int -> int really means int -> (int -> int), "takes an int and gives back a function that takes an int". add 3 4 gives add the 3, gets a function back, and gives that function the 4.

You won't need this often at first. Know it for two reasons. It is why calls have no commas: each space hands over one more argument. And it is why forgetting an argument gives a strange type error instead of a "missing argument" message. If OCaml says something has type int -> int where you expected int, you left an argument out.

The pipe |>, for when nested calls get hard to read

Nested calls read inside out. To find out how many digits 42 has, you might write:

# String.length (string_of_int (double 21));;
- : int = 2
# 21 |> double |> string_of_int |> String.length;;
- : int = 2

The second line does the same thing. x |> f means f x: "send x into f". A chain of them reads left to right, in the order things happen: start with 21, double it, turn it into a string, measure it. When you have three or more steps, the pipe is usually easier to read. With one step, double 21 is fine.

Printing, unit and ;, for when a function prints or does several things in a row

Lesson O.5 teaches unit and ; when you first need them. This is the longer reference. Some functions don't need any input. They still take one argument, the value (), because every OCaml function takes something:

# let say_hi () = print_endline "hi";;
val say_hi : unit -> unit = <fun>
# say_hi ();;
hi
- : unit = ()
# say_hi;;
- : unit -> unit = <fun>

unit -> unit: takes nothing interesting, gives nothing interesting. It is there for what it does, which is print. The last line is a common slip: say_hi without () doesn't call it. It only names the function, so nothing is printed.

To do several things in a row, put ; between them. a; b means "do a, throw its () away, then do b, and the value of the whole thing is b":

# let report name score =
    print_string name;
    print_string ": ";
    print_int score;
    print_newline ();;
val report : string -> int -> unit = <fun>
# report "Ada" 90;;
Ada: 90
- : unit = ()

print_string prints without a new line, print_int prints an int, and print_newline () ends the line. Note there is no ; after the last step: ; goes between steps, not after each one. The last step can also give a real value:

# let shout s =
    print_endline (String.uppercase_ascii s);
    String.length s;;
val shout : string -> int = <fun>
# shout "hey";;
HEY
- : int = 3

Only unit belongs before a ;. The value before a ; is thrown away. If it isn't (), you probably made a mistake, and OCaml warns you.

# let next x = x + 1; x;;
Line 1, characters 13-18:
1 | let next x = x + 1; x;;
                 ^^^^^
Warning 10 [non-unit-statement]: this expression should have type unit.

val next : int -> int = <fun>

This is a warning, not an error: the definition still happened. x + 1 was computed and thrown away, and next 5 is 5, not 6. In a dune project (lesson O.6) this warning stops the build, which is what you want.

It is (double 3) + 1.

What type is the then part? What type is the else part?

With let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1), what is sum_to 4?

Write it out: 4 + sum_to 3, and keep going until you reach the base case.

4 + 3 + 2 + 1 + 0.

The calls go down to sum_to 0, which is 0, and then the additions happen on the way back: 1, 3, 6, 10.
