Learn OCaml · Lesson 3

Lists and pattern matching

A list holds many values in order. match looks at a value and picks what to do from its shape. By the end of this lesson you can read and write a match. That is the skill the rest of the course leans on most: almost every function in your compiler is a match.

Goal

Write a function that takes a list apart with match and gives an answer for every shape the list can have.

You'll use

Values, types and reading a type error from O.1. Functions, if and recursion with a base case from O.2. If one of these is new, read that lesson first and come back.

Warm up

Two questions from lesson O.2, from memory. Pulling an idea back out of your head is what makes it stay.

What is sum_to 3?

let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1)

Write one row per call: sum_to 3 waits for sum_to 2, and so on down to the base case.

3 + 2 + 1 + 0 is 6. Each call waits for a smaller one, and sum_to 0 answers 0 without calling anything. Today you do the same thing on lists.

What is (fun x -> x * 10) 4?

fun x -> x * 10 is a function. The 4 after it is its argument.

40. fun x -> x * 10 is a function with no name, written right where it is needed. You will hand functions like this one to other functions in this lesson.

Many values in one list

So far every value had its own let. That stops working fast. A shop has hundreds of prices, and the programs your compiler reads have any number of lines. You need one value that holds many values in order. That is a list. You write it with square brackets and a semicolon between the items:

# [3; 4; 2];;
- : int list = [3; 4; 2]
# ["milk"; "eggs"; "bread"];;
- : string list = ["milk"; "eggs"; "bread"]

Read int list as "a list of ints". Before you read on, guess what happens with a mix.

What does OCaml say to [3; "four"]?

In O.1, what did OCaml do when an int and a string met in one expression?

A type error. The first item is an int, so OCaml expects every item to be an int, and it marks "four".

# [3; "four"];;
Line 1, characters 4-10:
1 | [3; "four"];;
        ^^^^^^
Error: This expression has type "string" but an expression was expected of type
         "int"

Every item in a list has the same type. The rule pays off later: a function that takes an int list knows every item is an int, so it never has to ask "what if this one is a string?".

Semicolons, not commas

Most languages write [3, 4]. In OCaml that is a list with one item, the pair (3, 4). Its type gives it away: (int * int) list. Pairs come later in this lesson. For a list of two ints, write [3; 4].

A list is a first item and a smaller list

To write a function that works on a list of any length, you need to know how a list is put together. The answer is short. A list is one of two things:

  • the empty list, written []
  • a first item in front of a smaller list, written x :: rest

The operator :: puts one item in front of a list. So [3; 4; 2] is a short way to write 3 :: 4 :: 2 :: [].

# 3 :: [4; 2];;
- : int list = [3; 4; 2]
# 3 :: 4 :: 2 :: [];;
- : int list = [3; 4; 2]

Drawn as boxes, each box holds one item and an arrow to the rest of the list. The last arrow points at [].

[3; 4; 2]

 +---+---+    +---+---+    +---+---+
 | 3 | o-+--->| 4 | o-+--->| 2 | o-+---> []
 +---+---+    +---+---+    +---+---+
 first rest

Cover the first box with your hand. What is left, [4; 2], is a whole list too. That is the "smaller list", and it is why recursion fits lists so well.

After these two lines, what is a?

let a = [4; 2]
let b = 3 :: a

:: makes a new list. Has anything in OCaml so far changed a value that already exists?

a is still [4; 2]. :: made one new box holding 3, with its arrow pointing at a. That new list is b. A list never changes after it is made.

How two lists share boxes, and why the front is the cheap end (for when you care about speed)

Lists are immutable: once made, a box never changes. So adding to the front doesn't touch the old list. It makes one new box that points at it:

b ---> +---+---+
       | 3 | o-+--+
       +---+---+  |
                  v
a ------------> +---+---+    +---+---+
                | 4 | o-+--->| 2 | o-+---> []
                +---+---+    +---+---+

b and a share the boxes for 4 and 2. That is safe only because nobody can change them, and it makes :: fast: one new box, however long the list is. You'll see this idea again in week 1, where many parts of a compiler's graph share the same nodes.

The boxes are also called cells. The first item is the head and the rest is the tail, and :: is said "cons", short for "construct". To reach the third item you follow two arrows. That is why a list is good for going through items one by one from the front, and slow for "give me item number 5000".

The empty list [] on its own has type 'a list, a list of anything, because there is nothing in it yet to say which type.

Pick a case with match

Before you take a list apart, meet the tool on something simpler. A shop needs the price of an item from its name. With if that is a chain of else if. match says the same thing as a table:

let price item =
  match item with
  | "milk" -> 3
  | "eggs" -> 4
  | _ -> 0

Read it in three moves:

  1. Name the value. match item with says which value to look at.
  2. Try each case. Each line that starts with | is a case: something to compare with, an arrow, then the answer. OCaml tries the cases from the top.
  3. Use the first one that fits. Its answer is the value of the whole match.

The last case, _, fits anything. It is how you say "everything else". Like if, a match is an expression, so every case must give the same type.

What is price "tea"?

Go down the cases. Is "tea" equal to "milk"? To "eggs"? What is left?

0. Neither name fits, so OCaml reaches _, which fits anything.

One case per item

This price only knows milk. Add two cases so that price "eggs" is 4 and price "bread" is 5. Anything else must still cost 0.

Where do the new cases go: above the _ line or below it?

You will see this exact shape right after these lessons. The calculator you build picks what to do with match op with | "add" -> ....

Take a list apart

A case can do more than compare. It can describe a shape and give names to the parts. Such a description is called a pattern. A list has two shapes, so a match on a list has two cases:

let describe l =
  match l with
  | [] -> "empty"
  | x :: _ -> "starts with " ^ string_of_int x
# describe [];;
- : string = "empty"
# describe [7; 8];;
- : string = "starts with 7"

Follow describe [7; 8]:

  1. Try []. The list is not empty, so this case does not fit.
  2. Try x :: _. It fits: there is a first item, 7, in front of a smaller list.
  3. Name the parts. x is now 7. Names made by a pattern exist only on the right of that case's arrow.

The _ stands for a part you don't need, here the rest of the list. When you do need it, give it a name: x :: rest.

The list [7; 8] is matched against the pattern x :: rest. What is rest?

Look at the boxes. What does the arrow in the first box point at: an item or a list?

[8]. x is one item, and rest is always a list, even when it holds one item or none. For [8] matched the same way, rest is [].

Read it like a type error from O.1, top to bottom:

  1. Where. The line numbers and the dots mark the whole match.
  2. What. "Not exhaustive" means "does not cover everything".
  3. The missing case. OCaml shows a value you forgot. Add a case for it.

It is a warning, so first still exists. Call first [] and the program stops with Exception: Match_failure. In the projects you build later, this warning stops the build, so treat it as an error now.

According to the warning, which list can first not handle?

Find the line "Here is an example of a case that is not matched" and read the line under it.

[]. OCaml checked both shapes a list can have and found the one with no case. In most languages you find this when a user hits it. Here you find it the moment you write the function.

The first item, or a fallback

Write first_or default l: the first item of l, or default when l is empty. first_or 0 [7; 8; 9] is 7 and first_or 0 [] is 0. The starter ignores the list.

Two shapes, two cases. Leave neither out.

Walk a whole list

describe only looked at the first item. To add up every item you have to reach all of them, and the list can be any length. The two shapes tell you how. If you can sum the smaller list, the sum of the whole list is one addition away:

let rec sum l =
  match l with
  | [] -> 0
  | x :: rest -> x + sum rest

Say it aloud: "the sum of an empty list is 0. The sum of x in front of rest is x plus the sum of rest." It is the recursion from O.2 with new parts. The [] case is the base case. The step calls sum on rest, which is one item shorter, so the calls always reach []. Step through it.

What is mystery [5; 6; 7]?

let rec mystery l =
  match l with
  | [] -> 0
  | _ :: rest -> 1 + mystery rest

The pattern uses _ for the first item, so the items' values never matter. What gets added for each one?

3. Each item adds 1 and the empty list adds 0, so mystery counts the items. The library calls it List.length.

Do the same thing to every item

Prices went up: every one doubles. You have a list and want a new list of the same length. The same two cases do it. This time the answer is a list, so the step puts the new item in front with ::.

let rec double_all l =
  match l with
  | [] -> []
  | x :: rest -> x * 2 :: double_all rest

Here is double_all [3; 4; 2], one call per row. Read "waits for" from the top down, then "returns" from the bottom up.

Only x * 2 is about doubling. Everything else is "walk the list and build a new one". So make the changing part a parameter: a function f to use on each item.

Your own map

Finish my_map f l: a new list with f used on every item. my_map (fun x -> x + 1) [1; 2; 3] is [2; 3; 4]. The starter walks the list but builds nothing.

In double_all, what went in front of the doubled rest? Here f x takes the place of x * 2.

You just wrote a function that already exists. List.map is the name for this pattern, and from now on you can use it:

# List.map (fun x -> x * 2) [3; 4; 2];;
- : int list = [6; 8; 4]
# List.map String.length ["milk"; "eggs"; "bread"];;
- : int list = [4; 4; 5]

Keep only some items

Next need: from a list of numbers, keep the ones above 0 and drop the others. The new list may be shorter. The base case is the same, and the step now has a choice to make.

In the case x :: rest, suppose x is -1, which you do not want. What is the answer for the whole list?

The rest of the list may still hold numbers you want. Only x is dropped.

keep_positive rest: the wanted items of the rest, with nothing put in front. When x is wanted, the answer is x :: keep_positive rest. An if picks between the two.

Keep only the positives

Write keep_positive l: a new list with only the items of l that are greater than 0, in the same order. keep_positive [3; -1; 0; 5] is [3; 5]. This one starts from an empty function. Use double_all as your model.

This pattern has a library name too: List.filter. You hand it a function that answers true for the items to keep.

# List.filter (fun x -> x > 3) [3; 4; 2; 9];;
- : int list = [4; 9]

Neither List.map nor List.filter changes the list you give it. Each one builds a new list.

More list tools: List.iter, List.rev, List.length and @, and why adding at the end is slow 
# List.iter print_endline ["milk"; "eggs"];;
milk
eggs
- : unit = ()
# List.rev [1; 2; 3];;
- : int list = [3; 2; 1]
# List.length [1; 2; 3];;
- : int = 3
# [1; 2] @ [3; 4];;
- : int list = [1; 2; 3; 4]

List.iter calls a function on each element for what it does (here, printing), and gives back (). Lesson O.5 teaches it, and (), when you first need them. List.rev reverses. List.length counts, by walking the whole list, so don't call it again and again on the same long list. @ joins two lists.

Adding to the end is slow. a @ b can't change the last cell of a to point at b, because cells never change. So it copies every cell of a. On a list of 10,000 elements, adding one element at the end copies 10,000 cells. Do that again and again and the work grows with the square of the length. The usual fix: build the list backwards with :: (one cell each), then call List.rev once at the end.

The types. List.map has type ('a -> 'b) -> 'a list -> 'b list: given a function from 'a to 'b and a list of 'a, you get a list of 'b. List.filter has type ('a -> bool) -> 'a list -> 'a list. List.fold_left, which comes two sections on, has type ('acc -> 'a -> 'acc) -> 'acc -> 'a list -> 'acc.

Carry a running total

The last pattern turns a whole list into one value, such as a total. sum did that, but look at its trace again: every addition waited until the end. People add a column of numbers another way. They keep a running total and update it at each number. Here is that idea as a function. The running total is an extra parameter, usually called acc, short for accumulator.

let rec sum_from acc l =
  match l with
  | [] -> acc
  | x :: rest -> sum_from (acc + x) rest

You start it with a total of 0: sum_from 0 [3; 4; 2].

In row 3, acc is 7 and x is 2. The next call gets acc + x.

9. Row 3 calls sum_from 9 []. Nothing is waiting this time. Each call adds first and hands the new total on, so when the list is empty the answer is already in acc.

Repair the running total

sum_from acc l should give acc plus the sum of l. sum_from 0 [1; 2; 3] is 6 and sum_from 10 [] is 10. The step in the starter is already right. One case is wrong.

Tail recursion: why the running-total version can handle a list of a hundred million items (depth for experts)

Look again at sum: x + sum rest. The addition can't happen until sum rest comes back. So each call has to wait, and remember its x, while the next call runs. The computer keeps those waiting calls in a region of memory called the call stack, one frame per waiting call. For a list of n elements, n frames pile up before the first addition happens:

sum [1; 2; 3]

  | sum []            returns 0          |   <- top: running now
  | 3 + sum []        waiting, holds 3   |
  | 2 + sum [3]       waiting, holds 2   |
  | 1 + sum [2; 3]    waiting, holds 1   |
  +--------------------------------------+   one frame per element

The stack has a size limit. OCaml 5 gives it a lot of room (up to about a gigabyte), so you need very deep recursion to reach it, but you can. Here is sum_to from lesson O.2 with a hundred million calls:

# let rec sum_to n = if n = 0 then 0 else n + sum_to (n - 1);;
val sum_to : int -> int = <fun>
# sum_to 100_000_000;;
Stack overflow during evaluation (looping recursion?).

(The underscores in 100_000_000 are only for reading. OCaml ignores them.) A list sum with a hundred million elements would fail in the same way. Older OCaml versions, and many other languages, hit the limit much sooner. Python, for example, stops at about a thousand nested calls.

The fix is to make the recursive call the very last thing the function does, with nothing left to do after it comes back. Then the current frame has nothing left to remember, and OCaml reuses it for the next call instead of piling up a new one. Such a call is a tail call, and a function whose recursive calls are all tail calls is tail recursive. sum_from is tail recursive: the addition happens before the call, not after it, and the running total travels down in acc. No call waits for anything, so the stack holds one frame the whole time. The same change makes the hundred-million version finish:

# let rec sum_to_acc acc n = if n = 0 then acc else sum_to_acc (acc + n) (n - 1);;
val sum_to_acc : int -> int -> int = <fun>
# sum_to_acc 0 100_000_000;;
- : int = 5000000050000000

One test of the exercise above uses a list of a million elements. List.fold_left is tail recursive for the same reason, which is one more reason to use it. Don't rewrite every function this way. The plain version is easier to read and fine for the lists and trees in this course. Reach for an accumulator when the input can be very long.

fold_left is the name for that

sum_from has one part that is about adding: acc + x. Make that part a parameter, as you did for map, and you have List.fold_left. You give it three things:

  1. How to update. A function that takes acc and one item x and gives the new acc.
  2. The start. What acc is before any item has been seen.
  3. The list. The items to walk through, from the left.
# List.fold_left (fun acc x -> acc + x) 0 [3; 4; 2];;
- : int = 9

It walks the list exactly as the table for sum_from did, and the last acc is the answer. The accumulator can mean anything you want to build up. Here it is "the biggest so far":

# List.fold_left (fun acc x -> if x > acc then x else acc) 0 [3; 9; 4];;
- : int = 9

When you write a fold, ask two questions. What does acc mean (a total, a count, the best so far)? And what should it be before any item has been seen?

Pairs: two values that travel together

A price list needs a name and a price for each item. A list can't mix strings and ints, so you need a way to glue two values into one. That is a tuple: a fixed number of values, which may have different types, written with commas inside parentheses. A tuple of two is called a pair.

# let pair = ("eggs", 4);;
val pair : string * int = ("eggs", 4)
# let (name, cost) = pair;;
val name : string = "eggs"
val cost : int = 4

The type string * int reads "a string and an int". The * here means "and", not multiplication. The second line is a pattern again: "this has the shape of two things, call them name and cost". A pattern like that can also stand where a parameter goes: fun (name, cost) -> cost takes one pair and gives its second part.

Now a price list is a list of pairs, and one pattern can take apart the list and its first pair at once:

let prices = [("milk", 3); ("eggs", 4)]

let rec total items =
  match items with
  | [] -> 0
  | (_, cost) :: rest -> cost + total rest

What is total prices?

In the first call the pattern fits with cost as 3 and rest as [("eggs", 4)]. The name is skipped with _.

7. It is sum again. The only change is the pattern (_, cost), which reaches inside each pair for the price.

More on tuples: three or more values, fst and snd, and how a tuple differs from a list 
# ("Ada", 36, true);;
- : string * int * bool = ("Ada", 36, true)
# fst pair;;
- : string = "eggs"

A tuple can hold any fixed number of values. fst and snd give the first and second part of a pair, but more often you name the parts with a pattern.

A list and a tuple differ in two ways: a list can have any length but one type, and a tuple has a fixed length but each position can have its own type. A shopping list is a list. One line on it, a quantity and an item, is a tuple.

When there might be no answer

The library can look a name up in a list of pairs: List.assoc_opt "eggs" prices finds the 4. Predict before you read on.

prices holds milk and eggs. What should looking up "tea" give back?

If the answer were 0, could you tell "tea is free" from "there is no tea"?

A number would lie. 0 could be a real price, and code could add -1 to a bill by mistake. OCaml gives back a value that cannot be confused with a price: None.

# List.assoc_opt "eggs" prices;;
- : int option = Some 4
# List.assoc_opt "tea" prices;;
- : int option = None

The type is int option, and a value of that type has two shapes: Some n, which holds an int, or None, which holds nothing. It is not an int. 1 + List.assoc_opt "eggs" prices is a type error. To get at the int you match on both shapes, and the missing-case warning makes sure you handled None:

let show_price item =
  match List.assoc_opt item prices with
  | Some p -> item ^ " costs " ^ string_of_int p
  | None -> "no " ^ item ^ " today"

show_price "eggs" is "eggs costs 4", and show_price "tea" is "no tea today".

Your own functions can give back an option too. The next exercise needs one more pattern: [x] fits a list with exactly one item.

The last item, as an option

Repair last l: Some of the last item, or None for the empty list. last [1; 2; 3] is Some 3. The starter gives back the first item.

Library functions that fail when there is no answer, and why OCaml has no null

Why not return a special "nothing" value, the way many languages use null? Because null pretends to be a normal value. Code that forgets to check for it compiles fine and crashes later, often far from the cause. In OCaml, "maybe nothing" has its own type. An int is always a real int, and when something might be missing, the type says option and the exhaustiveness check makes you deal with None.

List.find_opt gives the first item that passes a test, as an option:

# List.find_opt (fun x -> x > 10) [3; 12; 40];;
- : int option = Some 12
# List.find_opt (fun x -> x > 100) [3; 12; 40];;
- : int option = None

Some library functions skip the option and raise an error instead. List.find raises Not_found when nothing matches, and List.hd (the first element) fails on an empty list:

# List.find (fun x -> x > 100) [3; 12; 40];;
Exception: Not_found.
# List.hd [];;
Exception: Failure "hd".

Prefer the _opt versions while you are learning, so the type reminds you. Exceptions, and when they are the better choice, are in lesson O.4.

Write a lookup yourself

One last function, and it uses everything on this page: a list, a pair pattern, recursion and an option. It is also a real piece of an interpreter. The calculator you build after these lessons keeps each line's answer under its name, and finding a name again is this job.

Look up a name

Write lookup name items, where items is a list of pairs like prices. Give Some of the number paired with name, or None when no pair has that name. If a name is there twice, the first one wins. lookup "eggs" [("milk", 3); ("eggs", 4)] is Some 4.

Start from total. Its pattern (_, cost) :: rest skipped the name. Here you need it.
