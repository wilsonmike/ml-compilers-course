Learn OCaml · Lesson 1

First steps in OCaml

You'll install OCaml, type your first expressions, learn the six basic kinds of value, and, most important of all, learn to read the messages OCaml gives you when something doesn't fit. Nothing here assumes you have programmed before.

How to use this track

These six lessons are numbered O.1 to O.6, and they lead into week 0. Week 0 ends with lesson 0.6, the OCaml crash course, which moves fast. This track goes slowly and explains why OCaml does things the way it does. Type every example yourself. Reading code and typing code teach different things.

What OCaml is, and why the course offers it

OCaml is a programming language. You write instructions in a text file, and OCaml turns them into something the computer can run. It has been around since 1996 and is used for compilers, financial software and tools that check other programs for bugs.

The thing that makes OCaml different from a language like Python is that it checks types before your program runs. A type is the kind of a value: a whole number, a piece of text, true or false. OCaml reads your whole program first and checks that every piece fits. If you try to add a number to a word, it refuses to run anything and tells you which line is wrong.

That can feel strict on day one. It is also the main reason the course offers OCaml. A compiler is a big program that handles many kinds of things at once: numbers, names, operations, whole trees of them. When you change one part, OCaml points at every other part that no longer fits. In Python you find those places by running the program and watching it crash, sometimes weeks later.

A trade, not a free lunch

You will spend more time arguing with the type checker before your code runs, and less time hunting bugs after. Most people find the trade worth it once their program is longer than a page.

Opening a terminal

A terminal is a window where you type commands instead of clicking. On Windows, open PowerShell from the Start menu. On macOS, open Terminal from Applications, Utilities. On Linux, it is usually called Terminal too.

The terminal is always "standing in" one folder, called the current folder (or working directory). Three commands get you around, and they have the same names in PowerShell, macOS and Linux:

pwd
ls
cd Documents
cd ..

pwd prints where you are ("print working directory"). ls lists the files and folders here. cd Documents moves into the folder called Documents, and cd .. moves back up one level. Type a command, press Enter, read what it prints. That is the whole loop.

Installing OCaml

OCaml comes with a package manager called opam, a program that downloads and installs OCaml and its libraries. You install opam once, and opam installs everything else. Pick the line for your computer:

  • Windows: follow the Install section of lesson 0.6. It has a native Windows route and a WSL route. Read only that section for now, and come back here when ocaml -version prints a number.
  • macOS: install Homebrew first, then run the lines below.
  • Linux or WSL: use your package manager for opam, then run the same lines.
brew install opam
opam init -y
eval $(opam env)
opam install -y dune utop ocaml-lsp-server

On Linux or WSL, replace the first line with sudo apt update && sudo apt install -y opam clang, the same line lesson 0.6 uses. clang is a C compiler that later weeks need. opam init builds the OCaml compiler, so it can take 10 minutes or more. eval $(opam env) tells this terminal where opam put things. If ocaml is "not found" in a new terminal later, run that line again.

The last line installs three tools. dune builds bigger projects (lesson O.6). utop is the program you'll use most in this track. ocaml-lsp-server lets an editor such as VS Code show you the type of anything you point at.

Check it worked:

ocaml -version

Talking to utop

Type utop in the terminal and press Enter. You get a prompt, a sign that it is waiting for you. utop is a REPL: it Reads what you type, Evaluates it, Prints the answer, and Loops back for more. Try this:

# 2 + 3;;
- : int = 5

The first line is what you type. You don't type the #: it is the prompt. The second line is OCaml's reply. Two things to notice.

First, the ;; at the end. It means "I'm done, run this now". Without it, utop thinks you are still typing and waits for more. If utop seems stuck, you probably forgot ;;. You only need ;; in utop, not in files.

Second, the reply has three parts. Read - : int = 5 as "a value with no name, of type int, equal to 5":

PartHereMeaning
name-The value has no name. A dash means "anonymous".
typeintWhat kind of value it is. Here, a whole number.
value5The value itself.

Every answer OCaml gives you comes with its type. That is how you learn the language: try something, read the type. The examples on these pages were run in the plain ocaml toplevel, which you can start with ocaml if utop isn't installed. Its prompt is #, utop's reads utop #, and the answers are the same. To leave either one, type #quit;; or press Ctrl+D.

# 10 - 3 * 2;;
- : int = 4
# 3 > 2;;
- : bool = true
# "hello";;
- : string = "hello"

Each line you type is an expression: a piece of code that has a value. 10 - 3 * 2 has the value 4 (multiplication goes first, as in math). 3 > 2 has the value true. Even "hello" on its own is an expression whose value is itself.

In OCaml almost everything is an expression with a value, including things that are statements in other languages, such as if. That idea comes back in every lesson of this track.

Naming values with let

let gives a value a name, so you can use it later:

# let price = 10;;
val price : int = 10
# price * 3;;
- : int = 30

This time the reply starts with val price instead of -. The value now has a name. Read it as "a value called price, of type int, equal to 10".

Here is the big difference from most languages: a name, once made, never changes. There is no way to say "price is now 11". OCaml has no assignment of that kind. If you write let price = 99 later, you don't change the old price. You make a new name that happens to be spelled the same and hides the old one from then on. This is called shadowing.

Step through it. Watch total in the last step.

# let price = 10;;
val price : int = 10
# let total = price * 3;;
val total : int = 30
# let price = 99;;
val price : int = 99
# total;;
- : int = 30

total is still 30. It was worked out from the first price, and that value never changed. Nothing you do later can reach back and alter a value that was already made.

Why would a language forbid changing things? Because it makes code much easier to reason about. When you see total on line 50, you know it is exactly what line 2 said it was. You never have to scan the lines in between for something that changed it. Your compiler will build trees out of thousands of values, and knowing that none of them change behind your back is worth a lot. (OCaml does have values you can change, called refs and arrays. They come in lesson O.5, and you'll use them rarely.)

= compares, it doesn't assign

Outside a let, = asks a question: are these equal? price = 100 doesn't set anything. It gives - : bool = false. If you see a bool where you expected a change, this is why.

The basic types

Six types cover almost everything in this track. Try each one in utop and read the reply.

TypeWhat it holdsExamples
intwhole numbers0, 42, -7
floatnumbers with a fractional part3.5, 2.0, 0.1
stringtext, in double quotes"hello", ""
booltrue or falsetrue, false
charone character, in single quotes'a', '7'
unit"nothing interesting", one value only()
# 'a';;
- : char = 'a'
# "A";;
- : string = "A"
# ();;
- : unit = ()

'a' and "A" look alike but are different types: a char is exactly one character, a string is any amount of text. unit looks odd at first. It is the type of expressions that do something (like printing) but have no useful answer. Its only value is written (), and you'll meet it again when you print things below.

Two kinds of number

Here is the first surprise. Integers and floats have separate arithmetic. + - * / work on ints. Floats use the same signs with a dot after them: +. -. *. /..

# 7 / 2;;
- : int = 3
# 7 mod 2;;
- : int = 1
# 7.0 /. 2.0;;
- : float = 3.5
# 2.0 *. 3.5;;
- : float = 7.

7 / 2 is 3, not 3.5. Dividing two ints gives an int, and the fractional part is thrown away (cut toward zero, so -7 / 2 is -3). mod gives the remainder. The language your compiler handles, .uir, rounds negative quotients down instead, to -4, and H.4 shows how to get that answer. Notice also that OCaml prints the float seven as 7.: a float always shows its dot, so you can tell it apart from the int 7.

Why separate signs? A computer stores ints and floats in completely different ways, and adding them takes different machine instructions. Many languages quietly convert one into the other for you, and sometimes pick the conversion you didn't want. OCaml makes you say which one you mean. That matters for this course: the language your compiler handles has 32-bit ints and, from week 2, 32-bit floats, and the two must never be mixed by accident, and OCaml's own rules train you to notice.

To go from one to the other, you convert on purpose:

# float_of_int 7 /. 2.0;;
- : float = 3.5
# int_of_float 3.9;;
- : int = 3
# let a = 7;;
val a : int = 7
# let b = 2;;
val b : int = 2
# float_of_int a /. float_of_int b;;
- : float = 3.5
# float_of_int (a / b);;
- : float = 3.

The last two lines are the classic mistake. float_of_int (a / b) divides two ints first (giving 3) and only then converts, so the half is already gone. Convert first, then divide.

int_of_float drops the fraction too: 3.9 becomes 3, it doesn't round.

Average of two ints, as a float

Write average a b: the average of two ints, as a float. average 3 4 is 3.5. The starter already defines it as a function. Functions come in lesson O.2, so for now just fill in the line after the =. The starter compiles, but it gives 3. for average 3 4.

Which happens first in the starter, the division or the conversion?

Strings and printing

^ joins two strings into one. String.length counts the characters. The dot in String.length means "the length function that lives in the String module", a module being a named group of related functions (more in lesson O.6).

# "cat" ^ "s";;
- : string = "cats"
# "Ada" ^ " " ^ "Lovelace";;
- : string = "Ada Lovelace"
# String.length "hello";;
- : int = 5
# string_of_int 42;;
- : string = "42"
# "Total: " ^ string_of_int 42;;
- : string = "Total: 42"
# int_of_string "42";;
- : int = 42

Like ints and floats, strings and numbers never mix by themselves. To put a number into a string, convert it with string_of_int (or string_of_float). OCaml's conversion functions are all named result_of_input, so string_of_int reads "a string, made from an int".

To show something on the screen, print it. print_endline prints a string and then moves to a new line:

# print_endline "hello";;
hello
- : unit = ()

Two lines came back. hello is what got printed. - : unit = () is the value of the expression. Printing does something useful, but its answer is the boring value () of type unit. That is what unit is for.

To print numbers and text together, Printf.printf takes a format string with holes in it, then one value per hole. %d is a hole for an int, %s for a string, %f for a float, and \n means "new line":

# Printf.printf "%d %s\n" 42 "apples";;
42 apples
- : unit = ()
# Printf.printf "%s scored %d\n" "Ada" 90;;
Ada scored 90
- : unit = ()
# Printf.printf "%.2f\n" 3.14159;;
3.14
- : unit = ()

%.2f prints a float with two digits after the point. OCaml checks the holes against the values. Put a float where %d expects an int and you get a type error, before anything prints.

A greeting with ^

Write greet name so that greet "Ada" is "Hello, Ada!". The starter is close but misses two characters.

Spaces and punctuation have to be inside the quotes.

Reading type errors

You will see type errors every day. They are not OCaml telling you off. They are OCaml telling you exactly where two pieces don't fit, before the program has done anything wrong. The skill is reading them calmly. They all have the same shape, so once you can read one you can read them all.

Error 1: an int and a float

# 1 + 2.0;;
Line 1, characters 4-7:
1 | 1 + 2.0;;
        ^^^
Error: This expression has type "float" but an expression was expected of type
         "int"

Read it from the top. Where: line 1, and the ^^^ marks sit under 2.0. That is the piece OCaml is complaining about. What you gave: "This expression has type float". The marked piece, 2.0, is a float. What the place needs: "an expression was expected of type int". It sits next to +, and + only takes ints. The fix is either 1 + 2 or 1.0 +. 2.0, depending on what you meant.

utop may mark the spot differently, for example by underlining the piece in the line you typed instead of printing ^^^ marks. The Error: text is the same in both, and so are warnings, so that's the part to read.

Error 2: joining a string and a number

# "a" ^ 1;;
Line 1, characters 6-7:
1 | "a" ^ 1;;
          ^
Error: This expression has type "int" but an expression was expected of type
         "string"

The mark is under 1. You gave an int. ^ joins strings, so the place needs a string. Fix: "a" ^ string_of_int 1.

Error 3: printing a number with a string printer

# print_endline 5;;
Line 1, characters 14-15:
1 | print_endline 5;;
                  ^
Error: This expression has type "int" but an expression was expected of type
         "string"

Same pattern. print_endline prints strings only, so the spot after it expects a string, and you gave the int 5. Fix: print_endline (string_of_int 5), or use Printf.printf "%d\n" 5.

Error 4: an if without an else

This one defines a function f and uses if. You'll meet both properly in the next lesson. if x > 0 then 1 has no else.

# let f x = if x > 0 then 1;;
Line 1, characters 24-25:
1 | let f x = if x > 0 then 1;;
                            ^
Error: This expression has type "int" but an expression was expected of type
         "unit"
       because it is in the result of a conditional with no else branch

The mark is under the 1, which is an int. But why would anything expect unit? The last line explains: an if is an expression, so it must have a value whether or not the condition holds. With no else, the missing branch can only produce (), so OCaml requires the then branch to produce unit too. Fix: add an else, as in if x > 0 then 1 else 0.

Error 5: the right sign, the wrong number

# 1 +. 2.0;;
Line 1, characters 0-1:
1 | 1 +. 2.0;;
    ^
Error: This expression has type "int" but an expression was expected of type
         "float"
  Hint: Did you mean "1."?

This time you used the float sign +. but wrote the int 1. OCaml even adds a hint: you probably meant 1., the float one. Read hints. They are often right.

The recipe for any type error
  1. Find the marks. The ^^^ line points at one expression. Ignore the rest of the line for now.
  2. "This expression has type X" is what you gave: the type of the marked piece.
  3. "but an expression was expected of type Y" is what that place needs: the type the surrounding code (an operator, a function, an if) requires there.
  4. Ask which side is wrong. Sometimes the marked piece is wrong (convert it, or fix a typo). Sometimes the surrounding code is wrong (you used + where you meant +.).
The marks can point at the innocent piece

OCaml reads left to right. In 1 + 2.0 it saw + first, decided ints were wanted, and then blamed 2.0. If you meant floats, the real mistake is the +. The marks show where OCaml noticed the clash, which is not always where you made it.

Write label item qty so that label "eggs" 12 is "eggs: 12". item is a string and qty is an int.

Running a file

utop is for trying things. Real programs live in files. Make a file called hello.ml (any plain text editor works, and VS Code is a good choice) with these two lines:

let () = print_endline "Hello, world!"
let () = Printf.printf "%d + %d = %d\n" 2 3 (2 + 3)

Then, in the terminal, cd into the folder that holds it and run it with ocaml:

ocaml hello.ml

It prints:

Hello, world!
2 + 3 = 5

Two differences from utop. There is no ;;: in a file, each let starts a new definition, so OCaml can tell where one ends. And each line starts with let () =. Read it as "run this, and its answer must be ()". Printing returns (), so it fits. If you write let () = 5, OCaml stops you with a type error, because 5 isn't unit. It is a small check that you didn't mean to compute something and throw it away.

Notice the parentheses in (2 + 3). Without them, OCaml would hand 2 to printf as the third value and then try to add 3 to whatever printf returned, which is a type error. Calling a function grabs its arguments before + gets a turn. The next lesson explains why.

  • Name values with let, and explain why shadowing a name doesn't change values made earlier.
  • Use the six basic types, and keep int arithmetic (+) and float arithmetic (+.) apart.
  • Join strings with ^, convert numbers with string_of_int, and print with print_endline and Printf.printf.
  • Read a type error: the marks, what you gave, what the place needs.
  • Run a program from a file with ocaml hello.ml.

Check yourself

What value does OCaml give for 7 / 2?

Both 7 and 2 are ints. What type does dividing two ints give?

An int can't hold a half. What happens to it?

7 / 2 is int division, so the answer is the int 3 and the half is thrown away. For 3.5 you need floats: 7.0 /. 2.0.

utop replies val total : int = 30. Which part is the type?

A reply has three parts: name, type and value. Which one comes after the colon?

Name total, then : and the type int, then = and the value 30.

You type let price = 10;;, then let total = price * 3;;, then let price = 99;;. What is total now?

Does the third line change the old price, or make a new name?

When was total worked out, and which price existed then?

The second let price makes a new name that shadows the old one. total was computed from the first price, which never changed, so it stays 30.

OCaml says Error: This expression has type "int" but an expression was expected of type "string", with the marks under a number. What does the place need?

"has type" is what you gave. "expected of type" is the other one.

"Expected of type string" is what the surrounding code needs. You gave an int, so convert it with string_of_int, or change the code around it.

What value does float_of_int 7 /. 2.0 give? Type the number.

Which happens first here, the conversion or the division?

float_of_int 7 is 7., and /. is float division.

7 becomes the float 7. before dividing, so /. keeps the half: 3.5. Compare float_of_int (7 / 2), which is 3..

Why does if x > 0 then 1 (with no else) give a type error?

Everything is an expression with a value. What is the value when x is negative?

Look at the last line of error 4 again.

An if without else is allowed, but only when the then branch has type unit (for example, a print). Returning an int needs an else that also returns an int.
