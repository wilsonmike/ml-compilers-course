First steps in OCaml

In Run your first program, the page ran your three-line programs for you. Six short lessons from now, you write the program that runs them. This first lesson gets OCaml working on your computer and teaches you to read what it says back. You don't need to have programmed before.

Goal

Type a value into OCaml, read the type it prints back, and fix a type error by reading the message.

Where this is going

The six Learn OCaml lessons are numbered O.1 to O.6. After them you go back to Build the thing that runs it and write it in OCaml. Type every sample on these pages yourself. Typing code teaches you things that reading it does not.

Warm up

Two questions from the page before this one, from memory. Pulling an idea back out of your head is what makes it stay.

What is %out?

%a   = add 1 5
%out = mul %a 3

Work out the first line, then use its answer in the second.

%a is 6, and 6 × 3 is 18.

In %a = add 1 5, what is %a?

Later lines write %a when they want to use this line's answer.

Each line makes one value and gives it a name. OCaml does the same job with the word let, and you'll use it on this page.

Install OCaml

OCaml is a programming language, and it is the one you'll write your compiler in. It has one habit that makes it good for that job. It checks your whole program before it runs any of it, and it tells you which piece doesn't fit.

You install it from a terminal, a window where you type commands. On Windows, open PowerShell from the Start menu. On macOS or Linux, open Terminal. Type one line, press Enter and read the reply.

Windows. Run the first line. Then close the terminal, open a new one and run the other two. When opam init asks a question, take the default answer, and say yes if it offers to set up your shell.

winget install Git.Git OCaml.opam
opam init
opam install dune utop ocaml-lsp-server

macOS. Install Homebrew first, then run these four lines.

brew install opam
opam init -y
eval $(opam env)
opam install -y dune utop ocaml-lsp-server

Linux, or WSL on Windows. Use the macOS lines, but replace the first one with sudo apt update && sudo apt install -y opam clang git.

opam is the program that downloads and installs OCaml and its tools. opam init builds OCaml itself, which takes 10 to 30 minutes. Read on while it works. When it is done, check it:

ocaml -version

You should see a line like this one. Your number may be newer.

The OCaml toplevel, version 5.2.1

You open a new terminal the next day, type ocaml -version, and it says the command is not found. What is the most likely cause?

Yesterday's terminal could find it. What does the new window not know yet?

OCaml is still there. On macOS, Linux and WSL, run eval $(opam env) in the new terminal. On Windows, the fix is in the Install section of lesson 0.6, linked below.

Or keep going without it for now: every sample on these pages shows OCaml's reply, and every exercise lets you compare your code with the answer. You will need a working OCaml by lesson 0.6.

Moving around in a terminal with pwd, ls and cd, for when a command says a file is not found

A terminal is always "standing in" one folder, called the current folder or working directory. Three commands get you around. They have the same names in PowerShell, macOS and Linux.

pwd
ls
cd Documents
cd ..

pwd prints where you are ("print working directory"). ls lists the files and folders here. cd Documents moves into the folder called Documents, and cd .. moves back up one level.

A value and its type

In your second terminal, type utop and press Enter. (If utop is not found, type ocaml. It does the same job.) You get a prompt, a sign that OCaml is waiting for you. This program is called the toplevel. You type one piece of OCaml, it works it out and it prints a reply.

You type 2 + 3;; and press Enter. Which reply do you expect? A guess is fine.

OCaml tells you more than the answer.

OCaml prints the answer and also what kind of thing the answer is. Try it now.

# 2 + 3;;
- : int = 5

The first line is what you type. The # is the prompt, so you don't type it. The ;; means "I'm done, work this out now". If the toplevel seems stuck, you probably forgot ;;.

A value is one piece of data, such as a number or some text. A type is the kind of value it is. Every reply gives you both. Read - : int = 5 as "a value with no name, of type int, equal to 5".

PartHereMeaning
name-The value has no name yet.
typeintWhat kind of value it is. Here, a whole number.
value5The value itself.

Four types cover this whole lesson. Type one value of each and read the replies.

TypeWhat it holdsExamples
intwhole numbers0, 42, -7
floatnumbers with a decimal point3.5, 2.0, 0.1
stringtext, in double quotes"hello", ""
booltrue or falsetrue, false
# 3.5;;
- : float = 3.5
# "hello";;
- : string = "hello"
# 3 > 2;;
- : bool = true

What does OCaml reply to "7";;?

Look at what is around the 7.

Double quotes make text. "7" is a string that happens to hold a digit, and it is a different value from the int 7.

To leave the toplevel, type #quit;; (this time you do type the #) or press Ctrl+D. In utop the prompt reads utop #, and the replies are the same.

Two more basic types, char and unit, for when a later lesson mentions them 
# 'a';;
- : char = 'a'
# "A";;
- : string = "A"
# ();;
- : unit = ()

A char is exactly one character, in single quotes. A string is any amount of text, so 'a' and "A" have different types. unit is the type of code that does something, such as printing, but has no useful answer. Its only value is written ().

Each line you type is an expression: a piece of code that has a value. Even "hello" by itself is an expression whose value is itself. In OCaml almost everything is an expression.

Name a value with let

In .uir, the line %a = add 2 3 made a value and named it, so later lines could use it. OCaml does that with let. Type the first line below, then guess before you type the second.

# let price = 10;;
# price * 3;;

What value does price * 3 give? (* means multiply.)

Put 10 where the name price is.

price stands for 10, so the answer is 30.

# let price = 10;;
val price : int = 10
# price * 3;;
- : int = 30

The first reply starts with val price where a dash used to be. The value has a name now. Read it as "a value called price, of type int, equal to 10". For a line such as let total = price * 3, OCaml takes three steps:

  1. Work out the right side. price * 3 is 30.
  2. Find its type. 30 is an int.
  3. Attach the name. From now on, total means 30.

The exercise editor is not the toplevel. In it you write only the OCaml, with no # and no ;;.

Three names

Make apples 12 and pears 7. Then make fruit the two added together. Use the names on the third line, not the number 19.

A name never changes

What if you use let again with a name you already have? Guess what the last line replies.

# let size = 4;;
# let area = size * size;;
# let size = 10;;
# area;;

What value does area have at the end?

When was area worked out, and what was size then?

area was worked out on line 2, when size was 4. It is 16 and stays 16. Line 3 does not reach back and change it.

In OCaml, a name, once made, never changes. A second let size does not change the old size. It makes a new name with the same spelling that hides the old one from then on. This is called shadowing. Step through it with a price.

Why would a language forbid changing things? Because it makes code easier to trust. When you see total fifty lines later, it is exactly what the line that made it said. Your compiler will build graphs out of thousands of values, and none of them will change behind your back.

= compares, it doesn't change

Outside a let, = asks a question: are these equal? price = 100 does not set anything. It replies - : bool = false.

The toplevel's replies for the price example, and where changeable values do exist 
# let price = 10;;
val price : int = 10
# let total = price * 3;;
val total : int = 30
# let price = 99;;
val price : int = 99
# total;;
- : int = 30

OCaml does have values you can change, called refs and arrays. They come in lesson O.5, and you'll use them rarely.

Arithmetic with whole numbers

You have seen + and *. Minus is - and divide is /. Divide has a surprise in it.

What value does OCaml give for 9 / 2? Guess, then try it in the toplevel.

Both numbers are ints, so the answer is an int too. An int can't hold a half.

9 / 2 is 4. Dividing two ints gives an int, and the leftover part is thrown away.

# 9 / 2;;
- : int = 4
# 9 mod 2;;
- : int = 1
# 10 - 3 * 2;;
- : int = 4
# (10 - 3) * 2;;
- : int = 14

mod gives the leftover, called the remainder: 2 goes into 9 four times, with 1 left. Multiplying and dividing go before adding and subtracting, as in math class, so 10 - 3 * 2 is 10 - 6. Parentheses change the order.

Minutes into hours and minutes

A film is 200 minutes long. Make hours the number of whole hours in total, and minutes the minutes left over. Use total, / and mod, and leave the first line alone.

Dividing negative numbers, for when your compiler has to divide

Int division cuts toward zero, so -7 / 2 is -3. The language your compiler handles, .uir, rounds negative answers down instead, to -4. H.4 shows how to get that answer.

Two kinds of number

An int is a whole number. A float has a decimal point. Now add two floats.

What does OCaml reply to 1.5 + 2.0;;?

Every sum so far had ints on both sides of the +.

In OCaml, + adds ints and nothing else. Floats have their own sign, +., with a dot after it.

Ints use + - * /. Floats use the same signs with a dot: +. -. *. /.

# 1.5 +. 2.0;;
- : float = 3.5
# 7.0 /. 2.0;;
- : float = 3.5
# 2.0 *. 3.5;;
- : float = 7.

OCaml prints the float seven as 7. so you can tell it from the int 7. Why two sets of signs? A computer stores ints and floats in different ways. Many languages quietly turn one into the other for you, and sometimes they pick the way you did not want. OCaml makes you say which you mean.

To turn an int into a float on purpose, write float_of_int, a space, then the int. Do it before you divide:

# float_of_int 7 /. 2.0;;
- : float = 3.5
# float_of_int (7 / 2);;
- : float = 3.

The second line divides two ints first, which gives 3. The half is gone before the conversion happens.

Average of two ints, as a float

The first line is written for you. It makes average work for any two ints, called a and b. Lesson O.2 teaches that line, so change only the second one. average 3 4 should be 3.5, but the starter gives 3.

Which happens first in the starter, the division or the conversion?

Going the other way with int_of_float, and why the course cares about keeping ints and floats apart 
# int_of_float 3.9;;
- : int = 3

int_of_float drops the part after the point. It does not round. Adding ints and adding floats take different machine instructions. The language your compiler handles has 32-bit ints and, from week 2, 32-bit floats, and the two must never be mixed by accident. OCaml's rules train you to notice.

Strings

A string is text in double quotes. The sign ^ joins two strings into one.

What value does "2" ^ "3" give?

The quotes make these text, not numbers. Joining adds nothing in between.

^ glues the second string onto the end of the first. No math happens and no space is added.

# "cat" ^ "s";;
- : string = "cats"
# "Ada" ^ " " ^ "Lovelace";;
- : string = "Ada Lovelace"
# String.length "hello";;
- : int = 5
# string_of_int 42;;
- : string = "42"
# "Total: " ^ string_of_int 42;;
- : string = "Total: 42"

A space is a character too. If you want one, it has to be inside quotes, as in the second line. String.length counts the characters in a string.

Strings and numbers never mix by themselves. To put a number into a string, turn it into one with string_of_int. OCaml names its converters result_of_input, so string_of_int reads "a string, made from an int".

A greeting with ^

As before, change only the second line. greet "Ada" should be "Hello, Ada!". The starter is close but misses two characters.

Spaces and punctuation have to be inside the quotes.

Read a type error

Sooner or later you will forget string_of_int.

What do you think OCaml does with "score: " ^ 90;;?

^ joins strings. What type is 90?

90 is an int and ^ needs a string there, so OCaml stops before running anything. This is a type error.

# "score: " ^ 90;;
Line 1, characters 12-14:
1 | "score: " ^ 90;;
                ^^
Error: This expression has type "int" but an expression was expected of type
         "string"

You will see messages like this every day. They are not OCaml telling you off. They say where two pieces don't fit, and they all have the same shape. Read this one piece by piece:

  1. Find the marks. Line 1, characters 12-14 and the ^^ marks point at one piece of your code: 90.
  2. Read what you gave. This expression has type "int". An expression is a piece of code that has a value. "This expression" is the marked piece, and it is an int.
  3. Read what the place needs. but an expression was expected of type "string". The code around the marked piece, here the ^, needs a string in that spot.
  4. Decide which side is wrong. Here it is the marked piece. Turn it into a string: "score: " ^ string_of_int 90.

Sometimes the wrong side is the code around the marks. Try this one.

# 1 + 2.0;;
Line 1, characters 4-7:
1 | 1 + 2.0;;
        ^^^
Error: This expression has type "float" but an expression was expected of type
         "int"

You wanted the float answer 3. from that line. What is the fix?

The marks are under 2.0, but which sign adds floats?

OCaml reads left to right. It saw +, decided ints were wanted and then blamed 2.0. The marks show where OCaml noticed the clash, which is not always where you made the mistake.

A shopping list line

Finish the second line so that label "eggs" 12 is "eggs: 12". item is a string and qty is an int.

Try the obvious item ^ ": " ^ qty first and read the error with the four steps above.

Three more real errors to practice on, and how utop shows them

utop may mark the spot by underlining the piece in the line you typed, with no ^^^ line. The Error: text is the same. Older versions of OCaml print the type names without quotes.

# print_endline 5;;
Line 1, characters 14-15:
1 | print_endline 5;;
                  ^
Error: This expression has type "int" but an expression was expected of type
         "string"

print_endline prints strings only, so the spot after it needs a string, and you gave the int 5. Fix: print_endline (string_of_int 5).

# 1 +. 2.0;;
Line 1, characters 0-1:
1 | 1 +. 2.0;;
    ^
Error: This expression has type "int" but an expression was expected of type
         "float"
  Hint: Did you mean "1."?

You used the float sign +. but wrote the int 1. OCaml adds a hint: you probably meant 1., the float one. Read hints. They are often right.

# let price = 10;;
val price : int = 10
# pirce + 1;;
Line 1, characters 0-5:
1 | pirce + 1;;
    ^^^^^
Error: Unbound value "pirce"
Hint: Did you mean "price"?

This one is not a type error. "Unbound value" means no let has made that name. It is nearly always a spelling mistake.

Printing with print_endline and Printf.printf, for when you want a program to show something

print_endline prints a string and then moves to a new line:

# print_endline "hello";;
hello
- : unit = ()

Two lines came back. hello is what got printed. - : unit = () is the value of the expression. Printing does something useful, but its answer is the plain value () of type unit.

To print numbers and text together, Printf.printf takes a format string with holes in it, then one value per hole. %d is a hole for an int, %s for a string, %f for a float, and \n means "new line":

# Printf.printf "%d %s\n" 42 "apples";;
42 apples
- : unit = ()
# Printf.printf "%.2f\n" 3.14159;;
3.14
- : unit = ()

%.2f prints a float with two digits after the point. OCaml checks the holes against the values. Put a float where %d expects an int and you get a type error before anything prints. int_of_string "42" goes from a string to the int 42.

Running OCaml from a file, for when your program is longer than one line

The toplevel is for trying things. Real programs live in files. Make a file called hello.ml in any plain text editor (VS Code is a good choice) with these two lines:

let () = print_endline "Hello, world!"
let () = Printf.printf "%d + %d = %d\n" 2 3 (2 + 3)

In the terminal, cd into the folder that holds it and run ocaml hello.ml. It prints:

Hello, world!
2 + 3 = 5

There is no ;;. In a file, each let starts a new definition, so OCaml can tell where one ends. Read let () = as "run this, and its answer must be ()". Printing gives (), so it fits. The parentheses in (2 + 3) matter: without them OCaml would hand 2 to printf as the third value and then try to add 3 to what printf gave back, which is a type error.

Check yourself

What value does OCaml give for 7 / 2?

Both 7 and 2 are ints. What type does dividing two ints give?

An int can't hold a half. What happens to it?

7 / 2 is int division, so the answer is the int 3 and the half is thrown away. For 3.5 you need floats: 7.0 /. 2.0.

utop replies val total : int = 30. Which part is the type?

A reply has three parts: name, type and value. Which one comes after the colon?

Name total, then : and the type int, then = and the value 30.

You type let price = 10;;, then let total = price * 3;;, then let price = 99;;. What is total now?

Does the third line change the old price, or make a new name?

When was total worked out, and which price existed then?

The second let price makes a new name that shadows the old one. total was computed from the first price, which never changed, so it stays 30.

Which line replies - : float = 3.5?

Floats need the sign with a dot, and a float on both sides of it.

+. adds floats, and both sides must be floats. 1.5 + 2.0 uses the int sign, and 1.5 +. 2 has an int on the right.

OCaml says Error: This expression has type "int" but an expression was expected of type "string", with the marks under a number. What does the place need?

"has type" is what you gave. "expected of type" is the other one.

"Expected of type string" is what the surrounding code needs. You gave an int, so convert it with string_of_int, or change the code around it.

What value does float_of_int 7 /. 2.0 give? Type the number.

Which happens first here, the conversion or the division?

float_of_int 7 is 7., and /. is float division.

7 becomes the float 7. before dividing, so /. keeps the half: 3.5. Compare float_of_int (7 / 2), which is 3..
