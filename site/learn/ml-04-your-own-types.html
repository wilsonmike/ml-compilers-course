Learn OCaml · Lesson 4

Your own types

So far every value had a type OCaml gave you: int, string, a list. In this lesson you make your own types. Your compiler is built from two of them: a record that holds one step of a program, and a variant for a value that can be one of a few kinds.

Goal

Define a record and a variant, build a tree out of a variant, and write a function that walks the tree.

You'll use

match, lists and option from O.3, let rec from O.2, and ^ and string_of_int from O.1.

Two shapes to watch for

Two types on this page come straight from the course. type node = { id : int; op : string; src : node list } is the piece your week 1 compiler is built from. type arg = Lit of int | Name of string is in the first interpreter you write in Build the thing that runs it.

Warm up

Two questions from earlier lessons, from memory. Pulling an idea back out of your head is what makes it stay.

What is total [2; 3; 4]?

let rec total l =
  match l with
  | [] -> 0
  | x :: rest -> x + total rest

The second case takes the first element and calls total on the rest.

2 + 3 + 4 + 0 is 9. One case per shape of list, and the function calls itself on the smaller part. You'll write that same pattern on trees today.

A function returns an int option. What can its result look like?

An option either holds a value or holds nothing.

An option is one of two kinds: Some with a value inside, or None. Today you'll build types like that yourself.

Values that belong together

In O.3 you packed two values into one with a tuple, such as ("eggs", 4). Here is a tuple that describes a rectangle on a screen:

let r = (3, 4)

Which number is the rectangle's width?

Look for anything in the tuple that says what each number means.

A tuple only has positions. You have to remember which one is which, and OCaml can't catch you if you swap two ints.

A record fixes that by giving each part a name. A named part is called a field. Here is the record your compiler uses for one step of a program, called a node:

# type node = { id : int; op : string; src : node list };;
type node = { id : int; op : string; src : node list; }
# let two = { id = 0; op = "2"; src = [] };;
val two : node = {id = 0; op = "2"; src = []}
# let three = { id = 1; op = "3"; src = [] };;
val three : node = {id = 1; op = "3"; src = []}
# let sum = { id = 2; op = "add"; src = [two; three] };;
val sum : node =
  {id = 2; op = "add";
   src = [{id = 0; op = "2"; src = []}; {id = 1; op = "3"; src = []}]}
  1. Describe the shape. The type line lists three fields. id is a number that tells nodes apart. op says what the node does. src, short for sources, is the list of nodes whose values it uses.
  2. Build values. Write every field with = and a value. A plain number uses no other node, so its src is [].
  3. Read the reply. You never said two is a node. OCaml worked it out from the field names.

Draw each node as a box and each source as an arrow, and sum is the picture of 2 + 3:

Read a field, copy a record

You read a field with a dot. A field's value is an ordinary value, so sum.src is a list like any other:

# sum.op;;
- : string = "add"
# List.length sum.src;;
- : int = 2

A record's fields can't be changed after you build it. To get a node like sum with a different op, you build a new one using with:

# let prod = { sum with op = "mul" };;
val prod : node =
  {id = 2; op = "mul";
   src = [{id = 0; op = "2"; src = []}; {id = 1; op = "3"; src = []}]}
# sum.op;;
- : string = "add"

{ sum with op = "mul" } means "a new record that copies every field from sum, except op". The old sum is still there, unchanged.

A shortcut for later starters: when a name is spelled like the field it fills, write it once. { id = 0; op; src } means { id = 0; op = op; src = src }.

What is List.length two.src?

two was built with src = [].

two.src is the empty list, and its length is 0. A plain number has no sources.

Label a node

label turns a node into text for a person to read. It already gives the id and the op, like "2: add". Finish it so the number of sources follows in parentheses: "2: add (2)".

What happens when you leave a field out

When you build a record from scratch you must give every field. { id = 5; op = "4" } fails with Error: Some record fields are undefined: "src". If you want most fields to stay the same, start from an existing record with with.

Making a new value and keeping the old one, as with does, is a habit you'll see all over OCaml. Nobody else who holds sum gets a surprise.

A value that is one of a few kinds

In the language your compiler will read, one line looks like mul %a 4. It means "multiply the value named a by 4". So each input to an op is one of two kinds: a name, or a plain number. You want to keep both inputs in one list. But ["a"; 4] is a type error, as [3; "four"] was in O.3: a list holds one type.

The fix is one new type that covers both kinds. A variant is a type whose values are one of a few listed kinds:

# type arg = Lit of int | Name of string;;
type arg = Lit of int | Name of string
# Lit 4;;
- : arg = Lit 4
# [Name "a"; Lit 4];;
- : arg list = [Name "a"; Lit 4]

Read the type as "an arg is either a Lit carrying an int, or a Name carrying a string". Lit is short for literal, a number written out directly. Lit and Name are constructors: each one builds a value of the type from the data after it. A constructor always starts with a capital letter.

Both elements now have the type arg, so the list is fine. You have used a variant already: option is one, with the constructors Some and None.

Which of these is a value of type arg?

Check the capital letter, then check what each constructor carries.

Name carries a string, so Name "out" is right. Lit carries an int, not a string. lit has no capital, so OCaml reads it as an ordinary name and says Unbound value "lit".

Kinds that carry nothing, and why not just use strings

A constructor doesn't have to carry data. A playing card's suit is one of four kinds and nothing more:

# type suit = Hearts | Diamonds | Clubs | Spades;;
type suit = Hearts | Diamonds | Clubs | Spades
# let colour s = match s with Hearts | Diamonds -> "red" | Clubs | Spades -> "black";;
val colour : suit -> string = <fun>
# colour Clubs;;
- : string = "black"

Hearts | Diamonds -> "red" is one case that covers two constructors. Why is this better than the strings "hearts" and "clubs"? Because a typo like "heats" is still a string, and nothing would warn you. Heats is not a constructor, so OCaml refuses it at once.

Take a variant apart with match

A function that gets an arg doesn't know which kind it got. It finds out with match, the tool you used on lists in O.3. This time there is one case per constructor:

# let describe a =
    match a with
    | Lit n -> "the number " ^ string_of_int n
    | Name s -> "the value named " ^ s;;
val describe : arg -> string = <fun>
# describe (Lit 4);;
- : string = "the number 4"
# describe (Name "a");;
- : string = "the value named a"

Follow describe (Lit 4):

  1. Find the kind. OCaml tries the cases from the top. The value is a Lit, so the first case matches.
  2. Name what is inside. The pattern Lit n gives the name n to the int the value carries. Here n is 4.
  3. Use it. The right side of the arrow builds "the number 4".

Checking the kind and pulling out the data happen in one step. You can't reach for the int inside a Name by mistake, because a Name has none.

Starters often use a short form: let describe = function Lit n -> ... | Name s -> ... is the same describe. function means "take one argument and match on it".

Print an operand

show writes an arg the way the compiler's language spells it: a name gets a % in front, and a number is written as it is. The Name case works. The Lit case returns an empty string. Repair it so show (Lit 4) is "4".

Forget a kind and OCaml tells you

Say you write describe in a hurry and leave out the Name case.

What do you think happens when you define it?

let describe a =
  match a with
  | Lit n -> "the number " ^ string_of_int n

OCaml knows every constructor of arg. It can compare that list with your cases.

OCaml checks every match against the type before the program runs. Its reply is below.

Lines 2-3, characters 2-44:
2 | ..match a with
3 |   | Lit n -> "the number " ^ string_of_int n..
Warning 8 [partial-match]: this pattern-matching is not exhaustive.
Here is an example of a case that is not matched:
Name _

val describe : arg -> string = <fun>

This is the missing-case warning you read in O.3. A match that covers every constructor is called exhaustive. The value this one can't handle is Name _, a Name carrying anything.

As before, it is only a warning. Call describe (Name "a") anyway and the program stops with Exception: Match_failure.

The catch-all _ hides the warning

A case | _ -> ... matches anything. Ending a match with | _ -> "something" makes the warning go away, and the help goes with it. Every kind you forgot, or add later, quietly gets that answer. Use _ only when you mean "every other kind behaves the same".

A kind that carries two values

A constructor can carry more than one value. Here is a shape that is either a circle, which needs a radius, or a rectangle, which needs a width and a height:

# type shape = Circle of float | Rect of float * float;;
type shape = Circle of float | Rect of float * float
# let area s = match s with Circle r -> 3.14159 *. r *. r | Rect (w, h) -> w *. h;;
val area : shape -> float = <fun>
# area (Rect (2.0, 3.0));;
- : float = 6.

float * float is the tuple type from O.3: "a float and a float". So you build a rectangle with parentheses and a comma, Rect (2.0, 3.0), and the pattern Rect (w, h) names both parts.

Perimeter of a shape

The starter adds a third shape, Square of float (the length of one side). Write perimeter : shape -> float, the distance around the shape. A circle's is 2 × π × r, a rectangle's is 2 × (w + h), and a square's is 4 × side. Use Float.pi for π.

One match case per constructor. Keep the type exactly as the starter has it, because the tests build shapes with it.

An expression as a tree

A compiler doesn't only compute arithmetic. It has to hold arithmetic as a value, so it can look at it and improve it first. A piece of arithmetic such as (2 + 3) * 4 is an expression, the word from O.1 for code that has a value. Each one is one of three kinds: a plain number, an addition of two smaller expressions, or a multiplication of two smaller expressions. That sentence is a variant:

# type expr = Num of int | Add of expr * expr | Mul of expr * expr;;
type expr = Num of int | Add of expr * expr | Mul of expr * expr
# let e = Mul (Add (Num 2, Num 3), Num 4);;
val e : expr = Mul (Add (Num 2, Num 3), Num 4)

The new thing is that expr appears inside its own definition. An Add carries two expressions, and each of those can be a Num, an Add or a Mul. A type that refers to itself is called recursive. It can hold arithmetic of any size. It still ends, because every branch reaches a Num sooner or later, and a Num carries only an int.

The value e is (2 + 3) * 4. Here it is as boxes and arrows, with the numbers on top and the result at the bottom. A picture shaped like this is called a tree.

The value needs no parentheses and no "times goes first" rule. Its shape already says the Add happens inside the Mul.

Without the parentheses, 2 + 3 * 4 means "2, plus the result of 3 times 4". Which value is its tree?

Which operation happens last? That one is the outermost constructor.

The addition happens last, so Add is on the outside, and the Mul of 3 and 4 is its right side.

Compute the value of a tree

To evaluate an expression means to work out its number. A recursive type calls for a recursive function, with one case per constructor:

# let rec eval e =
    match e with
    | Num n -> n
    | Add (a, b) -> eval a + eval b
    | Mul (a, b) -> eval a * eval b;;
val eval : expr -> int = <fun>
# eval e;;
- : int = 20
  1. A number is worth itself. This case makes no further call, so it is where the calls stop.
  2. An addition asks for both sides first. It calls eval on each smaller tree, then adds the two answers.
  3. A multiplication does the same with times.

Here is eval e, one call per row. An indented call sits inside the call above it and has to finish first.

      eval (Num 3)Num n, n = 33

Step through the same calls on the picture:

What is eval (Add (Num 2, Mul (Num 3, Num 4)))?

The Add has to wait for its right side, the Mul.

The Mul is 3 * 4 = 12, then the Add is 2 + 12 = 14. Same numbers as e, different tree, different answer.

Which side does OCaml compute first?

The trace does the left side first because it reads more easily. OCaml doesn't promise an order for the two sides of eval a + eval b, and in practice it often does the right one first. For a function like eval, which only computes a value and changes nothing, the order can't change the answer.

Walk a tree yourself

Every function over a tree has the shape of eval: match on the kind, call yourself on the smaller trees, combine the answers. Only the combining changes. Your compiler's functions over node work the same way, with src holding the smaller trees.

Evaluate an expression tree

The starter's expr has five constructors: Num, Add, Sub (subtraction, left minus right), Mul, and Neg (the negative of one expression). Its eval ends in a catch-all, so it answers 0 for most trees. Finish eval so every tree gets its real value. For example eval (Neg (Sub (Num 2, Num 9))) is 7.

Delete the | _ -> 0 line first and read the warning. Keep the type exactly as it is: the tests build trees with it.

Count the boxes in a tree

Write size : expr -> int, the number of boxes in the picture of a tree. A Num is one box. An Add or a Mul is one box plus all the boxes in its two sides. So size (Mul (Add (Num 2, Num 3), Num 4)) is 5.

Add a kind later and the warning finds every function to fix

Programs grow. Say you add a fourth constructor, Neg of expr, and leave eval as it was:

# type expr = Num of int | Add of expr * expr | Mul of expr * expr | Neg of expr;;
type expr =
    Num of int
  | Add of expr * expr
  | Mul of expr * expr
  | Neg of expr
# let rec eval e =
  match e with
  | Num n -> n
  | Add (a, b) -> eval a + eval b
  | Mul (a, b) -> eval a * eval b;;
Lines 2-5, characters 2-33:

In a big program you might have twenty functions that match on expr. Add a constructor and the compiler hands you a list of every one that needs a new case. You don't have to remember them. In a dune project, which you'll set up in lesson O.6, this warning is treated as an error, so the program won't build until you fix it.

A catch-all cuts that safety net. If eval ended in | _ -> 0, there would be no warning, and eval (Neg (Num 5)) would quietly return 0. A wrong answer with no warning is the hardest kind of bug to find.

When something goes wrong

Not every question has an answer. Try this one before reading on.

What does OCaml do with 10 / 0?

Is there any int that would be a correct answer?

No int is right, so OCaml refuses to give one. It prints Exception: Division_by_zero. and stops.

Stopping is safe, but the code that asked gets no chance to react. Often you'd like to hand back a value that says "this failed, and here is why". You know a type that says "maybe no answer": option. But None can't carry a reason. For that OCaml has result, a variant with two constructors. Ok carries the answer. Error carries a description of what went wrong.

# let check_age n = if n < 0 then Error "negative age" else Ok n;;
val check_age : int -> (int, string) result = <fun>
# check_age 31;;
- : (int, string) result = Ok 31
# check_age (-4);;
- : (int, string) result = Error "negative age"
# let report n =
    match check_age n with
    | Ok age -> "age " ^ string_of_int age
    | Error msg -> "bad input: " ^ msg;;
val report : int -> string = <fun>
# report (-4);;
- : string = "bad input: negative age"

Read the type (int, string) result as "either Ok with an int, or Error with a string". The caller takes it apart with match. OCaml checks that match like any other, so a caller who forgets the error case gets the warning.

Division that reports its error

Dividing by zero in OCaml stops the program. Write safe_div : int -> int -> (int, string) result that returns Ok (a / b) normally, and Error "division by zero" when b is 0.

Check b before you divide. The error message must be exactly "division by zero".

A longer result example: reading an age someone typed

Here two things can go wrong, and the message says which. int_of_string_opt turns text into an int and returns an option, so bad text gives None.

# let parse_age s =
    match int_of_string_opt s with
    | None -> Error "not a number"
    | Some n -> if n < 0 then Error "negative age" else Ok n;;
val parse_age : string -> (int, string) result = <fun>
# parse_age "31";;
- : (int, string) result = Ok 31
# parse_age "abc";;
- : (int, string) result = Error "not a number"
# parse_age "-4";;
- : (int, string) result = Error "negative age"

Option is right when "no answer" needs no explanation. If you look for something in a list and it isn't there, None says it all:

# List.find_opt (fun x -> x > 10) [3; 12; 7];;
- : int option = Some 12
# List.find_opt (fun x -> x > 100) [3; 12; 7];;
- : int option = None

Exceptions, briefly

What 10 / 0 did is called raising an exception. An exception doesn't return a value. It stops the current function, then the one that called it, and so on, until some code catches it. If nothing catches it, the whole program stops.

You can raise one yourself with failwith and a message. You catch one by wrapping the risky code in try ... with. The part after with is written like the cases of a match, but it matches exceptions:

# failwith "boom";;
Exception: Failure "boom".
# try 10 / 2 with Division_by_zero -> 7;;
- : int = 5
# int_of_string "7x";;
Exception: Failure "int_of_string".
# int_of_string_opt "42";;
- : int option = Some 42

If the code inside try finishes normally, its value is the answer. Many library functions come in two versions, like the last two lines: one raises an exception, and the one ending in _opt returns an option and never raises.

What is the value of try 10 / 0 with Division_by_zero -> 7?

The division raises Division_by_zero. Which case catches it?

The division raises, the Division_by_zero case catches it, and the value after its arrow becomes the answer: 7.

Raising a named exception, and what a type doesn't tell you

raise Not_found raises the standard "I looked and it isn't there" exception. Both raise and failwith have any type you like, so they fit in any branch:

# let get_first l = match l with x :: _ -> x | [] -> raise Not_found;;
val get_first : 'a list -> 'a = <fun>
# get_first [];;
Exception: Not_found.
# let first_big l = try List.find (fun x -> x > 100) l with Not_found -> 0;;
val first_big : int list -> int = <fun>
# first_big [3; 500; 7];;
- : int = 500
# first_big [3; 12];;
- : int = 0

If the code inside try raises Not_found, the Not_found -> 0 case runs. Any other exception passes straight through and keeps going up.

Notice what the type of List.find doesn't tell you: that it can fail. List.find_opt puts the failure in the type, as an option, and the compiler makes the caller deal with it. find leaves it out, and you only find out when it happens.

If you use List.find, or the table lookup Hashtbl.find from O.5, on something that might be missing, and nothing catches Not_found, the program stops with Exception: Not_found and no hint of which lookup failed. When the missing case is normal, reach for the _opt version and match on it.

What you can do now

  • Define a record like node, build one, read its fields, and copy it with one field changed using { r with ... }.
  • Define a variant like arg and take it apart with match, one case per constructor.
  • Read the warning for a missing case, and say why a catch-all _ can hide bugs.
  • Write a recursive type for a tree, like expr, and a recursive function that walks it.
  • Return a result when failure is expected, and raise and catch an exception.

Everything so far built new values and never changed an old one. Next, in O.5, you meet values that can change: refs, arrays and hash tables.

Check yourself

n is { id = 2; op = "add"; src = [] } and let m = { n with op = "mul" }. What is m.id?

Which fields does with copy from n?

Only op is given a new value. Every other field comes from n.

{ n with op = "mul" } copies every field of n except op. So m.id is n.id, which is 2, and m is {id = 2; op = "mul"; src = []}.

With type shape = Circle of float | Rect of float * float, which of these is a value of type shape?

Each constructor needs the data its type says it carries.

Rect carries float * float, a pair. How do you write a pair?

A pair is written with parentheses and a comma, so Rect (2.0, 3.0) is right. Circle alone is missing its radius, and Rect 2.0 3.0 passes two separate values instead of one pair. Both are errors.

What is eval (Mul (Add (Num 1, Num 2), Num 5))?

Draw the tree. What is at the bottom, and what are its two inputs?

The Mul needs the value of Add (Num 1, Num 2) first.

The inner Add is 1 + 2 = 3, then the Mul is 3 * 5 = 15. This tree is (1 + 2) * 5. Trees don't need parentheses because their shape already says what goes first.

You add | Neg of expr to expr. Your eval ends with | _ -> 0. What happens?

Does the _ case match a Neg?

If a match already has a case for everything, is it exhaustive?

_ matches every value, including Neg, so the match is exhaustive and the compiler has nothing to warn about. You get a wrong answer, 0 instead of -5, with no sign that anything is off. That's the catch-all trap.

A program reads a date that a person typed. It can be malformed in several ways, and you want to show the person what was wrong. Which return type fits best?

Is bad input expected here, or a bug?

Does the caller need to know why it failed?

People mistype dates all the time, so failure is expected, and the message has to say what was wrong. result carries that message in Error, and the type forces the caller to handle it. An option would lose the reason, and an exception hides the possibility of failure from the type.

What does int_of_string_opt "7x" return?

Is "7x" a whole number?

The _opt version never raises. It returns an option.

None. The text isn't a valid int, and the _opt version reports that with None. int_of_string "7x", without _opt, would raise Failure "int_of_string" instead.
