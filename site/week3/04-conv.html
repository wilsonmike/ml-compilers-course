A convolution by hand

A convolution slides a small window along a row of numbers and adds up what it sees. It is how a program blurs a sound or finds an edge in a photo, and next to the matrix multiply it is the loop nest machine learning runs most. You will write one in .uir, so that your compiler can turn it into C in the next lesson.

Goal

Write a 1D convolution, handle its edges with a mask, and index a 2D one on a flat buffer.

You'll use

The GEMM from lesson 3.3: an accumulator that lives in the output element, and r*cols + c indexing. Bounds proved from intervals (lesson 2.3). The ops where, cmplt and mod from week 1. If a mod that floors feels shaky, see H.4 Numbers that behave like C.

Warm up

Two ideas from earlier lessons that this one needs. Pulling an idea back out of your head is what makes it stay.

A matrix with 6 columns sits in a flat row-major buffer. At which offset is the element in row 1, column 4?

Element (r, c) is at r*cols + c.

1*6 + 4 = 10. One full row of 6, then four steps.

In .uir, what is mod -1 6?

.uir's mod floors. Dividing by 6, the remainder is always one of 0 to 5.

5, because -1 = 6*(-1) + 5. C's % would say -1. You will need this at the edges.

Slide a window and add up

Take a row of numbers, x. It could be sound samples, or one row of pixels in a photo. In this one the brightness jumps from 2 to 8:

x = [2 2 2 8 8 8]

Now take a short list of weights called the kernel: w = [-1 0 1]. (Unrelated to the C function named kernel that your renderer prints.) Lay it over the first three numbers of x. Those three numbers are the window. Multiply each one by the weight above it and add the three products. That sum is the first output. Slide the kernel one step right and repeat. Doing this at every position is a convolution:

y[i] = x[i]*w[0] + x[i+1]*w[1] + x[i+2]*w[2]

Work out y[1] by hand.

The window for output 1 is x[1], x[2], x[3], which is 2, 2, 8.

2*(-1) + 2*0 + 8*1 = 6. The window sits across the jump, so the answer is large.

This kernel subtracts the left neighbor from the right one. It gives 0 where the row is flat and a large number where it jumps, so it finds edges. Change the kernel to [1 1 1] and each output adds three neighbors, which smooths the row: a blur. The loops are the same and only the weights differ. A convolution layer in a neural network is this too, with weights it learned.

There are 4 outputs and not 6, because the window has to fit inside x. It can start at 0, 1, 2 or 3, which is 6 - 3 + 1 places. A convolution whose window never leaves the input is called valid. One element of the kernel is called a tap.

For readers who know the math definition: this one does not flip the kernel

A math textbook's convolution reverses the kernel first, so it computes x[i+2]*w[0] + x[i+1]*w[1] + x[i]*w[2]. What this lesson computes is called cross-correlation there. Machine learning libraries use the unflipped form and call it convolution, and so does this course. The loops are the same either way.

The window sum as two loops

Put this next to one output element of the GEMM in lesson 3.3:

GEMM1D convolution

what it multipliesA[i*K + k] * B[k*N + j]x[i + k] * w[k]

The one new thing is the index i + k: start at i, then step k into the window. Two outputs next to each other read some of the same inputs. Before you read the program, predict what the bounds check makes of that index.

%i = range 4, %k = range 3 and %ik = add %i %k. The buffer %x has 6 elements. What does the compiler do with shrink %x %ik []?

A range's interval is [0, n-1]. Add the two intervals end by end.

i is in [0, 3] and k is in [0, 2], so i + k is in [0, 5]. That fits a 6-element buffer exactly, with no extra work.

Here is the whole loop nest, for f32 buffers %x (6), %w (3) and %y (4):

%i   = range 4
%yv  = shrink %y %i []
%z   = store %yv 0.0          # reset y[i], once per i
%y0  = after %y %z
%k   = range 3
%ik  = add %i %k
%xv  = shrink %x %ik []       # x[i + k]: interval [0, 3] + [0, 2] = [0, 5]
%xe  = load %xv
%wv  = shrink %w %k []
%we  = load %wv
%p   = mul %xe %we
%yv0 = shrink %y0 %i []
%cur = load %yv0              # runs inside the k loop: its only use is there
%sum = add %cur %p
%s   = store %yv0 %sum
%ek  = end %s %k
%ei  = end %ek %i
%y1  = after %y %ei
  1. Reset the output. %z stores 0.0 into y[i]. Its offset uses %i, so it runs once per output.
  2. Read the two inputs. x[i + k] and w[k], both inside the k loop.
  3. Add into the output. Load y[i] from %y0, the version after the reset. Add the product and store it back.
  4. Close the loops. k first, which makes it the inner loop, then i.

Write the valid convolution

Slot 0 is x (6 i32), slot 1 is w (3 i32), slot 2 is y (4 i32). Make the final contents of slot 2 equal y[i] = x[i]*w[0] + x[i+1]*w[1] + x[i+2]*w[2] for every i in 0..3. The starter only uses w[0]. The tests set slots 0 and 1. i32 sums wrap as usual.

The C the oracle renders for this loop nest, for when you write your renderer

No masking is needed: the range intervals alone prove i + k stays in [0, 5]. The oracle renders it as two loops, with the reset store in the outer one:

for (int32_t r6 = 0; r6 < 4; r6++) {
  b2[r6] = 0x0.0p+0f;
  for (int32_t r11 = 0; r11 < 3; r11++) {
    float v12 = b2[r6];
    int32_t v13 = (int32_t)((uint32_t)r6 + (uint32_t)r11);
    float v15 = b0[v13];
    float v17 = b1[r11];
    float v18 = (v15 * v17);
    float v19 = (v12 + v18);
    b2[r6] = v19;
  }
}

The edges: reading past the end

Often you want as many outputs as inputs, so that a blurred row is as long as the original. Then the window is centered on i, and it hangs off both ends: y[0] needs x[-1] and y[5] needs x[6]. The usual answer is zero padding: any read outside x counts as 0.

y[i] = x[i-1]*w[0] + x[i]*w[1] + x[i+1]*w[2]     with x = 0 outside [0, 6)

Call the index that gets read j = i + k - 1. The obvious program shrinks x at j.

With %i = range 6 and %k = range 3, a program does shrink %x %j [] on the 6-element x. What does ./compile print?

Work out the interval of i + k - 1. The bounds check runs before the program does.

j is in [-1, 6]. A view has to be provably inside its buffer for every value in that interval, and -1 and 6 are not, so the program is rejected before it runs.

So the offset itself has to change. You need one that is legal for every i and k, even when it points at the wrong element. mod %j 6 is one: mod floors, so its result is always in [0, 5], as in the warm up. At j = -1 it reads x[5], and at j = 6 it reads x[0]. Both are the wrong element, read legally. The next part throws them away.

A mask instead of an if

In C you would put if (j >= 0 && j < 6) around the read. .uir has no if. A program is a graph of values, and every line of a loop body is computed on every pass. What it has is where, which computes both of its sides and then picks one. So the plan has two parts: always load something legal, then pick between the loaded value and 0. The bool that does the picking is called a mask.

%j  = add %ik -1              # i + k - 1, in [-1, 6]
%lo = cmplt %j 0              # off the left end
%hi = cmplt %j 6              # not off the right end
%ok = where %lo false %hi     # 0 <= j < 6
%jm = mod %j 6                # [0, 5]: provably in bounds
%xv = shrink %x %jm []
%xe = load %xv                # a real element, maybe the wrong one
%xz = where %ok %xe 0.0       # the padding value where j is off the end

Read %ok as: if j is below 0 then false, otherwise whether j is below 6. The rest of the loop is the valid convolution, with %xz in place of %xe.

The mask doesn't prove anything

It's tempting to think where %ok ... makes the raw index safe, because the bad element is never used. But the load still happens, and the bounds proof only looks at the offset's interval. A where doesn't narrow an interval (lesson 2.3). The offset itself has to be provably legal, which is why you need both the mod and the mask.

Add the mask

Slots 0, 1 and 2 are x (6 i32), w (3 i32) and y (6 i32). The starter is the whole padded convolution except the mask, so at the two ends it wraps around and reads the far end of x. Add the mask so that reads outside x count as 0.

Same-size convolution with zero padding

Slot 0 is x (6 f32), slot 1 is w (3 f32), slot 2 is y (6 f32). Make the final contents of slot 2

y[i] = x[i-1]*w[0] + x[i]*w[1] + x[i+1]*w[2]

for every i in 0..5, where any x outside [0, 6) counts as 0.0. Every view must be provably in bounds, so mask the index instead of shrinking at i + k - 1 directly. Add terms in order k = 0, 1, 2, starting from 0.0, so the f32 rounding matches.

Why real compilers like masks even where an if is allowed

A loop body with no branch does the same work on every pass. That is the shape a CPU's vector instructions need, since they run several passes at once and cannot take a branch for only some of them. Picking with a mask after computing both sides is how compilers vectorize loops that had an if in them.

Two dimensions on a flat buffer

A photo has rows and columns, so its kernel does too: a small rectangle that slides right and down. The buffers stay flat. As in the GEMM, element (r, c) of a buffer with W columns is at r*W + c (lesson 0.4).

What is the same: the accumulator in the output element, its reset, and bounds from intervals. What is new: four loops and not three. Two pick the output position, oi and oj. Two walk the kernel, ki and kj. The input under kernel tap (ki, kj) is in row oi + ki and column oj + kj, which is the 1D index once per direction. For an H by W input and a KH by KW kernel:

y[oi*OW + oj] = sum over ki, kj of x[(oi + ki)*W + (oj + kj)] * w[ki*KW + kj]
OH = H - KH + 1,  OW = W - KW + 1

Take output (1, 1) of that figure by hand:

  1. Find the window. Rows 1 to 2 and columns 1 to 2 of x: 6 7 above 10 11.
  2. Turn each position into an offset. Each buffer uses its own row length: r*4 + c in x, ki*2 + kj in w and oi*3 + oj in y.
  3. Multiply and add. 6*1 + 7*0 + 10*0 + 11*(-1) = -5, stored at y[1*3 + 1].

Same 4 by 4 input. Which offset in x does output (2, 1) read for kernel tap (1, 1)?

Row oi + ki, column oj + kj, then r*4 + c.

Row 2 + 1 = 3 and column 1 + 1 = 2, so 3*4 + 2 = 14.

Every output here was a dot product of the kernel with one window, like one GEMM element. Stack the windows as the rows of a matrix and the whole convolution is windows @ w. The toggle shows it. Next, lesson 3.5 turns loop nests like these into C: it decides which line goes inside which for.

A convolution is a matrix multiply in disguise, and what week 5 does with that

Look at the valid 1D convolution again. Every output is a dot product of the kernel with one window. Write the windows as the rows of a matrix:

windows (4 x 3)      w (3)        y (4)
[1 2 3]              [ 1]         [-2]
[2 3 4]      @       [ 0]    =    [-2]
[3 4 5]              [-1]         [-2]
[4 5 6]                           [-2]

That windows matrix doesn't need to exist in memory. Row i, column k of it is just x[i + k], the same element read by several rows. The whole trick of a convolution is that index map: (i, k) → i + k. Week 5 introduces movement ops (reshape, permute, pad) that describe exactly these index maps on shapes, so you'll write conv as a few movement ops followed by a multiply and a reduce, and the compiler will produce these loops for you. Padding becomes a pad op, and the masking you wrote by hand becomes something the compiler emits.

Check yourself

A valid 1D convolution has an input of length 10 and a kernel of length 3. How many outputs are there?

The window has to fit entirely inside the input. Where can its first element start?

8: the window can start at 0 through 7, so 10 - 3 + 1 outputs.

With x = [1 2 3 4 5 6] and w = [1 0 -1], what is y[2] for the valid convolution?

The window for output 2 is x[2], x[3], x[4].

-2: 3*1 + 4*0 + 5*(-1). Every output of this kernel is the difference of two elements two apart, and x rises by 1 per element, so all four outputs are -2.

For the padded convolution, j = i + k - 1 with i in [0, 5] and k in [0, 2]. Which offset can you shrink a 6-element x at?

Work out each interval. In .uir, mod floors: a nonzero remainder has the sign of the right operand.

A view of one element at offset [lo, hi] needs lo ≥ 0 and hi + 1 ≤ 6.

mod j 6 floors, so it's in [0, 5] even though j can be -1 (mod -1 6 is 5). max j 0 is in [0, 6] and add j 1 is in [0, 7], both past the end, and j itself starts at -1. The oracle rejects the other three. A where never narrows an interval. In C, -1 % 6 is -1, so a renderer can't print mod as a bare %.

In the convolution, why does the reset store write to y[i] instead of to a one-element alloc?

Which ranges does store %a 0.0 depend on, if %a is a view at a constant offset?

Placement follows open ranges. A reset that depends on i (through its offset) runs once per i, and one that depends on nothing runs once in total. Accumulating straight into the output at an offset built from the outer ranges gives you the reset for free.

A 2D input is H = 5 rows by W = 7 columns, flat and row-major. Which offset is output (oi, oj)'s kernel tap (ki, kj)?

Row-major means you multiply the row by the number of columns.

Row oi + ki, column oj + kj, and a row is 7 elements long, so (a). Option (b) multiplies by the number of rows instead of the row length, and (c) is the column-major formula, which walks down columns.

The valid convolution of a length-6 input with a length-3 kernel equals windows @ w. What's the shape of windows? (rows, columns)

One row per output, one column per kernel tap.

4 by 3: four outputs, three taps. Row i, column k is x[i + k], so the 12 entries are only 6 distinct input elements.
