Week 3 · Lesson 5

Rendering loops

A program with ranges is still a graph: nothing in it says "this line goes inside that loop". Your renderer has to work that out. Every value gets a depth from the ranges it depends on, every end becomes a for loop, and the result is a nest of blocks you can print top to bottom.

Where does a value live?

Week 2's renderer printed one flat list. Now each value has to land inside the right loops. The rule from the spec is short:

  • A value is computed inside every loop whose range it depends on, and no deeper. Its depth is the deepest of its open ranges. A constant, or anything built only from constants and buffers, lives outside every loop.
  • A load is placed the same way, with one exception. First place it by its own open ranges. Then find the innermost loop holding every use of it. If that loop is deeper, and it stores into the version the load reads, the load moves into it and sees the current contents on every iteration. A use counts as inside a loop only if it's placed there itself. That's the accumulator from lesson 3.2.
  • An end is a loop. It sits in the block around its loop, and its loop body is a new block holding everything whose deepest range is the one it closes.

Those three rules turn the graph into nested blocks. Inside every block the week 2 order still applies: sources first, and loads of a version before the store that overwrites it. Step through the valid 1D convolution from lesson 4.

Which loop is outside?

The graph never says "loop oi is outside loop oj". You read it off the ends. %eoj = end %eki %oj closes oj, but its effect still depends on oi, so %eoj has oi open. Then %eoi = end %eoj %oi repeats that whole oj loop for every oi. In general, the ranges an end still has open after closing its own are exactly the loops around it.

So the loop order is a property you compute by walking the graph, and the placement of every node follows from it. The syllabus says this is the first week you'll likely want a rewrite engine to "order the ranges properly": a pass that, rule by rule, pushes each node into the loop where it belongs and pulls loop-invariant work out. You can also do it directly, by computing depths and building blocks as in the stepper. Either way, keep it in its own pass. Week 4's rangeify will create ranges for you, and a renderer that knows how to place nodes is what turns those into loops.

What the grader allows now

The render grader still removes comments and strings, then looks for loops. For a program that contains a range, for is allowed and while, do and goto are not. For a program with no ranges (every week 2 test), any loop at all fails the test, exactly as before.

Which loop does a node live in?

A toy graph has two kinds of node: Range (d, name)Range(depth, name), a loop counter at nesting depth d (1 is the outermost loop), and Op (name, srcs)Op(name, srcs). Check yourself

Loops nest i (outermost), then j, then k. A value is add %i %k. Where is it computed?

A value lives at the depth of its deepest open range.

It depends on k, the innermost range, so it's computed every k iteration, even though it doesn't use j.

Same nest. Where is mul %i 3 computed?

What's the deepest range it depends on?

Its only range is i, so it's hoisted out of j and k. Ordinary values stay at the depth of their ranges. Only a load whose uses sit in a deeper loop that writes the version it reads moves toward those uses.

In the convolution, the accumulator load %cur = load %yv0 depends on i but not on k. Its only use is inside the k loop, and the k loop stores into the version it reads. Where does it run?

This is the one placement rule that isn't about open ranges.

A load runs in the innermost loop holding all its uses, and because that loop stores into the version it reads, it reloads every iteration and sees the running sum. Anywhere else, every iteration would add to the same starting value.

Which range does the store depend on, and which one does the end close?

2. The store depends on i, but the end closes j, which its effect doesn't use. The oracle rejects it: "end closes a range its effects don't use".

One range %i is closed by two different ends, one around a store into slot 0 and one around a store into slot 1. Is that a valid program?

A range is the loop. How many loops can one loop be?

A range names one loop, so it gets one end. To write two buffers in the same loop, give that end both effects. The oracle accepts end %s0 %s1 %i and rejects the two-end version.

After this program, what's in c[2]?

%b  = buffer 3 dtype=i32 slot=0
%c  = buffer 3 dtype=i32 slot=1

One loop runs both stores. What does the second store write at i = 2?

4: the loop writes i*i into c[i], so c = [0 1 4]. Both afters take the same end, one per buffer it wrote.
