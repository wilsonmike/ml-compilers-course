Lab: rangeify

In this lab your compiler learns whole vectors. It checks shapes, runs expand, reduce and stage, and turns every one of them into loops when it renders C. You build it in the order the week taught it, and every step ends with something you can run.

What you are building

The same three commands as last week. What changes is which programs they take.

  • compile FILE judges programs with values that have a shape. An ALU op takes operands of one shared shape, () or (n,), and works elementwise. Three ops are new: expand, reduce and stage. A program that breaks a shape rule is REJECTED.
  • compile render FILE prints loops for those programs. The C must be at most 20,000 bytes, whatever the vector length.
  • compile simplify FILE does not change.

The suite has 55 run tests and 35 render tests. The language contract is spec/uir-week4.md. If this page and the spec disagree, the spec wins.

How a render test is graded, step by step, for when a kernel fails

For each # render test, the grader goes through five steps in order:

  1. Runs your.exe render FILE and fails the test on a nonzero exit.
  2. Fails the test if your output is over 20,000 bytes (counted as UTF-8).
  3. Parses the program with the oracle to decide whether loops are allowed (the rule in the table above), strips comments and string literals from your C, and fails the test if it finds while, do or goto, or for when loops aren't allowed.
  4. Writes its own main and compiles both files with clang -std=c11 -O2 -ffp-contract=off -fsanitize=undefined -fsanitize-trap=undefined ... -lm.
  5. Runs it and compares every element of every buffer with the oracle: i32 and bool exactly, f32 bit for bit, any NaN matching any NaN.

The bit-for-bit comparison is what makes the fold order matter. A reduce that folds right to left turns 1e8, 1, -1e8, 1 into 0 instead of 1, and one that starts from 0.0f turns a lone -0.0 into +0.0. Either way the bits differ and the test fails.

  1. Change the type rule. An ALU op used to need scalars. Now every operand must have the same shape, and the result has that shape. For where that includes the condition. A vector with a scalar is still an error.
  2. Add expand. expand x [n] takes a scalar and a shape with n of 1 or more. Its result has shape (n,).
  3. Refuse vectors in hand-written loops. A vector made by an ALU op or a new op may not depend on an open range.

Run reduce and stage

First write a reduce yourself, so you know what your evaluator has to compute.

A dot product

Slots 0 and 1 are a and b (4 f32 each). Write their dot product, the left fold of a[i] * b[i], into the one-element buffer in slot 2. No hand-written range.

  1. Type reduce. reduce x op=add takes one i32 or f32 vector and gives a scalar. The op is required and is add, mul or max. A scalar operand, a bool vector or any other op is rejected.
  2. Fold from the left. Start with x[0]. Fold in x[1], then x[2], to the end, with your scalar op at every step. Never start from 0 or 1.
  3. Pass stage through. stage x has the type of x and its value. In the evaluator it does nothing.
  4. Widen the bounds. In your interval analysis, an expand, a reduce and a stage each get the full range of their dtype.

Turn a store into a loop

Now render. Rangeify is a pass that takes the checked program and builds a week 3 program. Start with the op that makes the plainest loop, a store of a whole vector.

  1. Write "the element at i". One function takes a vector and a scalar index and returns a scalar. An elementwise op is the same op on its operands' elements at i. A load of a view is a scalar load at the view's offset plus i. An expand is its scalar. Remember each answer, so the same question builds one node.
  2. Lower the store. Make a range n. Store the value's element at the range into the view at the range. Close it with an end, and hand that end to the after that took the store.
  3. Print it with week 3. Give the new program to your placement pass and your printer.
  4. Keep week 2 loopless. Send a program through rangeify only when it may loop. The contract toggle in "What you are building" has the rule.

Turn a reduce into a loop

A reduce becomes the accumulator loop from lesson 3.2.

How many trips does the loop for a reduce of 4,096 elements make?

Lesson 4.3: the first element does not go through the loop. It is the seed.

4095. Element 0 seeds the accumulator, and the loop folds in elements 1 to 4095.

  1. Seed. Make a one-element alloc. Store the operand's element at 0 into it.
  2. Fold. Open a range n-1. Load the accumulator, fold in the operand's element at the range plus 1, store the result and close with end.
  3. Read. Load the accumulator after the loop. That scalar is the reduce.
  4. Build it once. Remember the result for each reduce, so two uses share one loop.

A reduce of one element makes a range 0, and week 3 already runs that zero times.

Turn a stage into a temp

The last op. A staged vector is computed once, into memory of its own.

%q = stage %d has 2,048 elements, and a reduce and a store both read %q. How many loops does the C have?

Lesson 4.4: one loop fills the temp. Then count the uses.

3. One loop fills the temp, one folds it and one stores. The fill loop is built once, however many uses read it.

  1. Fill a temp. Make an alloc of n elements. Add a loop that stores the operand's element at i into it.
  2. Answer with a load. The element at i of a stage is a load from the filled temp at i.
  3. Build it once. Every use of the same stage reads the same temp.
  4. Stage a store that reads its own memory. If any load in a stored vector's graph reads the buffer the store writes, treat the value as staged: fill a temp, then copy it in.

A stage of a scalar can be the scalar itself.

Check yourself

Your renderer passes every small week 4 render test but fails the 4096-element ones with a size error. What's the likely cause?

Which kind of code grows with n?

Only unrolled code grows with the vector length. Fold order would show up as wrong bits, and stage never changes the result or makes the code grow with n.

May the rendered C for this program contain a for loop?

%x = buffer 4 dtype=f32 slot=0
%y = buffer 4 dtype=f32 slot=1
%v = load %x
%t = mul %v %v
%s = store %y %t
%y1 = after %y %s

Read the loop rule in the contract table.

mul %v %v is an ALU op on a (4,) value, which is enough for the grader to allow for loops. The size threshold in the rule is 32 elements, not 16, and it applies to any rank-1 value even without an ALU op.

What outcome should ./compile print for this file?

%x = buffer 4 dtype=f32 slot=0
%v = load %x
%w = add %v 1.0
%s = reduce %w op=add
%t = assert %s 4.0

What shapes does the add see?

REJECTED. %v is (4,) and 1.0 is a scalar, and there is no implicit broadcast, so the add is a type error. It needs expand 1.0 [4].

Your staged and unstaged versions of the same program give different bits. Where is the bug?

Lesson 4.4: what can stage change?

Stage changes work and memory traffic, never the result. Different bits mean your two lowerings compute different things, often a reduce that folds the temp in a different order than the recomputed value.
