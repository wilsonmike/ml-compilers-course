How it works

  1. Guess firstEach idea starts with a question you answer before it is explained, then a diagram you step through one line at a time.
  2. Repair, then write1,200 quizzes and 437 graded exercises. You fix a nearly finished program before you write your own. Python and .uir run right here with no install.
  3. BuildEach week ends in a lab where you grow your own compiler until that week's test suite passes.

The course opens with two short steps where you run a program and write a tiny interpreter. Weeks 1 to 10 have six lessons each. C, memory and matrix math live in the library, and your path brings each one in just before the week that needs it. A week is a chunk of material, not a deadline.

Set up your machine (when you start building)

Python and .uir lesson exercises run right in your browser on this site with no setup. Clone the repo when you want to run C or OCaml exercises locally, or when you start grading your own compiler at the end of week 1. New to programming? Lesson P.1O.1 shows you how to set up your computer and use a terminal.

  1. Get the course folder: git clone https://github.com/wilsonmike/ml-compilers-course.
  2. Install Python 3.10 or newer. The course tools run on it, on both tracks. Install OCaml too. Lesson 0.6 shows how.
  3. Install a C compiler, clang or gcc. clang --version tells you if you have one. On macOS run xcode-select --install, and on Ubuntu sudo apt install clang. On Windows, install a MinGW-w64 build of gcc (lesson 0.1 says where), or work inside WSL with Ubuntu, which the OCaml track and CUDA also prefer.
  4. In the course folder, run python tools/serve.py and open http://127.0.0.1:4111. Exercises run through it, and the top bar shows whether it's on.

You don't need a GPU. Weeks 8 to 10 run CUDA in an emulator when there isn't one (lesson 8.5). Each week's lab ends with python tools/test.py --compiler YOUR_COMPILER --week N.

Your compiler is yours

The point of the course is that you write it. The templates/AGENTS.md file, copied into your repository, lets an AI assistant explain, draw and ask debugging questions, but never write compiler code. The reference compiler in _reference/ is the oracle the tests compare against. Run it as often as you like, and leave it closed. It's written in Python too, so a glance at it would hand you answers you're meant to find yourself.It's written in Python, so it can't be pasted into your OCaml, but reading it would still spoil the puzzles.
