ML compilers, from zero

A course where you build a machine learning compiler yourself, one week at a time. You start by interpreting add 2 3 and, months later, generate code fast enough to train a language model.

Start with lesson 0.1 Skip to week 1

It's for programmers who are comfortable in some language but have never written a compiler or a GPU kernel. Week 0 teaches the C, memory and matrix math the rest assumes. Each week after it is six lessons, the last one a lab where your compiler passes that week's tests. Go at your own pace: a week is a chunk of material, not a deadline. New to all this? Read Start here first, then begin with lesson 0.1.

The resources have a study guide and quiz review for every week, a guide to each failing test, a debugging walkthrough, and a glossary of every term the lessons use.

How the course works

Each lesson explains one idea with diagrams you can step through, then asks you to use it. Quizzes check that the idea landed. Exercises in your language, C, or .uir run on your machine against hidden tests, with hints if you get stuck.

Pick your language

You write your compiler in Python or in OCaml. Python is the default. Choose under Language at the bottom of the sidebar. Exercises and the few instructions that differ, such as build commands, follow your choice. Lesson 0.7 sets up a Python compiler, and lesson 0.6 teaches OCaml from scratch. Pick OCaml if you want its pattern matching and type checker, and Python if you'd rather spend your time on the compiler than on a new language.

At the end of each week you extend your own compiler, in your own repository, until the week's test suite passes. Week 1's suite has 148 tests, and it catches every one of the bugs deliberately planted in the reference compiler, so a green run means something.

Start here

Get the course folder with git clone https://github.com/wilsonmike/ml-compilers-course. Install Python 3.10 or newer (lesson 0.7) and, on the OCaml track, OCaml (lesson 0.6). You also need a C compiler, clang or gcc, on your PATH: the week 0 C exercises use it, and from week 2 the grader compiles the C your compiler prints. clang --version tells you if you have one. If not, run xcode-select --install on macOS or sudo apt install clang on Ubuntu. On Windows, install a MinGW-w64 build of gcc (lesson 0.1 says where), or work inside WSL with Ubuntu, which the OCaml track and CUDA also prefer. You don't need a GPU: weeks 8 and 9 run CUDA in an emulator when there isn't one (lesson 8.5). From the course folder, run python tools/serve.py and open http://127.0.0.1:4111 to run exercises. The indicator in the top bar shows whether the runner is on, and lessons still read fine without it. Each week's lab ends with python tools/test.py --compiler YOUR_COMPILER --week N.

Your compiler is yours

The point of the course is that you write it. The templates/AGENTS.md file, copied into your repository, lets an AI assistant explain, draw, and ask debugging questions, but never write compiler code. The reference compiler in _reference/ is the oracle the tests compare against. Run it as often as you like, and leave it closed. It's written in Python too, so a glance at it would hand you answers you're meant to find yourself.It's written in Python, so it can't be pasted into your OCaml, but reading it would still spoil the puzzles.
