A grid of numbers in one row of memory

Week 3 has you write loops over grids of numbers, and your buffers are still flat rows of boxes. This lesson gives you the words for those grids and the one skill week 3 needs: finding where a cell of a grid sits in a flat buffer.

Goal

Read a shape, and turn a row and a column into a position in a flat buffer with r*cols + c.

Warm up

Two questions from weeks 1 and 2, from memory. Pulling an idea back out of your head is what makes it stay.

A buffer holds 12 numbers. Its boxes are numbered starting from 0. What is the number of the last box?

The first box is 0, not 1.

The boxes are 0, 1, 2 and so on up to 11. That is 12 boxes.

A buffer holds 10 20 30 40 50 60. You skip 4 boxes from the start and read one number. Which number do you read?

Skipping 4 boxes passes boxes 0, 1, 2 and 3.

You land on box 4, which holds 50. Week 2 wrote this as shrink %b 4 []: a start plus an offset. Everything on this page is a way to work out that offset.

A grid has to fit in one row

A spreadsheet is a grid of numbers. So is a gray photo: each pixel is one number that says how bright that spot is. Here is a tiny one with 3 rows and 4 columns. Rows and columns count from 0, so the dark cell is row 1, column 2.

The computer's memory is not a grid. It is one long row of boxes. The simplest plan is to put all of row 0 in first, then all of row 1, then all of row 2.

With that plan, which box of the buffer holds row 1, column 2?

Row 0 goes in first. How many boxes does it fill?

Row 0 fills boxes 0 to 3. Row 1 starts at box 4. Now count along to column 2.

Box 6. Row 0 fills boxes 0, 1, 2 and 3. Row 1 starts at box 4, and column 2 is two steps along: 4, 5, 6.

Storing a grid one row after another is called row-major order. C, NumPy, PyTorch and this course all use it. Click a cell below to see where it lands in the buffer.

Names for a number, a row, a grid and a stack

Four words name these things by how many directions you can count along. Each direction is called an axis, and the number of axes is the rank.

A shape is the list of sizes, one for each axis. For a matrix the rows come first, so (3, 4) means 3 rows and 4 columns. For a stack, the number of grids comes before that. People also say tensor for all four, at any rank.

To count the numbers a shape holds, multiply its sizes. The (3, 4) photo holds 12 numbers, and the color photo holds 3 * 3 * 4 = 36.

The comma in (4,) only marks it as a list with one size. In a .uir program a shape is written with square brackets and no commas, like [3 4].

A gray photo is 2 pixels tall and 5 pixels wide. What is its shape?

Rows come first. How many rows does a photo 2 pixels tall have?

2 pixels tall means 2 rows, and 5 wide means 5 columns. Rows come first: (2, 5).

How many numbers does a tensor of shape (3, 2, 5) hold?

It is 3 grids. Each grid has 2 rows of 5.

3 * 2 * 5 = 30. One grid holds 10 numbers and there are 3 grids.

The rule: r*cols + c

You found box 6 by counting. A compiler needs a rule it can compute. In a grid with cols columns, row r, column c sits at position

r*cols + c

Here it is for row 2, column 1 of the (3, 4) grid:

  1. Skip the rows above. Rows 0 and 1 come first. Each is 4 boxes long, so that is 2 * 4 = 8 boxes.
  2. Step along the row. Column 1 is 1 step in.
  3. Add. 8 + 1 = 9, so the cell is in box 9.

The number of rows is not in the rule. You multiply by the number of columns, because that is how long one row is.

A grid has 5 columns. Which position holds row 3, column 2?

r*cols + c with r = 3, cols = 5 and c = 2.

3*5 + 2 = 17. Three whole rows are 15 boxes, then two steps along.

A grid has shape (3, 2). Which position holds row r, column c?

How many boxes long is one row of this grid?

Shape (3, 2) is 3 rows of 2 columns. Each row is 2 boxes long, so skipping r rows skips r*2 boxes.

Repair: read one cell of a flat grid

get takes a grid stored row after row in a flat list, its number of rows and columns, and a row r and column c. It should return the number in that cell. It gets square grids right and other grids wrong. Fix the position it reads.

Loop over one row

Week 3 does not read one cell. It loops over whole rows and columns. A loop over a grid is a loop that builds flat positions with the same rule.

A (2, 3) grid is stored as 1 2 3 4 5 6. A loop counts c from 0 to 2 and adds up the numbers at positions 1*3 + c. What is the total?

The positions are 3, 4 and 5. Which numbers sit there?

Positions 3, 4 and 5 hold 4, 5 and 6, and 4 + 5 + 6 = 15. That loop walked row 1.

To walk row r, hold r still and count c from 0 to cols - 1:

  1. Start a total at 0.
  2. Find the position. It is r*cols + c for the current c.
  3. Add that box to the total. Then move to the next c.

Because c goes up by 1 each turn, the position does too. A row is a run of boxes side by side. To walk a column you would hold c still and count r, and the position would jump by cols each turn. The matrix multiply in lesson 0.5 walks a row of one grid and a column of another.

Add up one row

Write row_sum. It takes a grid stored row after row in a flat list, the number of columns cols and a row number r, and returns the total of that row. For the grid 1 2 3 4 5 6 with 3 columns, row 1 adds up to 15.

One buffer, more than one shape

The buffer never says how many rows it has. It is 12 numbers in a row. The shape is a choice you make when you read it, and you can make a different choice for the same 12 numbers.

Click a cell, then switch the shape. The dark box in the buffer stays where it is. Only its row and column change.

Reshape the contiguous (3, 4) buffer to (2, 6). Which flat index holds [1, 0]?

[1, 0] means row 1, column 0. Contiguous means the 12 numbers sit side by side. The new grid has 6 columns.

1*6 + 0 = 6. No number moved. The same box was row 1, column 2 when the shape was (3, 4).

Reading the same numbers with a new shape is called a reshape. It costs nothing, because it only changes the rule. Week 5 adds it to your compiler along with permute, pad and broadcasting, starting at lesson 5.1. For week 3 the rule is enough.

From a position back to a row and column, for when you need the trip back

Divide and take the remainder. In a grid with cols columns, position p is row p div cols, column p mod cols. Position 9 with 4 columns is row 9 div 4 = 2, column 9 mod 4 = 1. Lesson 5.1 does this for any rank.

Strides, offsets and six views of one buffer: the general rule, for week 5 and the drills below

One row of memory

A tensor is an array with any number of dimensions, also called axes. A single number has 0 axes, a vector has 1, a matrix has 2, and a stack of matrices has 3.

Lesson 0.1 showed that memory is a long array of bytes. A 3 by 4 matrix of floats is 12 floats stored back to back. Nothing in memory says "3 rows". The grid is a story we tell about the buffer.

The story has three parts:

  • shape: how many positions each axis has, like (3, 4). "3 rows, 4 columns."
  • strides: how far to move in the buffer when one index goes up by 1. For (3, 4) stored row by row, they're (4, 1). Moving down a row skips 4 cells, and moving right a column skips 1.
  • offset: where element [0, 0] lives. Usually 0.

To find a position, multiply each index by its stride and add them up:

flat = offset + i * stride[0] + j * stride[1]

With strides (cols, 1) and offset 0 this is r*cols + c. Every view below just changes the shape, strides or offset. The buffer never changes.

Strides here count elements, not bytes, so lesson 0.2's "C * 4 bytes" is a stride of C here. (NumPy counts strides in bytes, but PyTorch and this course count elements.)

Notation: (4,) is a shape with one axis of size 4 (the comma makes it a tuple of one number). "Contiguous" means stored back to back with no gaps. You'll also see ndim, the number of axes (the rank), and numel, the total number of elements.

Row-major

"Row-major" (C order) means the last axis is contiguous: its stride is 1. Each earlier stride is the product of all the sizes after it. For shape (2, 3, 4) the strides are (12, 4, 1).

Reshape: new shape, same buffer

Reshaping (3, 4) to (2, 6) or (4, 3) just recomputes row-major strides for the new shape. The read order is still 0, 1, 2, ... 11, so no data moves. This works because the buffer is contiguous. Reshaping a view that has already been permuted can't always be written as new strides. Week 5 handles that case with index math (division and remainder) instead of strides, so it still needs no copy.

Permute: swap the strides

A transpose of (3, 4) is shape (4, 3) with strides (1, 4). Same buffer, swapped strides. It's free to create, but reading it row by row now jumps 4 cells at a time. Lesson 0.2 showed why that's slow: every jump can land on a different cache line.

Broadcast: stride 0

Adding a 4-element vector to every row of a 3 by 4 matrix needs the vector to "look like" 3 by 4. Give the row axis stride 0. Moving down a row then moves 0 cells, so every row reads the same 4 numbers. No copy happens.

Shrink and pad: index ranges and a mask

Shrink takes a window. The middle 2 by 2 of our matrix, written [1:3, 1:3] (rows 1 to 2 and columns 1 to 2, because the end of a range is excluded), starts at offset 5, because element [1, 1] is at 1·4 + 1 = 5. It keeps the same strides (4, 1). Only the offset and shape change.

Pad goes the other way and adds positions that have no memory behind them. A pad of 1 on each side of the columns turns (3, 4) into (3, 6). A logical column j is valid only when 1 ≤ j < 5. Valid positions read buffer column j - 1. Invalid ones don't touch memory at all and produce 0. That "is this index valid" check is a mask. It's also why the course proves every load is in bounds: a padded index that skipped its mask would read someone else's memory.

A view is not data

Writing to a broadcast view would mean three logical cells sharing one memory cell. Compilers either forbid it or copy first (materialize). Week 4 is largely about deciding when to copy.

Where this goes

Your compiler gets shrink in week 2, and reshape, permute and pad in week 5. Like the views on this page, they move no data. They stay index math until a loop reads through them. The step that does this is called rangeify: in week 4 it turns shapes into loops, and in week 5 it turns each movement op into the index math inside each memory read.

Optional drills for week 5

These three drills are in C and use strides, offsets and padding. Open the toggle just above this section first. They do not count toward finishing the lesson.

Row-major strides

Write row_major_stride(ndim, shape, d): the stride of axis d in a contiguous row-major buffer of that shape. It's the product of every size after axis d, and the last axis is always 1.

Read through a pad

A row of n real values is padded with left zeros in front and any number of zeros after. Write padded_get(row, n, left, j), which returns logical element j of the padded view: row[j - left] when that is a real element, and 0 for every other j, including negative j and j past the end.

The starter forgets the mask. The tests put other numbers right next to the row, so reading outside it shows up as a wrong answer, which is exactly the bug a missing mask causes in a real kernel.

Where does logical element k live?

A view is shape, strides and offset over a buffer. Number its logical positions 0 .. numel-1 in row-major order. Write view_at(ndim, shape, strides, offset, k), which returns the buffer index that position k reads.

Turn k back into one index per axis (the last axis changes fastest), then apply flat = offset + Σ index[d] * strides[d]. For shape (3, 4) and k = 5: the last index is 5 % 4 = 1, then 5 / 4 = 1 is the row index, so the position is [1, 1]. It has to work for every view in the toggle: reshape, permute, broadcast (stride 0) and shrink (an offset).

With ndim = 0 there is one element, and it lives at offset.
