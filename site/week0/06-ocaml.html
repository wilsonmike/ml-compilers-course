Values and functions

let binds a name to a value. Names never change. Functions are values too, and you call them without parentheses or commas.

let tax_rate = 0.08
let with_tax price = price *. (1.0 +. tax_rate)    (* float ops end in a dot *)
let rec factorial n = if n <= 1 then 1 else n * factorial (n - 1)

let () = Printf.printf "%.2f %d\n" (with_tax 10.0) (factorial 5)   (* 10.80 120 *)

Integers use + - * / and floats use +. -. *. /.. There's no automatic conversion. 1 + 1.0 is a type error, and you write float_of_int 1 +. 1.0. Recursive functions need let rec. let () = ... is how you write "run this when the program starts".

Syntax you'll see in every starter

Each line below runs. Paste them into utop and check: area is 12, double 5 is 10, first pair is 1, show (safe_div 7 2) is "3", show (safe_div 1 0) is "none", add 2 3 is 5, greeting is "hello, world", and c1 and c2 are 1 and 2.

let area = let w = 3 in let h = 4 in w * h       (* let ... in: a name used only in what follows *)
let double = fun x -> 2 * x                       (* fun: a function with no name *)
let pair : int * string = (1, "one")              (* a tuple; its type is written with * *)
let first (a, _) = a                              (* taking a tuple apart *)
let safe_div a b = if b = 0 then None else Some (a / b)   (* type: int -> int -> int option *)
let show o = match o with Some v -> string_of_int v | None -> "none"
let counter = ref 0
let () = counter := !counter + 1                  (* := sets a ref, ! reads it *)
let add (x : int) (y : int) : int = x + y         (* optional type annotations *)
let greeting = "hello, " ^ "world"                (* ^ joins strings *)
let make_counter () = let n = ref 0 in fun () -> incr n; !n   (* returns a function *)
let next = make_counter ()
let c1 = next ()
let c2 = next ()

An option is either Some value or None: OCaml's way of saying "maybe a result". A type like card list -> int reads "a function from a list of cards to an int". The last three lines show a function that returns a function: each call to make_counter () makes its own private n.

Variants and pattern matching

This is the feature you're choosing OCaml for. A variant type lists every shape a value can have, and each shape can carry data. match takes a value apart by its shape.

type suit = Hearts | Diamonds | Clubs | Spades
type card =
  | Number of int * suit        (* 2 through 10 *)
  | Jack of suit | Queen of suit | King of suit
  | Ace of suit

let points card =
  match card with
  | Number (n, _) -> n
  | Jack _ | Queen _ | King _ -> 10
  | Ace _ -> 11

let suit_of = function            (* "function" is shorthand for fun x -> match x with *)
  | Number (_, s) | Jack s | Queen s | King s | Ace s -> s

let is_red c = match suit_of c with Hearts | Diamonds -> true | Clubs | Spades -> false

(* guards with "when", and nested patterns *)
let describe = function
  | Number (n, Hearts) when n >= 9 -> "a high heart"
  | Ace Spades -> "the ace of spades"
  | _ -> "some card"

Each | line in the type is a constructor. Number of int * suit means the Number constructor carries a pair: an int and a suit (here * means "and", not multiplication).

The compiler checks that every match covers every case. Add a Joker constructor and every match that forgot about it gets a warning that points at the line. As your types grow over the semester, this is what keeps old code honest.

The catch-all hides new cases

A final | _ -> ... case matches everything, including constructors you add next month, so the exhaustiveness check can't help you there anymore. Use _ on purpose, not by habit.

Records, mutation, exceptions

A record is a struct with named fields. Fields are immutable unless you mark them mutable. An exception can carry data and is caught with try ... with, which pattern matches just like match.

type account = { owner : string; mutable balance : int }
exception Insufficient_funds of int

let withdraw acct amount =
  if amount > acct.balance then raise (Insufficient_funds (amount - acct.balance));
  acct.balance <- acct.balance - amount

let () =
  let a = { owner = "Sam"; balance = 100 } in
  withdraw a 30;
  (try withdraw a 500 with Insufficient_funds short -> Printf.printf "short by %d\n" short);
  Printf.printf "%s has %d\n" a.owner a.balance

; sequences two expressions and <- assigns a mutable field. A single mutable variable is a ref: let count = ref 0 in incr count; !count. Prefer immutable data, and reach for mutation when it actually makes the code simpler.

Lists and arrays

Lists are immutable and singly linked, written [a; b; c] (semicolons, not commas). Arrays are fixed size, mutable, and indexed with a.(i).

type task = { title : string; finished : bool }    (* "done" is a keyword *)
let todos = [ { title = "buy milk"; finished = true };
              { title = "call the bank"; finished = false };
              { title = "water plants"; finished = false } ]

let left = todos |> List.filter (fun t -> not t.finished) |> List.map (fun t -> t.title)
let n_done = List.fold_left (fun acc t -> if t.finished then acc + 1 else acc) 0 todos

let rec total = function [] -> 0 | x :: rest -> x + total rest    (* matching on a list *)

let scores = Array.make 5 0
let () = scores.(2) <- 7; Printf.printf "%d %d\n" (Array.length scores) scores.(2)   (* 5 7 *)

|> pipes a value into a function: x |> f |> g is g (f x). x :: rest is the pattern for "first element, then the rest".

A recursive type: a tree of words

Variants can refer to themselves. Here's a binary search tree of strings. Smaller words go left, bigger ones go right, and you never change a tree. insert builds a new one that shares the untouched branches with the old one.

type tree = Leaf | Node of tree * string * tree

let rec insert w t =
  match t with
  | Leaf -> Node (Leaf, w, Leaf)
  | Node (l, x, r) ->
    if w < x then Node (insert w l, x, r)
    else if w > x then Node (l, x, insert w r)
    else t                                       (* already there *)

let rec to_list = function Leaf -> [] | Node (l, x, r) -> to_list l @ [x] @ to_list r

let t = List.fold_left (fun t w -> insert w t) Leaf ["pear"; "apple"; "zebra"; "mango"; "kiwi"]

Hashtbl and equality

Hashtbl is a mutable hash table. It uses structural hashing and equality by default, so it works with any key type.

let counts : (string, int) Hashtbl.t = Hashtbl.create 64

let see word =
  let n = Option.value ~default:0 (Hashtbl.find_opt counts word) in
  Hashtbl.replace counts word (n + 1)

let () =
  List.iter see ["kiwi"; "pear"; "kiwi"];
  Hashtbl.iter (fun w n -> Printf.printf "%s: %d\n" w n) counts   (* order is not guaranteed *)

~default:0 is a labeled argument: you pass it by name. Hashtbl.find_opt returns an option, and Option.value ~default:0 turns None into 0.

OCaml has two equalities. a = b is structural: it walks both values and compares everything inside, which can take as long as the values are big. a == b is physical: it asks whether they're the very same object in memory, which is one pointer comparison. Remember this distinction. It matters in week 1.

Modules

A module groups related types and functions. Each file is one module, and you can nest more with module Name = struct ... end. A .mli file next to a .ml file lists what the module exposes. Anything not listed is private.

module Deck = struct
  let suits = [Hearts; Diamonds; Clubs; Spades]
  let full = List.concat_map
      (fun s -> List.init 9 (fun i -> Number (i + 2, s)) @ [Jack s; Queen s; King s; Ace s]) suits
end

let () = Printf.printf "%d cards\n" (List.length Deck.full)   (* 52 cards *)

Reading files and arguments, exit codes, and why a crash is not an answer: for the lab

This program belongs to the scratch project words from the dune toggle above. Run it as dune exec words -- count notes.txt.

let () =
  match Sys.argv with
  | [| _; "count"; path |] ->
    let lines = In_channel.with_open_text path In_channel.input_lines in
    Printf.printf "%d lines\n" (List.length lines);
    exit 0
  | _ ->
    prerr_endline "usage: words count FILE";     (* stderr *)
    exit 2

Sys.argv.(0) is the program name. exit n ends the program with status n, the usual way for a command to say it failed. For run tests, the course's grader looks only at the outcome line you print (for simplify and render later, it also checks exit status 0 or 2). [| _; "count"; path |] matches an array of exactly three elements. prerr_endline prints a line to stderr, and Printf.eprintf prints formatted text to stderr. In_channel.input_lines needs OCaml 5.1 or newer, which any fresh install has. (Splitting the whole text on '\n' instead overcounts by one when the file ends with a newline.)

The test runner, tools/test.py, runs your compiler as COMPILER FILE from the course repo's folder and reads the one line it prints: MATCH FILE, MISMATCH FILE, REJECTED FILE or OVERBUDGET FILE, with the path exactly as it was given. Build with dune build and point the grader at the binary itself, not at dune exec, because the grader runs tests in parallel and parallel dune exec runs fight over dune's lock. Run it from the course repo and give the full path to your binary. On WSL, use python3 and a path like ~/my-ml-compiler/_build/default/bin/main.exe:

An uncaught exception is not a diagnosis

An uncaught OCaml exception prints Fatal error: exception ... to stderr and prints nothing on stdout, so the grader gets no outcome line and the test fails, even one that expected REJECTED. When your compiler rejects a program, raise your own exception, catch it in the main function and print REJECTED and the file name. Let anything else crash loudly while you're developing, so you see it.

An int does not wrap at 32 bits

Now the three traps. Each one starts with a guess.

In OCaml, what is 2147483647 + 1?

An OCaml int has more than 32 bits.

2147483648. On a 64-bit machine an OCaml int has 63 bits, so this sum fits with room to spare.

One of the 64 bits is used inside OCaml to tell integers from pointers. That leaves 63, and the largest int, max_int, is 262 − 1. The i32 in the language you compile must wrap at 32 bits, so a plain + in your interpreter gives wrong answers for large numbers. The Int32 module has true 32-bit integers. Its literals end in l.

let a = Int32.of_int 2147483647
let b = Int32.add a 1l
let c = Int32.to_int b
  1. Move in. Int32.of_int turns an int into an int32. It keeps the low 32 bits.
  2. Compute. Int32.add adds and wraps at 32 bits. b is -2147483648l.
  3. Move out. Int32.to_int turns it back into an int. c is -2147483648.

An add that wraps at 32 bits

add32 a b should add two i32 values held in plain ints and wrap the way .uir does. The starter uses +, so it is wrong when the sum does not fit. Repair it with the three moves above.

Wrap a native int to 32 bits

Now from an empty function. Write wrap32 x: the signed 32-bit value with the same low 32 bits as x. With it you can keep using plain ints and wrap after every operation.

Two roads: the Int32 module, or bit operations. x land 0xFFFFFFFF keeps the low 32 bits, and lsl and asr shift left and right, copying the sign bit.

The other Int32 operations and their edge cases, for when you write the interpreter

OCaml's plain int is 63 bits on a 64-bit machine. So max_int is 262 − 1 = 4,611,686,018,427,387,903, and 2147483647 + 1 is just 2147483648. It does not wrap at 32 bits.

let a = Int32.max_int                 (* 2147483647l *)
let b = Int32.add a 1l                (* -2147483648l: wrapped *)
let c = 2147483647 + 1                (* 2147483648: a plain int did not *)
let () = Printf.printf "%ld %ld %d\n" a b c

(* the other Int32 operations you'll want: *)
(* Int32.mul  Int32.div  Int32.rem  Int32.logxor  Int32.shift_left
   Int32.compare  Int32.of_int  Int32.to_int  Int32.to_float  Int32.of_float *)

Int32.div and Int32.rem truncate toward zero, like C, and raise Division_by_zero on zero. That's a trap here: the course's div and mod round down (floor), and they give an answer for a zero divisor instead of failing. Int32.of_int keeps the low 32 bits. Int32.of_float truncates, and its result is unspecified for NaN or anything out of range, so check those cases yourself when floats arrive in week 2. Read the docs for each function before you use it. The exact edge-case behavior is what the tests check.

You can also keep using plain int and normalize to 32 bits after every operation. Either way works. Pick one and be consistent.

Two kinds of equal

Two strings are built the same way. What are a = b and a == b?

let a = "ad" ^ "d"
let b = "ad" ^ "d"

Each ^ makes a new string. One of the two operators asks whether both names point at the very same string.

true and false. Both hold the letters add, so = says true. They are two separate strings in memory, so == says false.

You met both in O.5. Their usual names are structural equality for =, which compares what is inside, and physical equality for ==, which asks whether the two are the very same object in memory. If you come from C or Python, your fingers will type ==. In OCaml that is almost never the one you want.

  1. Read a word. Your compiler cuts add out of a line of a file. That is a new string.
  2. Compare it. word == "add" is false, since the two are different objects. word = "add" is true.

Use = and its opposite <> unless you mean "same object". Week 1 does mean it once, on purpose: when equal nodes are always one shared object, as in the last exercise of O.5, == is the fast and correct test.

Is this word an op?

known_op name should say whether name is one of the ops in the list. It answers false for every word cut from a line of text. Find the one character that is wrong and repair it.

How fast each equality is, and what Hashtbl.hash looks at

= walks both values and compares everything inside, which can take as long as the values are big. == is one pointer comparison. Hash tables use structural hashing and structural equality by default.

Hashtbl.hash doesn't look at everything

The default hash only looks at a limited number of nodes inside a value, about ten meaningful ones. Two big values that differ deep inside can hash the same, and they're still told apart correctly by =, just slowly. If you ever key a table on large nested values, think about what you're actually hashing.

A match that hides a missing case

This code builds with no warning. Then you add | Div to the type and rebuild. What happens?

type op = Add | Mul | Max

let name op =
  match op with
  | Add -> "add"
  | Mul -> "mul"
  | _ -> "max"

What does the last case, _, match?

_ matches anything, including a constructor added later. So the build stays quiet and Div is called "max". That is a wrong answer with no message.

In O.4 you saw the compiler check that every match is exhaustive, with a case for every constructor of its type. Leave one out and you get a warning that names it. dune turns that warning into an error, so the build stops. As your node type grows week by week, this check finds every function you forgot to update.

A catch-all case, _, switches the check off for that match. So write one case per constructor wherever a new constructor would need its own answer. Use _ on purpose, not by habit.

Take out the catch-all

points was written when a deck had only number cards and face cards. Since then Ace (worth 11) and Joker (worth 0) joined the type, and no warning appeared. Replace the _ case so every constructor is named. A number card is worth its number and a face card is worth 10.

Blackjack hand value

Now a whole function. With the card type in the starter, write hand_value : card list -> int. Numbers are worth their number, faces 10, and an Ace 11. But while the total is over 21, an Ace may count as 1 instead, one Ace at a time.

Pattern match for the points, then add them up with List.fold_left (O.3). Keep the types in the starter exactly as they are: the tests build cards with those constructors.

Division and floats, the course's way

Two more places where OCaml's numbers and the course's numbers disagree. Both are optional drills, and both come back in week 1 and week 2.

Division. OCaml's / rounds toward zero, as C does: -7 / 2 is -3. Dividing by 0 raises Division_by_zero. The course's div rounds down, so div -7 2 is -4, and it gives -1 for a zero divisor instead of failing.

The course's 32-bit division

Write div32 a b for i32 values held in plain ints, the way .uir's div works: the floor quotient, wrapped to 32 bits, and -1 when b = 0. div32 (-7) 2 is -4. (Lesson 1.2 has a variant that returns mod too.)

OCaml's / truncates toward zero, like C, so the starter is wrong for negative quotients that aren't exact, and it raises on 0. Exactly one i32 quotient doesn't fit in 32 bits. Which one?

Floats. OCaml's float is a 64-bit double. The course's f32, which arrives in week 2, is single precision. To round a double to the nearest single, convert it to the 32-bit encoding and back:

let to_f32 x = Int32.float_of_bits (Int32.bits_of_float x)

to_f32 0.1 is 0.10000000149011612, the single nearest to 0.1. Comparisons on floats follow the IEEE rules: nan = nan is false. Test for NaN with Float.is_nan.

Is it already an f32?

Write is_f32 : float -> bool: true when the double x is exactly representable in single precision. NaN and the infinities count as representable.

Round it with the trick above and compare. Then check what your answer says about nan.

What the two conversion functions do, with the printed digits 
let to_f32 x = Int32.float_of_bits (Int32.bits_of_float x)
let () = Printf.printf "%.17g\n%.17g\n" 0.1 (to_f32 0.1)
(* 0.10000000000000001
   0.10000000149011612 *)

Int32.bits_of_float rounds to single precision and gives you its 32 bits. Int32.float_of_bits reads them back as a double holding that exact single value. H.4 Numbers that behave like C goes through wrapping, flooring and float bits slowly.

The k most common words

Write top_words : int -> string list -> (string * int) list. Count every word, then return the k most frequent as (word, count) pairs: higher counts first, and ties broken alphabetically (plain compare on strings, so "A" sorts before "a"). If there are fewer than k distinct words, return them all.

Tools: Hashtbl to count, Hashtbl.fold to get a list out, List.sort with your own comparison and List.filteri to take a prefix.

Toposort a tiny DAG, in OCaml

This is lesson 0.3's toposort, now in your own language. A graph is a list of records { name : string; srcs : string list }, each name appearing once. Write topo graph root: every name reachable from root, each exactly once, in depth-first post-order. Visit a node's srcs left to right, then emit the node itself.

For (a + b) * (a + b) that's ["a"; "b"; "add"; "mul"]. Nodes not reachable from root are left out. One hidden test is a doubling DAG (x0 to x30), so remember what you've visited.

OCaml hints

List.find (fun n -> n.name = x) graph looks a node up (it raises Not_found if nothing matches). A Hashtbl remembers what you've seen. Build the output in a ref list with out := x :: !out, then List.rev it at the end.

What does the last line print?

type account = { owner : string; mutable balance : int }
exception Insufficient_funds of int

  if amount > acct.balance then raise (Insufficient_funds (amount - acct.balance));
  acct.balance <- acct.balance - amount

let () =

= compares contents. == asks whether two values are the same object in memory.

Were the two lists built separately?

Same contents, so structurally equal. They're two separately built lists, so they aren't physically equal. If you had a way to guarantee that equal values are always the same object, == would be enough. Hold that thought until week 1.
