Week 6 · Lesson 4

Gradients through shapes

By the end of this lesson you can send a gradient backward through ops that change shape: sums, copies, pads, cuts and reorders. A model is mostly these ops, so the backward walk from lesson 6.3 has to get through all of them. One idea covers every case: each shape op has a partner that carries the gradient back to where the numbers came from.

Goal

Name the partner of reduce and of each movement op, and use them to get the gradient of a matmul with no matmul rule.

You'll use

The backward walk and its one rule per op (lesson 6.3). reshape and permute (lesson 5.2), pad, shrink and expand (lesson 5.3) and matmul built from them (lesson 5.4). The code exercises use lists (P.3O.3).

Warm up

Two questions from earlier lessons, from memory. Pulling an idea back out of your head is what makes it stay.

u = mul a b with a = 3 and b = 5 (lesson 6.3). Nudge a up by 1 and leave b alone. How much does u move?

Work out u before and after: 3 · 5, then 4 · 5.

From 15 to 20, so 5. That is the rule for mul: what a gets is what arrived, times b.

x has 3 elements. How many elements does pad %x [2 1] have (lesson 5.3)?

The list says how many zeros go on the left and how many on the right.

Six: two zeros, the three elements of x, then one zero.

Nudge one number in a sum

In lesson 6.3 the walk went backward one op at a time. Each op received g, which says how much the final answer y moves when that op's result moves by 1. The op then passed a share of it back to each input. Here is the simplest op that changes shape. x holds 2 5 7, and y adds them up to 14:

%y = reduce %x op=add

Guess first. Nudge the middle element from 5 to 6 and leave the other two alone. How much does y move?

Add up the new list: 2 + 6 + 7.

From 14 to 15, so 1. The 2 and the 7 give the same answer.

So the gradient of y with respect to x is 1 1 1. If the sum is not the last op and the g that arrives at it is 3, every element gets 3: 3 3 3. One number, repeated to fill a shape. You already own an op that does that.

The gradient of reduce op=add is an expand. Every input that was added gets a copy of g.

When the reduce folded the first axis of a grid, g has one axis less than the input. Say x has shape (2, 3), so reduce %x op=add pop=1 has shape (3,), and g is 10 20 30:

  1. Put the axis back. reshape g [1 3] gives one row.
  2. Fill the shape. expand to [2 3] repeats that row: 10 20 30, twice.

Nudge a number that was copied

Now go the other way. x is one number, 5. expand copies it three times, and each copy is multiplied by a different weight. w holds 1 2 3:

%c = expand %x [3]
%p = mul %c %w
%y = reduce %p op=add

c is 5 5 5, p is 5 10 15 and y is 30.

Guess first. Nudge x from 5 to 6. How much does y move?

All three copies become 6. Work out the new p and add it up.

p becomes 6 12 18 and y becomes 36, so y moved by 6. That is 1 + 2 + 3.

Each copy has its own gradient: 1, 2 and 3, by the rule for mul. x is behind all three, so x gets them added up.

The gradient of an expand is a reduce op=add over the axes that grew. Step through it on a grid.

reduce only folds leading axes, so your compiler first moves the grown axes to the front with a permute. The exact steps are in the reference at the end.

Every shape op has a partner

reduce turns many numbers into one, and its gradient is an expand. expand turns one number into many, and its gradient is a reduce. Each is the other's partner.

Every movement op has a partner, for one reason: a movement op computes nothing. Each output element is one input element, moved. So the gradient only has to travel back to the place each number came from, and the partner is the op that makes that trip. Guess the four missing partners now.

Start with pad. x is 4 5 6, so pad %x [2 1] is 0 0 4 5 6 0. The g that arrives at the padded value is 10 20 30 40 50 60.

What is the gradient for x?

At which positions of the padded value do 4, 5 and 6 sit?

Positions 2, 3 and 4, so x gets what arrived there. The other three numbers arrived at zeros that the pad made up. Nothing is behind them, so they are dropped.

Cutting three elements out, starting at position 2, is shrink g 2 [3]. The partner of pad is shrink.

It works in reverse too. shrink %x 2 [3] keeps positions 2, 3 and 4 of a 6-element x. If 7 8 9 arrives, the gradient for x is 0 0 7 8 9 0, which is pad g [2 1]. Nudge an element outside the window and y does not move, so those get 0. The partner of shrink is pad.

Send a gradient back through pad and shrink

shrink_offsets takes a pad list such as [2 1] and returns the offsets of the shrink that undoes it. pad_widths takes a shrink's offsets, its sizes and the sizes of the value it cut from, and returns the pad list that undoes it. One of the two gives wrong answers. Repair it.

Permute and reshape go back the way they came

permute reorders axes. x has shape (2, 3, 4), so permute %x [1 2 0] has shape (3, 4, 2): its axis 0 is x's axis 1, and so on. g arrives with shape (3, 4, 2).

Which permute of g has x's shape, (2, 3, 4), again?

The size 2 has to come first. Which axis of g has size 2?

Axis 2 of g has size 2, axis 0 has size 3 and axis 1 has size 4, so the order is [2 0 1]. The same order again would give (4, 2, 3).

The partner of permute is a permute by the inverse order. The forward order p put x's axis p[k] at position k. The inverse sends position k back: inv[p[k]] = k. For p = [1 2 0]:

  1. Read p[0] = 1. So inv[1] = 0.
  2. Read p[1] = 2. So inv[2] = 1.
  3. Read p[2] = 0. So inv[0] = 2.
  4. Read off inv. [2 0 1].

reshape is the easy one. It keeps every number in the same row-major order and only changes the shape. The partner of reshape is a reshape of g back to the input's shape.

That fills in the table.

Undoing permute and expand

Write inverse_order, the order that undoes a permute, and summed_axes, the axes an expand grew (its gradient sums over them). An axis grew when its size was 1 before the expand and is larger after it.

Max sends everything to the winner

One more reduce shows up in models, and it does compute something. reduce %x op=max of 1 5 3 2 is 5.

Guess first. Nudge the 3 up to 4. How much does the max move?

What is the largest of 1 5 4 2?

It is still 5, so it moved by 0. Only the largest element can move the max.

So reduce op=max sends all of g to the position that holds the max and 0 to the rest. Here that is 0 g 0 0. When several positions tie for the max, they split g evenly, the same way max a b splits a tie in half. For 4 9 9 9 with g = 6, each 9 gets 2.

reduce op=mul has no rule. A gradient whose path goes through one is invalid.

Matmul needs no rule

In lesson 5.4 you built a matrix multiply from reshape, permute, expand, one mul and one reduce. In lesson 6.2 matmul became sugar for exactly those lines. Each of them now has a rule, so the backward walk needs no rule for matmul.

A is [[1 2] [3 4]], B is [[5 6] [7 8]], C = A @ B and L is the sum of all four elements of C.

Guess first. Nudge A[0][0] from 1 to 2. How much does L move?

A[0][0] is used twice: times B[0][0] in C[0][0], and times B[0][1] in C[0][1].

C[0][0] goes up by 5 and C[0][1] goes up by 6. L adds both, so it moves by 11.

The walk reaches the same number for A:

  1. The sum. L added every cell of C, so each cell of C gets 1.
  2. The reduce over k. Its partner expands those ones back into the cube with axes (k, m, n).
  3. The mul. A's side gets what arrived times B's side. Cell (k, m, n) now holds B[k][n].
  4. A's expand. A[m][k] was copied along n, so its partner sums over n: B[k][0] + B[k][1].
  5. A's permute and reshape. Their partners put the result back in A's shape.

For A[0][0] the sum in step 4 is 5 + 6 = 11, the number you found by nudging.

The gradient of a matmul

Slot 0 holds A (2x3) and slot 1 holds B (3x2). For L = the sum of every element of A @ B, store the gradient of L with respect to A into slot 2. The starter takes the gradient with respect to the wrong matrix. Repair it.

Check a gradient by nudging

A nudge is also how you test a gradient: change one input, run again and compare how far the answer moved with what gradient says. Do it for B, with the same A and B.

Nudge B[0][0] from 5 to 6. How much does L move?

B[0][0] is used in C[0][0], times A[0][0], and in C[1][0], times A[1][0].

C[0][0] goes up by 1 and C[1][0] goes up by 3, so L moves by 4.

The gradient for B, checked by a nudge

Slots 0 and 1 hold A and B, both 2x2. For L = the sum of every element of A @ B, store the gradient of L with respect to B into slot 2. The starter only loads the two grids, so the loss and the gradient are yours to write. In the first sample test, the first number stored should be the one you just found by nudging.

Every rule for movement ops, stack, index and stage, for when you write the gradient pass

The share an input element receives is the gradient of the output position it went to. g is the gradient of the op's result.

opits gradient, sent back to the operand
reshapereshape g back to the operand's shape. Row-major order doesn't change, so nothing else does either.
permute x ppermute g by the inverse order: inv[p[k]] = k
pad x [l0 r0 ...]shrink g l0 l1 ... with x's shape: the padding zeros were constants, so their gradient is dropped
shrink x o0 ...pad g [o0 (d0-o0-s0) ...], zeros around the window: elements outside it didn't affect y
stack a0 ... anindex g j to aj
index x jg padded back to x's shape, at position j
stage xstage g: the gradient of a staged value is staged too

Shrink and index need literal offsets for their gradients, because the pad that undoes them needs constant pad widths. A shrink at a computed offset is fine in a program, but you can't differentiate through it.

The exact ops for the gradients of expand and reduce, for when your shapes do not line up

expand: permute the grown axes to the front (in increasing order, the rest after), reduce op=add with pop= set to how many there were, then reshape to the operand's shape. When the operand was a scalar, reshape g to [n] and reduce.

reduce op=add pop=m: reshape g to put size-1 axes where the m popped axes were, [1 ... 1, rest], then expand to the operand's shape.

reduce op=max pop=m, in ops: compare every input to the result expanded back, cast the hits to 1.0, count them with a reduce, and multiply the hits by g / count. The spec's table has the exact lines. When several positions tie, the gradient is split evenly among them.

reduce op=mul has no rule. Its derivative is "the product of all the others", and the cheap way to compute that, u / x[i], divides by zero when an input is zero. It's not on any path the course needs, so the spec makes it invalid on a gradient path.

The matmul walk with every shape, and the two formulas textbooks give

Say A is M×K and B is K×N. For C = A @ B with G = ∂y/∂C:

  • The reduce over k reshapes G (M×N) to 1×M×N and expands it back along the k axis: K×M×N.
  • The mul sends A's copy G · B, and B's copy G · A, elementwise on the K×M×N block.
  • A's expand grew the N axis. Its gradient permutes N to the front (N×K×M), reduces it away (K×M) and reshapes to K×M×1. The permute's gradient gives M×K×1, and the reshape's gives M×K, A's shape.
  • B's expand grew the M axis: permute (M×K×N), reduce (K×N), reshape (K×1×N), and the reshape's gradient gives K×N, B's shape.

The result is ∂y/∂A = G Bᵀ and ∂y/∂B = Aᵀ G, the two matmuls every deep learning library hard-codes. Your compiler derives them.

Staging the backward pass, for when your MNIST kernel is slow

Week 4's fusion recomputes an unstaged value at every use. That's cheap for a forward pass, but a gradient graph reuses things a lot. Each element of the gradient with respect to a matmul's output is used once per input feature, 784 times for MNIST. Recomputing it at every use multiplies that work by 784. The spec's rule for stage helps: a staged value's gradient is staged too. Stage the logits of a layer, and their gradient is computed once into a buffer, exactly where the backward pass needs it.

Which parts must match the spec bit for bit

How you write a gradient's movement ops doesn't change any bits: they only move numbers. You can skip a reshape to the same shape, or merge two permutes. What has to match the spec exactly is the arithmetic: each share's ops, the order shares are added, and the fold order of the reduces in expand's gradient.

Check yourself

What is the gradient of permute x [2 0 1], given g?

inv[p[k]] = k.

p = [2 0 1]: inv[2] = 0, inv[0] = 1, inv[1] = 2, so [1 2 0]. Permuting by p and then by inv is the identity. A reshape would put the numbers back in the wrong places.

x has shape (3, 1) and is expanded to (3, 4). What shape does the gradient pass reduce, and over what?

Which axis grew?

Axis 1 grew from 1 to 4. Each of x's 3 values was copied 4 times, so each receives the sum of 4 shares. reduce pops leading axes, so the grown axis is permuted to the front first.

reduce [1 5 5 2] op=max is 5. With g = 1, what share does the element at index 1 get?

How many positions hold the max?

Two positions tie at 5, so each gets 1 / 2 = 0.5, and the others get 0.

The gradient of pad x [2 1] for a 3-element x?

Where in the 6-element output did x's elements go?

Positions 2, 3 and 4. The padded zeros (positions 0, 1 and 5) were constants, so their gradient is dropped.

L is the sum of every element of C = A @ B. What is the gradient of L with respect to A?

Nudge A[i][k]. Which elements of B is it multiplied by?

A[i][k] is multiplied by every element of row k of B, once each, and L adds all of those products. So its gradient is the sum of row k of B, the same for every row i. That is the exercise above. Textbooks write it as G Bᵀ with G all ones.
