Run your first program

Before you build a compiler, meet the tiny language it will read. In this step you read a program, guess what it does, run it and change it. You don't need to know any programming yet.

Goal

Read a three-line program in .uir, say what it computes, and write one of your own.

Guess first

Here is a whole program. Each line makes one value and gives it a name. Names start with %.

%a   = add 2 3
%out = mul %a 4

add 2 3 means 2 + 3. mul means multiply. The second line uses %a, the value the first line made.

What number does %out end up as? A guess is fine. You'll see the answer either way.

Work out the first line, then use its answer in the second.

The first line makes 5 and calls it %a. The second line multiplies %a by 4, so %out is 20.

Why such a small language?

A compiler is a program that reads another program and turns it into something a computer can run fast. Big languages are hard for a program to read. This one has a single shape for every line:

%name = op value value

That shape is simple enough that you can write a program that understands it in one sitting. You'll do that in the next step. By the end of the course, lines of this same shape describe code that runs on a graphics card.

See it as a picture

Every line is a box. An arrow goes from each value to the line that uses it. Press Next to run the program one line at a time. It asks you to guess each value before it shows you. Point at a line to see its box light up, or at a box to find its line.

Then press Edit, change a number or add a line such as %b = add %a %a, and watch the picture follow.

This picture is called a graph. Keep it in mind. Your compiler will store every program as a graph like this one, and most of the course is about changing that graph into a better one.

A program with an input

A program that always gives 20 isn't much use. This line makes an input, a number that is handed in when the program runs:

%x = param [] slot=0 dtype=i32 addrspace=ALU

It is long, and for now you can copy it as it is. Read it as "%x is a whole number someone gives me". Week 1 explains each word when you need it.

The exercises below run your program several times, with a different %x each time, and check %out.

Write one yourself

Make %out equal to x × x + 1. For an input of 3 the answer is 10. Use one line per step.

What you can do now

  • Read a .uir program: each line is a name, an op and its values.
  • Work out what a short program computes, one line at a time.
  • Use a name more than once, and build a result in small steps.
  • Say what a graph of a program shows: a box per line and an arrow from each value to its user.

Check yourself

What is %out?

%a   = mul 3 4
%b   = add %a 1
%out = add %b 1

Go one line at a time and write down each value.

%a is 12, %b is 13 and %out is 14.

What is wrong with this program?

%out = add %a 1
%a   = mul 2 2

A line can only use values from lines above it.

Lines run from top to bottom, so a name has to be made before it is used. Swap the two lines and the program works.

What does the long param line give you?

Think about what changed between the runs of your exercise programs.

A param is an input. The same program can run many times with different values for it.
