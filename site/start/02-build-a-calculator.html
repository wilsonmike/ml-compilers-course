Lines run top to bottom, so a value has to exist before a later line can use it.

Part 1: one op

Start with the smallest job. Given the name of an op and two numbers, return the answer. Here it is for add:

def apply(op, a, b):
    if op == "add":
        return a + b
let apply op a b =
  match op with
  | "add" -> a + b

Read it in two moves:

  1. Pick the op. Look at the op's name to decide what to do.
  2. Do the math. Turn the two numbers into one.

Every op you ever add to your compiler follows those two moves.

One op at a time

add is done. Fill in mul (multiply) and max (the larger of the two). Both branches return 0 right now.

Part 2: remembering names

A program has more than one line, and later lines use earlier answers. So the interpreter needs a place to keep each answer under its name. Call it env, short for environment.

Follow this program by hand. After each line, one more name is in env:

linewhat happensenv afterward
%a = add 2 32 and 3 are numbers. apply gives 5. Save it as a.a is 5
%out = mul %a 4Look up a and get 5. 4 is a number. apply gives 20. Save it as out.a is 5, out is 20

So each line takes three moves:

  1. Find the values. A number is used as it is. A name is looked up in env.
  2. Apply the op. Call the apply you just wrote.
  3. Save the answer. Store it in env under the line's name.

After the second line runs, what value does env hold for b?

%a = add 1 2
%b = add %a 4
%c = mul %b %b

Stop after line 2. Line 3 has not run yet.

Line 1 saves a as 3. Line 2 looks up a, adds 4, and saves b as 7.

This step is about running a program, not reading text, so the program arrives already split into pieces. Each line is a tuple (name, op, x, y). A number is an int and a name is a str, so %out = mul %a 4 is ('out', 'mul', 'a', 4).Each line is a tuple (name, op, x, y). Run a whole program

run returns the value of the last line. The loop and the lookup for x are written. Two places still say 0: find the value of y the same way, then compute the line's answer with apply.

What you just built

That loop is an interpreter. It is about ten lines long, and it runs every program from step 1. The compiler you build in week 1 does the same three moves. It also reads the text form, refuses programs with mistakes in them, and stores the program as a graph so it can improve it before running it.

What you can do now

  • Say what an interpreter is: a program that runs another program directly.
  • Write one branch per op that turns two numbers into one.
  • Keep each line's answer under its name, and look names up when later lines use them.

One weakness: your interpreter forgets each line once it has run it, so when two lines compute the same thing it does the work twice. Week 1 starts there.

Go deeper (optional)
