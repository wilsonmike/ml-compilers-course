Week 5 · Lesson 1

Any rank, flat memory

In week 4 you wrote programs on whole lists and your compiler turned them into loops. But an image is a grid, and a batch of images is a stack of grids. This week your language learns values with two, three or four dimensions. This lesson shows how such a value lives in the flat buffer you already have.

Goal

Say how many numbers a shape holds, and turn an index into a position in the flat buffer and back.

You'll use

The matrix index r*cols + c (lesson 3.3), whole-value load and store (4.1) and reduce (4.2). Shapes first showed up in lesson 0.4.

In the exercises: a loop over a list (P.2, P.3).

In the exercises: lists and let rec (O.3).

Warm up

Two questions from weeks 3 and 4, from memory. Pulling an idea back out of your head is what makes it stay.

A matrix with 4 columns is stored row after row in a flat buffer. Which position holds row 2, column 1?

r*cols + c. Rows and columns count from 0.

2*4 + 1 = 9. Skip two whole rows of 4, then step 1 box along.

%v is a week 4 value holding [1 2 3 4 5 6]. What is reduce %v op=add?

reduce folds a whole list into one number.

1 + 2 + 3 + 4 + 5 + 6 = 21. A week 4 reduce always eats the whole list.

A grid that week 4 cannot describe

Here are two grids of numbers. Each has 2 rows and 3 columns.

A = 1 2 3      B = 10 20 30
    4 5 6          40 50 60

You want two things: the grid A + B, and the total of each column of A, which is 5 7 9.

Week 4 can fake the first one. Store each grid as 6 numbers, row after row, and add the two lists. The numbers come out right, but the program never says that these are grids. The second job shows why that matters.

A is loaded as the week 4 list [1 2 3 4 5 6]. The only week 4 op that adds up a value is reduce. What does reduce op=add give you?

Does the list know where a row ends?

A week 4 value has one size, 6. Nothing in it says a row ends after 3 numbers, so reduce can only add everything.

Week 4 has no way to say "2 rows of 3". Week 5 adds it. A value can now have any number of dimensions, and four new ops rearrange such values: reshape, permute, pad and shrink. With them a matrix multiply or a convolution is a few lines, and by the end of the week your compiler turns all of it into loops. This lesson covers the base: what a shape is, and where each number sits in memory.

A shape is a list of sizes

A value is made of 2 grids. Each grid has 3 rows, and each row has 4 numbers. How many numbers is that?

Count one row, then one grid, then both grids.

2 * 3 * 4 = 24. You multiply the sizes.

You just read a shape. A shape is a list of sizes, one for each axis, which is a direction you can count along. The number of axes is the rank. Every size is at least 1.

To count the numbers in a shape, multiply its sizes. This page writes a shape as (2, 3, 4). Inside a .uir program you write it as [2 3 4]. A value with rank 2 or more is often called a tensor.

Count the numbers in a shape

Write size shape: how many numbers a value of that shape holds. The shape arrives as a list of sizes, so size [2; 3; 4] is 24. A scalar has the empty shape [] and holds one number.

Where one element sits in the buffer

Memory does not change this week. A buffer is still one flat row of boxes, so a (2, 3, 4) tensor is 24 numbers in a row. You name one element with an index, one number per axis: [1][2][3] is plane 1, row 2, column 3.

In week 3, row r, column c of a matrix sat at r*cols + c. Stretch that idea to three axes. In a (2, 3, 4) tensor, which position in the buffer holds [1][2][3]?

A whole plane is 12 numbers and a whole row is 4. How many planes, rows and boxes do you skip?

Skip 1 plane (12), then 2 rows (8), then 3 boxes: 12 + 8 + 3 = 23. That is the last box, because every part of the index is as large as it can be.

The layout is called row-major: the last axis changes fastest. Each axis has a stride, the number of boxes one step along that axis skips. A step skips everything to its right, so the stride is the product of the sizes to the right of the axis.

For [1][2][3] in shape (2, 3, 4):

  1. Find the strides. The last axis has stride 1. Axis 1 skips a row of 4. Axis 0 skips a plane of 3 * 4 = 12. The strides are (12, 4, 1).
  2. Multiply each index by its stride. 1*12, 2*4 and 3*1.
  3. Add them up. 12 + 8 + 3 = 23.

Week 3's r*cols + c is the same rule for a matrix, whose strides are (cols, 1).

The rule for any rank

Step through six elements. Guess each position before you press next.

The rule does not care how many axes there are. Start at the last axis with stride 1. Each time you move one axis left, multiply the stride by the size of the axis you just left. The function below does exactly that, with one mistake.

Repair: index to offset, any rank

offset shape index returns where an element sits in the flat buffer. offset [2; 3; 4] [1; 2; 3] should be 23. The helper go walks the axes from last to first and is nearly right, but the stride never grows, so it returns 6. Fix the one place that passes the next stride.

From a position back to an index

Your compiler also needs the trip back. When it changes a value's shape, it has a flat position and must find the index. That is called unflattening.

In a (2, 3, 4) tensor, which plane holds position 17?

A plane is 12 numbers. Plane 0 holds positions 0 to 11.

17 div 12 = 1, so plane 1. Position 17 is [1][1][1], because 12 + 4 + 1 = 17.

Each axis takes two moves. Divide by the axis's stride to throw away the axes to its right. Then take mod the axis's size to throw away the axes to its left. For position 23:

  1. Axis 0. 23 div 12 = 1. Nothing is to its left, so no mod is needed.
  2. Axis 1. 23 div 4 = 5, the row number counted across both planes. 5 mod 3 = 2.
  3. Axis 2. The stride is 1, so only the mod is left: 23 mod 4 = 3.

So position 23 is [1][2][3], as before. Positions are never negative, so div here is plain whole-number division. Lesson 5.5 builds this arithmetic for every reshape.

Unflatten a flat index

Write coord(f, d1, d2, axis) in C: for a row-major tensor of shape [d0 d1 d2], return the coordinate of flat index f along axis 0, 1 or 2. For [2 3 4], flat 23 is [1][2][3].

Load flat, then reshape

Buffers keep their week 2 shapes: a buffer of n numbers is (n,). So a grid is always made the same way. Load a list, then give it a shape with reshape. Here is A + B from the start of the lesson, written as grids:

%a  = buffer 6 dtype=i32 slot=0
%b  = buffer 6 dtype=i32 slot=1
%y  = buffer 6 dtype=i32 slot=2
%va = load %a
%ta = reshape %va [2 3]
%vb = load %b
%tb = reshape %vb [2 3]
%s  = add %ta %tb
%f  = reshape %s [6]
%st = store %y %f
%y1 = after %y %st
  1. Load. %va has shape (6,), as in week 4.
  2. Reshape. %ta has shape (2, 3): the same six numbers, read as 2 rows of 3.
  3. Compute. add works element by element on any rank. Both sides must have the same shape.
  4. Reshape back and store. store needs a value with the buffer's shape, so %f is (6,) again.

Both sides of a reshape are row-major, so it never moves a number. It only changes how you count them.

%va holds 6 numbers. What does reshape %va [4 2] do?

How many numbers does (4, 2) hold?

(4, 2) holds 8 numbers and %va has 6. A reshape must keep the element count, so the program is rejected.

Storing a matrix directly

store %y %m with %m of shape (3, 4) and %y a 12-element buffer is a type error (the oracle reports "the value must match the view's dtype and shape"). Reshape to [12] first. Params also keep their week 2 rule, rank 0 or 1, so param [2 3] slot=0 dtype=i32 addrspace=ALU is rejected. Shaped data comes from buffers.

Take axes off the front

Now the job week 4 could not do: the column totals of A. With %ta of shape (2, 3), reduce %ta op=add pop=1 adds row 0 and row 1 element by element. The result has shape (3,) and holds 5 7 9.

Two ops remove axes from the front of a shape. Take %t of shape (2, 3, 4):

  • index %t 1 picks plane 1 and drops axis 0: shape (3, 4). index %t 1 2 drops two axes, leaving row 2 of plane 1, shape (4,). index %t 1 2 3 is one scalar.
  • reduce %t op=add pop=m folds the first m axes away. pop=1 (the default) adds the two planes, giving (3, 4). pop=2 adds all six rows, giving (4,). If %t holds 0 to 23, element 0 of that is 0 + 4 + 8 + 12 + 16 + 20 = 60.
Only leading axes

index and reduce work on the front of the shape. To pick or sum along another axis, move it to the front first with permute (lesson 5.2). That's one rule to implement instead of one per axis.

Add the two planes

Slot 0 holds 24 i32s: a (2, 3, 4) tensor in row-major order. Store y[j][k] = x[0][j][k] + x[1][j][k], a (3, 4) result, into slot 1 as 12 numbers. The starter stores plane 0 only.

What you can do now

  • Read a shape as a list of sizes, and count its numbers by multiplying them.
  • Find an element's position in the flat buffer with row-major strides, and go back with div and mod.
  • Make a tensor with load and reshape, and reshape back to rank 1 before a store.
  • Remove leading axes with index and reduce pop=m.

Week 5's shape rules in full, for when you write the type checker
  • A shape is a tuple of positive ints of any length. () is a scalar.
  • Buffers, allocs and memory shrink views stay rank 0 or 1: a buffer is (n,), and a view is [k] or a single element. Params also stay rank 0 or 1.
  • Elementwise ALU ops, where, cast and assert take operands of one shared shape, of any rank.
  • reshape x [d0 d1 ...] takes any value. The element counts must match, and each element keeps its row-major position.
  • index x j0 ... j(m-1) needs rank at least m and i32 scalar indexes, each provably in range by week 1's rule. It drops m leading axes.
  • reduce x op=... pop=m takes op of add, mul or max, an i32 or f32 value of rank at least m, and m of at least 1 (default 1). It drops m leading axes.
  • When pop is more than 1, the fold visits the popped axes in row-major order, starting from the first element, exactly like week 4's left fold. The order matters for floats, where addition can round differently in a different order.

Check yourself

In a (2, 3, 4) tensor, what is the flat position of element [1][2][3]?

The strides are (12, 4, 1).

12·1 + 4·2 + 3 = 23, the last element. It's the last because every index is at its maximum.

%t has shape (2, 3, 4). What shape is reduce %t op=add pop=1?

Which end of the shape does pop take axes from?

pop=1 folds away the leading axis, so what's left is (3, 4): the two planes added together.

%t is (2, 3, 4) holding 0, 1, ..., 23 in row-major order. What is element 0 of reduce %t op=add pop=2?

The result has shape (4,). Element 0 sums column 0 of all six rows. Column 0 holds every fourth number.

Column 0 is 0, 4, 8, 12, 16, 20, and their sum is 60.

What shape is index %t 1 for %t of shape (2, 3, 4)? Answer like 3 4.

One index drops one leading axis.

It picks plane 1 and drops axis 0, leaving (3, 4).

%m has shape (3, 4) and %y is a 12-element buffer. How do you write %m into %y?

Memory stays rank 1. What does store require of its value's shape?

The value must match the view's shape, and buffers are rank 1. reshape %m [12] moves nothing, because both sides are row-major, and then one store writes all 12.
