Week 5 · Lesson 1

Any rank, flat memory

Until now every value was a scalar or a vector. From this week a value can have any number of axes: a matrix, a stack of matrices, a batch of images. Memory doesn't change at all. Buffers stay one long row of numbers, and the shape is just a way of reading that row.

A shape is a way of counting

A shape is a tuple of positive sizes. () is a scalar, (5,) a vector, (3, 4) a matrix with 3 rows of 4, and (2, 3, 4) two such matrices. The number of axes is the rank.

The elements are laid out in row-major order: the last axis changes fastest. That's the rule from lesson 0.4, and it gives each axis a stride, the distance in elements between neighbors along that axis. For (2, 3, 4) the strides are (12, 4, 1), so element [i][j][k] is number 12i + 4j + k in the flat row. Step through it:

Going the other way, from a flat position back to an index, is called unflattening. Divide by an axis's stride (div, integer division) to drop the axes to its right, then take mod its size to drop the axes to its left. For position 23 in (2, 3, 4): axis 0 is 23 div 12 = 1, axis 1 is (23 div 4) mod 3 = 5 mod 3 = 2, and axis 2 is 23 mod 4 = 3, so it's [1][2][3]. Lesson 5.5 builds exactly this arithmetic for every reshape.

Memory stays rank 1

Buffers, allocs and memory views keep their week 2 shapes: a buffer is (n,), a view is [k] or a single element. So a rank-3 value is always made the same way. Load a vector, then reshape it:

%x  = buffer 24 dtype=i32 slot=0
%v  = load %x                      # (24,)
%t  = reshape %v shape=[2 3 4]     # (2, 3, 4): same numbers, new shape

Storing goes the other way: store needs a value with the view's shape, so you reshape back to [24] first. Because the layout is row-major on both sides, neither reshape moves a single number.

Storing a matrix directly

store %y %m with %m of shape (3, 4) and %y a 12-element buffer is a type error (the oracle reports "the value must match the view's dtype and shape"). Reshape to [12] first. Params also keep their week 1 rule, so param 0 dtype=i32 shape=[2 3] is invalid. Shaped data comes from buffers.

Popping leading axes

Two ops take axes off the front of a shape.

  • index %t 1 picks plane 1 and drops axis 0: shape (3, 4). index %t 1 2 drops two axes, leaving row 2 of plane 1, shape (4,), and index %t 1 2 3 is one scalar.
  • reduce %t op=add pop=m folds the first m axes away. pop=1 (the default) adds the two planes, giving (3, 4). pop=2 adds all six rows, giving (4,).

When pop is more than 1, the fold visits the popped axes in row-major order, starting from the first element, exactly like week 4's left fold. For the tensor holding 0..23, reduce pop=2 at column 0 is 0 + 4 + 8 + 12 + 16 + 20 = 60.

Only leading axes

index and reduce work on the front of the shape. To pick or sum along another axis, move it to the front first with permute (lesson 5.2). That's one rule to implement instead of one per axis.

Add the two planes

Slot 0 holds 24 i32s: a (2, 3, 4) tensor in row-major order. Store y[j][k] = x[0][j][k] + x[1][j][k], a (3, 4) result, into slot 1 as 12 numbers. The starter stores plane 0 only.

Unflatten a flat index

Write coord(f, d1, d2, axis): for a row-major tensor of shape [d0 d1 d2], return the coordinate of flat index f along axis 0, 1 or 2. For [2 3 4], flat 23 is [1][2][3].
