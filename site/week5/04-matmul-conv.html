Week 5 · Lesson 4

Matmul and conv from movement

By the end of this lesson you can write a matrix multiply and a convolution with no loops at all: a few shape moves, one mul and one reduce. These two operations do almost all the work in a neural network. Once your compiler can express them this way, it can express a whole model.

Goal

Write a matrix multiply and a 1D convolution in .uir using only movement ops, one mul and one reduce.

You'll use

reshape and permute (lesson 5.2), pad, shrink, expand and stack (lesson 5.3) and reduce with pop (lesson 5.1). The loops you are replacing come from lesson 3.3 and lesson 3.4.

Warm up

Two questions from earlier lessons, from memory. Pulling an idea back out of your head is what makes it stay.

A = [[1 2] [3 4]] and B = [[5 6] [7 8]]. In C = A @ B (lesson 3.3), what is C[1][0]?

Row 1 of A is 3 4. Column 0 of B is 5 7. Multiply in pairs and add.

3·5 + 4·7 = 43. Every cell of C is one row of A paired with one column of B.

%c has shape (2, 1) and holds 5, then 7. What is element [1][2] of expand %c [2 3] (lesson 5.3)?

The size-1 axis is read at 0, whatever the output index is.

It reads c[1][0], which is 7. expand repeats a value along its size-1 axes.

The puzzle: a matrix multiply with no loops

In week 3 you wrote the matrix multiply as three loops. For each row m of A and each column n of B, a third loop walked k and added up products:

C[m][n] = A[m][0]·B[0][n] + A[m][1]·B[1][n] + ...

Here is a claim that should sound wrong. The same multiply can be written with no loops: a few shape moves, one mul and one reduce. The mul is the ordinary elementwise one. It multiplies two values of the same shape, cell by cell.

Guess first. A and B are both 2x2. Count every multiplication the three loops do to fill all of C. How many?

Each cell of C adds up two products. How many cells does C have?

Eight: four cells, two products each. One elementwise mul makes one product per cell, so it must run on values with eight cells.

That is the whole trick. A and B have four numbers each. If you can arrange each of them into a value with eight cells, so that every cell holds the right pair, one mul does all eight products at once. A shape with eight cells and three axes is (2, 2, 2): one axis each for k, m and n. Picture it as a small cube.

The eight products then have to be added in pairs, over k. That is a reduce, and reduce folds away the first axis. So k goes first, and the cube's axes are (k, m, n).

Line A and B up in a cube

Cell (k, m, n) of the cube must hold A[m][k] from A and B[k][n] from B. Step through the picture. The dark cells are the ones that feed C[1][0] from the warm up. Each caption ends with a guess to make before you press Next.

Here are the moves as a program. %A and %B are loaded values with 4 floats each.

%a3 = reshape %A [2 2 1]
%aT = permute %a3 [1 0 2]
%ax = expand %aT [2 2 2]
%b3 = reshape %B [2 1 2]
%bx = expand %b3 [2 2 2]
%p  = mul %ax %bx
  1. Give A a third axis. A has axes m and k and no n. reshape adds a size-1 axis at the end: (m, k, 1).
  2. Put k first. permute [1 0 2] swaps the first two axes: (k, m, 1).
  3. Do the same for B. B has k and n and no m. Its size-1 axis goes in the middle: (k, 1, n). Its k is already first.
  4. Fill the cube. expand repeats each one along its size-1 axis. Both are now (2, 2, 2).
  5. Multiply. Cell (k, m, n) of %p is A[m][k]·B[k][n].

Now B is 3x4, so k runs to 3 and n to 4. What shape do you reshape B to before the expand? Write the sizes separated by spaces.

The cube's axes are (k, m, n). B has no m, so that axis gets a 1.

[3 1 4]: k, then a size-1 axis where m goes, then n.

Sum away the k axis

%p holds all eight products. One more line finishes the job:

%C  = reduce %p op=add pop=1

pop=1 folds away one leading axis, which is k. For every (m, n) it adds the products in order k = 0, 1, the same order as the week 3 loop. What is left has axes (m, n), and that is C.

A cube %p has shape (3, 4, 5). What shape is reduce %p op=add pop=1?

The first axis is the one that gets folded.

(4, 5). The 3 products along k become one sum for each of the 20 cells.

Why write it this way

The cube is never stored. It is a description: cell (k, m, n) is one multiply of two loaded values. You say what C is, once, and choose no loop order. The compiler chooses. Rangeify, in the next lesson, turns these seven lines into two loops, one over the outputs and one over k, with the cube gone. Every model is then written one way, and making the loops fast is the compiler's job.

Line B up the right way

Slots 0 and 1 hold A and B, both 2x2. The program should store C = A @ B into slot 2. One shape is wrong, so B's numbers land in the wrong cells of the cube. Repair it.

Skip the permute and the answer is wrong

The permute looks like a detail. Take it out and reshape A straight to [2 2 1]. Every later line still passes its shape check.

Without the permute, what does the program compute?

The cube calls its first axis k. Which axis of A is first when nobody moves it?

A's first axis is its rows, m. The cube reads it as k, so row k of A gets used as column k. The shape is right and the numbers are wrong.

The syllabus stores A transposed

A matrix with its rows and columns swapped is called its transpose, written Aᵀ. The public syllabus writes its GEMM with no permute, reshaping slot 0 to [K M 1]. That is correct only if the buffer already holds A transposed. Hand that form an A stored the usual way, row by row, and it computes Aᵀ @ B without a word of complaint. No shape check can catch it. Test with a matrix that is not square, so a swapped axis changes the answer.

A matmul from movement ops

Slot 0 holds A, 2x3, stored row by row. Slot 1 holds B, 3x2, stored row by row. Store C = A @ B (2x2) into slot 2, using only load, movement ops, expand, one mul, one reduce and a store. No hand-written range. The starter is the syllabus form, which assumes A is stored transposed.

Write one yourself

Now from an empty program. A matrix times a vector is the same idea with one axis fewer:

y[m] = A[m][0]·v[0] + A[m][1]·v[1] + A[m][2]·v[2]

There is no n, so the lined-up value is a flat sheet with axes (k, m). Ask the same two questions as before. Which axis does each input lack? Is k first?

A matrix times a vector

Slot 0 holds A, 2x3, stored row by row. Slot 1 holds v, 3 floats. Store y = A @ v (2 floats) into slot 2. The starter loads both and stores zeros. Replace the %y line with shape moves, one mul and one reduce.

A convolution is shifted copies and a sum

The convolution from lesson 3.4 slides a window along x. With three kernel values, called taps:

y[i] = x[i-1]·w[0] + x[i]·w[1] + x[i+1]·w[2]

Past the ends, x counts as zero. In week 3 that took two loops and a mask. Here the plan is the matmul plan: get every product into one value, then sum one axis away. Start with %p = pad %x [1 1], which puts one zero on each side. For x = 1 2 3 4 5 that is 0 1 2 3 4 5 0.

Guess first. %p is 0 1 2 3 4 5 0. What is shrink %p 2 [5]?

A shrink at offset 2 starts at element 2 and takes 5 elements.

It is x moved one place left, with a zero filling the end. Element i is x[i+1], for every i at once.

So one shrink per tap gives the three shifted copies. stack them and the taps become a new first axis. With w = 1 0 -1:

rowholdsi=0i=1i=2i=3i=4times
shrink %p 0 [5]x[i-1]01234w[0] = 1
shrink %p 1 [5]x[i]12345w[1] = 0
shrink %p 2 [5]x[i+1]23450w[2] = -1
ythe column sums-2-2-2-2?

Read a column from top to bottom and you have the window for one output. Multiply each row by its tap and add down the column: y[0] = 0·1 + 1·0 + 2·(-1) = -2.

Fill in the last cell of the table. What is y[4]?

The last column reads 4, 5, 0. The taps are 1, 0, -1.

4·1 + 5·0 + 0·(-1) = 4. The padded zero did the job of week 3's mask.

Build the convolution

Here is the table as a program. %x has 5 floats and %w has 3.

%p   = pad %x [1 1]
%s0  = shrink %p 0 [5]
%s1  = shrink %p 1 [5]
%s2  = shrink %p 2 [5]
%win = stack %s0 %s1 %s2
%w2  = reshape %w [3 1]
%wx  = expand %w2 [3 5]
%pr  = mul %win %wx
%y   = reduce %pr op=add pop=1
  1. Pad. One zero on each side, so every window is full.
  2. Shift and stack. Three windows of 5 become %win, shape (3, 5): one row per tap, one column per output.
  3. Line up the kernel. w has a tap axis and no output axis. Reshape it to (3, 1) and expand to (3, 5).
  4. Multiply and sum. The tap axis is first, so reduce pop=1 folds it away. Shape (5,).

The tap axis plays the part k played in the matmul. First repair a convolution, then write one.

A same-size conv1d

Slot 0 holds x (6 f32), slot 1 holds w (3 f32). Store y[i] = x[i-1]·w[0] + x[i]·w[1] + x[i+1]·w[2] into slot 2 (6 f32), with x read as zero outside its 6 elements. The starter pads on the wrong side.

A two-tap convolution

Slot 0 holds x (5 f32), slot 1 holds w (2 f32). Store y[i] = x[i]·w[0] + x[i+1]·w[1] into slot 2 (4 f32). Every window fits inside x, so you need no pad. The starter stores zeros. Replace its %y line.

The general matmul for any M, K and N, for when you write a test of your own

When A arrives as M x K, row-major, add one permute to move k to the front. The reduce still folds the first axis, so whatever you want to sum over has to be first:

# %a, %b: loaded values (load the buffers first: memory can't be reshaped)
%a3 = reshape %a [M K 1]
%aT = permute %a3 [1 0 2]       # K M 1
%ax = expand %aT [K M N]
%b3 = reshape %b [K 1 N]
%bx = expand %b3 [K M N]
%p  = mul %ax %bx
%C  = reduce %p op=add pop=1          # M N

The cube is never stored. It's a description: element (k, m, n) of %p is one multiply of two loaded values. Lesson 5.5 shows how rangeify turns this description into loops, with the cube gone: one loop over the outputs, one over k.

The result has rank 2. Memory stays flat, so reshape it to [M*N] before the store.

The syllabus GEMM, 256x256 with A stored transposed, and a picture of its cube

The public syllabus opens with a .uir program that multiplies two 256x256 matrices. In our format, where broadcasts are written out with expand, it reads:

%a  = load %A                         # 65536 floats
%b  = load %B                         # 65536 floats
%a3 = reshape %a [256 256 1]    # axes: k, m, 1
%b3 = reshape %b [256 1 256]    # axes: k, 1, n
%ax = expand %a3 [256 256 256]
%bx = expand %b3 [256 256 256]
%p  = mul %ax %bx                     # p[k][m][n] = a[k][m] * b[k][n]
%c  = reduce %p op=add pop=1          # c[m][n] = sum over k, in order k = 0, 1, ...

Both inputs are lifted into a cube with axes (k, m, n). Each one is missing an axis, so expand repeats it along that axis: a is the same for every n, b the same for every m. The mul fills the cube with every product a[k][m] · b[k][n], and reduce pop=1 folds away the leading axis, k, leaving c[m][n]. Step through it on a 2x2 by 2x3 case.

reshape %a [K M 1] reads the buffer as K rows of M. For the product to be A @ B, row k of that buffer must hold column k of A: the buffer holds A transposed. Lesson 0.5 met the same fact from the other side. If your A arrives row-major as M x K, the syllabus form silently computes Aᵀ @ B instead, with the right shape and wrong values.

im2col: the usual name for the stack of shifted windows, and how it relates to lesson 3.4

A 1D convolution in the machine learning sense is a correlation: the kernel is not flipped. The stack of shifted windows is called the im2col view ("image to columns"): one row per kernel tap and one column per output, which is the transpose of the windows matrix in lesson 3.4. It turns the convolution into a multiply and a sum over taps, the same shape of computation as the matmul above. With x = 1..5 and w = [1 0 -1], the oracle gives y[0] = 0·1 + 1·0 + 2·(-1) = -2 and y[4] = 4·1 + 5·0 + 0·(-1) = 4.
