Reshape and permute

A buffer hands you numbers in one flat row. This lesson gives you two ops that rearrange them without doing any math. reshape reads the row as a grid, and permute swaps the grid's axes, for example rows with columns. The matrix multiply in lesson 5.4 needs both, and mixing them up is the most common shape bug there is.

Goal

Predict what reshape and permute do to a small grid of numbers, and use both in a program.

You'll use

Shapes, flat memory and row-major order from lesson 5.1, and load and store from lesson 2.2.

The two code exercises use lists and loops. If those are new, do P.3 first.

The two code exercises use lists and List.map. If those are new, do O.3 first.

Warm up

Two questions from lesson 5.1, from memory. Pulling an idea back out of your head is what makes it stay.

A value has shape (2, 3): 2 rows of 3. Its numbers sit in memory as one flat row, in row-major order, counted from 0. What position does element [1][2] have?

Every full row before it takes up 3 positions.

3·1 + 2 = 5. It is the last of the six numbers.

You walk along the flat row of a (2, 3) value, one number at a time. Which index changes at every step?

The walk goes [0][0], [0][1], [0][2], then [1][0].

In row-major order the last index changes fastest. Keep that in mind: permute is the op that changes which index is last.

Six numbers that should be a grid

This program loads six numbers from slot 0:

%x = buffer 6 dtype=i32 slot=0
%v = load %x

%v has shape (6,) and holds 10 20 30 40 50 60. You know these are really a grid with 2 rows of 3. Before you can ask for "row 1", %v has to become a grid. The op for that is reshape from lesson 5.1, which takes a value and the shape you want:

%m = reshape %v [2 3]

What is row 1 of %m?

Rows are 3 long. Deal the six numbers out in the order they sit in memory.

The first three numbers fill row 0 and the next three fill row 1. That is row-major order again.

reshape reads the numbers in row-major order and lays them out again, row-major, in the new shape. So the flat order never changes. %m is [[10 20 30] [40 50 60]], and this grid is the one we use for the rest of the lesson.

To find where a number lands, for example 40:

  1. Find its flat position. 40 is at position 3 of the row.
  2. Cut the row. [2 3] means rows of 3, so position 3 starts row 1. That is [1][0].
  3. Check with lesson 5.1's formula. 3·1 + 0 = 3.

Step through three shapes for the same six numbers. Watch the buffer under each one.

What reshape can and cannot do

reshape has one rule: the new shape must hold exactly as many numbers as the old one. The number of elements is the product of the sizes. Six numbers can be [2 3], [3 2], [6 1] or [6], and never [4 2].

It goes both ways. Memory stays flat, so before a store you reshape a grid back to one row, here with reshape %m [6]. Neither direction moves a number.

A value holds 12 numbers. Which reshape is rejected?

Multiply the sizes in each list.

5·3 = 15, and there are only 12 numbers. The other three all multiply to 12. A shape can have any number of axes.

Does the new shape fit?

Your compiler has to reject a bad reshape. count is written: it multiplies the sizes of a shape. can_reshape should say whether a value of shape old_shape can be reshaped to new_shape. Right now it compares how many axes the two shapes have, which is the wrong test. Fix it.

Swap rows and columns

Now you want the grid turned on its side, so that each column becomes a row:

[[10 20 30]          [[10 40]
 [40 50 60]]   to     [20 50]
                      [30 60]]

This is called a transpose. Matrix multiply needs one. The result has 3 rows of 2, shape (3, 2), and you already have an op that makes a (3, 2).

%m is the grid on the left. What is row 0 of reshape %m [3 2]?

Reshape never changes the flat order. Deal out 10 20 30 40 50 60 in rows of 2.

You get [[10 20] [30 40] [50 60]]. The shape is right and the numbers are in the wrong places. A reshape is not a transpose.

The op that does it is permute. It takes a value and a list that says, for each new axis, which old axis it is:

%t = permute %m [1 0]

Read [1 0] as "new axis 0 is old axis 1, and new axis 1 is old axis 0". Rows and columns trade places. The shape goes from (2, 3) to (3, 2), and element [i][j] of %t is %m[j][i].

What is %t[2][0]?

Swap the two indexes, then look in %m.

%t[2][0] is %m[0][2]: row 0, column 2 of the first grid, which is 30.

Reshape and permute side by side

Both ops can turn a (2, 3) into a (3, 2). Follow one number at a time through both. Under each grid is the order you get when you read it row by row.

What each op does to the flat order:

  • reshape keeps it. Read row by row, the result is still 10 20 30 40 50 60. Only the row length changed.
  • permute changes which index walks fastest. Read row by row, %t gives 10 40 20 50 30 60. That walk goes down the columns of %m, so the old row index is now the one that changes at every step.

Neither op copies data. The six numbers stay where they are in the buffer, and each op is only a new rule for where to look. In the reshape, element [i][j] is at position 2i + j. In the permute, element [i][j] is %m[j][i], at position 3j + i. Numbers are written in a new order only when a store puts the result in memory. Lesson 5.5 turns both rules into code.

With %t = permute %m [1 0], which position of the buffer does %t[2][1] read?

Use 3j + i with i = 2 and j = 1.

3·1 + 2 = 5, the last position, which holds 60. The first and last numbers stay put in a transpose. The ones between them move.

Fix a broken transpose

A whole program that transposes the grid takes three moves between the load and the store:

%x  = buffer 6 dtype=i32 slot=0
%y  = buffer 6 dtype=i32 slot=1
%v  = load %x
%m  = reshape %v [2 3]
%t  = permute %m [1 0]
%f  = reshape %t [6]
%s  = store %y %f
%y1 = after %y %s
  1. Make the grid. reshape %v [2 3] says the six numbers are 2 rows of 3.
  2. Swap the axes. permute %m [1 0] gives the (3, 2) transpose.
  3. Flatten for the store. reshape %t [6] reads the transpose row by row, so slot 1 gets 10 40 20 50 30 60.
A transpose is not a reshape

Reshaping a (3, 4) to (4, 3) gives the right shape with the wrong contents. The two agree only when a dimension is 1, or when the data happens to line up, for example when every value is the same. That's why a transpose test with constant data passes for a wrong answer. Test with distinct values everywhere.

Transpose a 3x4 matrix

Slot 0 holds a 3x4 f32 matrix, row-major. Store its 4x3 transpose into slot 1, row-major. The starter reshapes to [4 3], which is not a transpose.

More than two axes

Lesson 5.1's index and reduce only work on the leading axes. To sum along another axis, you first move it to the front, and permute does that for any rank. The list always means the same thing: new axis k is old axis p_k.

%x has shape (2, 3, 4). What shape is permute %x [1 2 0]?

New axis 0 is old axis 1. How long is old axis 1?

Look up each entry of the list in the old shape: axis 1 has size 3, axis 2 has size 4, axis 0 has size 2.

So the new shape is shape[p_k] for each k. Finding which element of %x an output element reads goes the other way: output index i_k belongs on old axis p_k. Take the order [2 0 1] and output element [1][0][2]:

  1. Pair each index with its axis. The order is 2 0 1 and the index is 1 0 2. So 1 goes to old axis 2, 0 goes to old axis 0 and 2 goes to old axis 1.
  2. Write them in old axis order. Axis 0 gets 0, axis 1 gets 2, axis 2 gets 1.
  3. Read. The output element is %x[0][2][1].

The order must be a permutation of 0..r-1 for a value of rank r: every axis number exactly once. permute %x [0 0] is rejected, because axis 1 would have nowhere to go.

A bigger example: 12 numbers, rank 3 and a scalar, for when you test your own reshape

reshape %x [d0 d1 ...] works for any rank. 12 numbers can become [3 4], [2 2 3] or [12 1]. The shape [] turns a one-element value into a scalar.

Nothing moves. If the buffer holds 0..11, the number 9 is the tenth element in every view, wherever the new shape puts its row and column. Step through it:

For a matrix there's one interesting order, [1 0]. For rank 3 there are six orders. With the order [2 0 1], a (2, 3, 4) tensor becomes (4, 2, 3).

How this compares to NumPy and PyTorch, if you know them

permute %m [1 0] is m.T or m.transpose(1, 0), and reshape is reshape. Those libraries also avoid copying where they can: a transpose there returns a view of the same memory with its strides swapped. This compiler gets the same effect another way. Lesson 5.5 rewrites every movement op into index arithmetic on the original buffer, so no loop exists only to move numbers around.

Check yourself

A buffer holds 0..11. After reshape [3 4], what is element [2][1]?

Rows of 4: row 2 starts at element 8.

4·2 + 1 = 9, and the buffer holds its own positions, so the value is 9.

Same buffer, reshaped to [3 4], then permute [1 0]. What is element [1][2] of the result?

The transpose's [i][j] is the original's [j][i].

It reads [2][1] of the 3x4, which is 9.

[[0 1 2] [3 4 5]] is transposed with permute [1 0] and flattened with reshape [6]. What is the second element of the result?

The transpose's first row is the original's first column.

The transpose is [[0 3] [1 4] [2 5]], which flattens to 0 3 1 4 2 5. The second element is 3.

What shape is permute %t [2 0 1] for %t of shape (2, 3, 4)?

Output axis k has the size of input axis p_k.

(shape[2], shape[0], shape[1]) = (4, 2, 3).

Is permute %m [0 0] valid for a (2, 3) %m?

Where would axis 1 go?

Every axis must appear exactly once. [0 0] drops axis 1 and repeats axis 0, so the oracle rejects it.

0..5 is reshaped to [3 2] and then back to [6]. What do you get?

Does reshape ever change the order of the elements?

Never. Both reshapes keep row-major order, so the round trip is the identity.
