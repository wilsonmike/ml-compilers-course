Pad, shrink, expand, stack

Four more ops that move numbers around without computing anything. You will grow a grid with a border of zeros, cut a piece out of it, repeat one row to fill a grid and join two rows into one grid. With these, lesson 5.2's two and index from lesson 5.1, your compiler can write down most of the data movement in a neural network.

Goal

Warm up

Two questions from earlier lessons, from memory. Pulling an idea back out of your head is what makes it stay.

A buffer %b holds 0 1 2 3 4 5 6 7. Which elements does the week 2 view shrink %b 2 [3] see?

The first number is where the window starts. The list is how many elements it holds.

The window starts at element 2 and is 3 long, so it sees 2 3 4.

A value holds 0 1 2 3 4 5 with shape (6,). You want it as 2 rows of 3 with the numbers in the same order. Which op?

One of the two ops from lesson 5.2 keeps every number where it is and only changes how you count.

reshape keeps the row-major order and changes the shape. permute reorders axes, and a rank-1 value has only one.

Grow a grid with a border of zeros

In lesson 3.4 a convolution window hung off the edge of its input, and you masked each bad read to zero by hand. It would be simpler to put the zeros around the input first. pad does that to a whole value in one op.

Take the grid %x = [[1 2] [3 4]], shape (2, 2). Predict before you read on.

pad %x [1 1 1 1] adds one row of zeros above, one below, one column on the left and one on the right. What is the result's shape, and what is at [1][1]?

Each axis gets one zero before and one after. Where does the old top left corner end up?

Rows go from 2 to 1 + 2 + 1 = 4, and so do columns. The old [0][0], which holds 1, moved one down and one right to [1][1].

The rule for pad %x [l0 r0 l1 r1 ...]:

  1. Read the list in pairs. Each axis gets two numbers: how many zeros go before it and how many after. For a grid that is [top bottom left right].
  2. Grow the shape. Each axis grows by its two numbers added together.
  3. Find a cell. Element [i][j] of the result is x[i - top][j - left] when that lands inside x. Everywhere else it is zero.

So pad %x [0 1 2 0] adds one row below and two columns on the left. The shape is (3, 4) and the rows are 0 0 1 2, 0 0 3 4 and 0 0 0 0.

A ring of zeros

Slot 0 holds a 2x2 f32 grid. Store the 4x4 grid with it in the middle and zeros all around into slot 1. The starter's grid is the right size with the zeros in the wrong place.

What the zero is, and what pad refuses (for the lab)

The new cells hold the dtype's zero: 0 for i32, 0.0 for f32 and false for bool. Cells copied from x are copied as they are, so a -0.0 or a nan inside x stays.

The list needs exactly two numbers per axis, in axis order, for any rank. Every pad amount must be at least 0. To cut, use shrink.

Cut a piece out

A convolution looks at one small window of its input at a time. So you need the opposite of pad: an op that keeps a piece and drops the rest. That op is shrink. Here is the padded grid from the last section, called %p:

0 0 0 0
0 1 2 0
0 3 4 0
0 0 0 0

shrink %p 0 0 [2 2] skips 0 rows and 0 columns, then keeps a window of shape (2, 2). What does the result hold?

Nothing is skipped, so the window starts at the top left corner. It is 2 rows tall and 2 columns wide.

The window covers rows 0 and 1 and columns 0 and 1: three border zeros and the 1. To get [[1 2] [3 4]] back, skip one row and one column: shrink %p 1 1 [2 2].

The rule for shrink %x o0 o1 [s0 s1]:

  1. Read the offsets. One per axis: how many rows to skip, then how many columns.
  2. Read the shape. The list at the end is the shape of the window, and of the result.
  3. Find a cell. Element [i][j] of the result is x[i + o0][j + o1].

This is the window from lesson 2.1, with one offset per axis. The first operand decides which one you get: memory gives a view you can store through and a value gives a new value. As in week 2, the window has to fit. An offset can be a computed number as long as your compiler can prove the fit with the bounds check from lesson 2.3.

Cut out the middle

Slot 0 holds a 4x4 f32 grid. Store its middle 2x2 piece (rows 1 and 2, columns 1 and 2) into slot 1. The starter cuts a window of the right shape from the wrong place.

Pad, then shrink, gives the original back

Pad by one on every side, then shrink at offsets 1 1 with the original shape, and you have the original again. A window anywhere else sees some of the zeros. That pair, a pad and a sliding window, is how lesson 5.4 builds a padded convolution.

Offsets that are computed: the exact fit rule (for the lab)

The offsets can be any i32 scalar expression. For every axis k, the offset's interval must satisfy lo ≥ 0 and hi + s_k ≤ x.shape[k]. It must be provably in range, the same interval check as week 2's views.

A window of 2 over 4 elements at offset mod %i 3 is fine: mod by 3 always gives a result in [0, 2], even for a negative %i, and 2 + 2 ≤ 4. At mod %i 4 the offset can reach 3, and 3 + 2 > 4, so it's rejected. A raw loaded %i could be anything, so it's rejected too.

A value shrink needs exactly one offset per axis of x, and the shape list has the same rank as x.

Repeat one row to fill a grid

A layer of a neural network adds the same row of numbers, the bias, to every row of a matrix. But add wants two operands of one shape. So the single row has to become a grid first, with the row repeated. In lesson 4.2, expand repeated one number to fill a vector. Now it repeats a row.

%r has shape (1, 3): one row holding 10 20 30. What is expand %r [2 3]?

The row axis has size 1 and must become 2. The op repeats. It does not fill with zeros.

The axis of size 1 grows to 2 by repeating the only row there is. The column axis already has size 3, so it stays as it is.

The rule for expand %x [d0 d1]:

  1. Keep the rank. The new shape has as many axes as x.
  2. Grow only size-1 axes. (3, 1) can become (3, 4). An axis of size 2 can't become 3.
  3. Find a cell. Every axis that had size 1 is read at 0. In (3, 1) grown to (3, 4), element [i][j] reads x[i][0].

A plain vector of shape (4,) has no size-1 axis to grow. Give it one with reshape: (4,) becomes (1, 4), and that expands to (3, 4).

Add a bias to every row

Slot 0 holds a 3x4 f32 matrix and slot 1 a bias of 4 values. Store y[i][j] = x[i][j] + b[j] into slot 2. The starter adds b[0] everywhere.

The scalar case and the shapes expand refuses (for the lab)

Week 4's form still works: a scalar expands to any shape, of any rank. Every other operand must have the same rank as the new shape, and each axis must either keep its size or have size 1. The new shape can't be empty and every size in it must be at least 1.

So expand of a (2,) value to [3] is rejected, and the oracle says: "can't expand [2] to [3]: same rank, and only size-1 axes grow". A (4,) value to [3 4] is rejected too, because the rank would change.

Join two rows into a grid

Sometimes the pieces arrive apart: two rows loaded from two buffers, and you want one grid. In week 1, stack 1 2 3 joined three scalars into a vector. This week it joins values of any shape.

%a is [1 2 3] and %b is [4 5 6], both of shape (3,). What shape is stack %a %b?

In week 1, stacking three scalars of shape () gave shape (3,). The count went in front.

stack puts one new axis in front, sized by the number of operands. The result is [[1 2 3] [4 5 6]], with %a as row 0.

The rule for stack %a %b ...:

  1. Check the shapes. Every operand must have the same shape.
  2. Add an axis in front. With n operands of shape (2, 2), the result has shape (n, 2, 2).
  3. Find a cell. The first index picks the operand and the rest index into it. index on the new axis gets each operand back.

Two rows, one grid

Slots 0 and 1 each hold a row of 3 f32 values. Store the 2x3 grid with slot 0's row on top into slot 2. Both rows are loaded for you. The starter's grid %g is all zeros: replace that line.

Work out shapes and reads in code

So far you did each rule by eye. Your compiler has to do them for every movement op in a program: work out the result's shape, and later (lesson 5.5) work out which cell of the input each output cell reads. Here are the four shape rules side by side.

Padded shape and expanded read

Write pad_shape shape pads, the shape of pad x [l0 r0 l1 r1 ...] when x has shape shape. Then write expand_src shape idx, the index into x that output index idx reads after an expand of an x with shape shape. Each starter returns one of its arguments unchanged.

All four rules in one table, for when you write the lab

The element column says what the result holds at index (i0, ..., ik).

opoperandsresult shapeelement
pad x [l0 r0 l1 r1 ...]a rank-r value, r pairseach axis grows by l + rx[i - l] where every axis is inside, else zero
shrink x o0 ... [s0 ...]a rank-r value, r i32 scalar offsetsthe listx[i0 + o0, ..., ik + ok]

stack a0 ... a(n-1)values of one shape(n,) then that shapea_i0[i1, ...]

None of the four takes attributes. Bounds analysis does not look inside them: the result of a pad, a value shrink or an expand is widened to the full range of its dtype.

Memory stays flat this week. Buffers and memory views are still rank 0 or 1, so you load a rank-1 value, move it around with these ops, and reshape back to rank 1 before a store.

Check yourself

What shape is pad %x [1 0 0 2] for a (2, 2) %x?

The pairs are per axis: (1, 0) for rows, (0, 2) for columns.

Rows grow by 1 + 0 to 3, columns by 0 + 2 to 4.

%x = [[0 1] [2 3]]. What is element [2][1] of pad %x [1 0 0 2]?

Subtract the left pads: [2 - 1][1 - 0].

It reads x[1][1], which is 3. Element [0][0] would be a padding zero, and so would any column past 1.

%c has shape (3, 1) and holds 0, 1, 2. What is element [2][3] of expand %c [3 4]?

The size-1 axis is read at 0, whatever the output index is.

It reads c[2][0], which is 2. Every column of row 2 is 2.

%a = stack 1 2. Is expand %a [3] valid?

Which axes can expand grow?

An axis of size 2 can't become 3. The oracle says: "can't expand [2] to [3]: same rank, and only size-1 axes grow".

%v has shape (4,) and %i is a loaded i32. Which shrink %v %o [2] is valid?

The rule is lo ≥ 0 and hi + 2 ≤ 4. What's each offset's interval?

mod %i 3 is in [0, 2], even for a negative %i, and 2 + 2 ≤ 4. With mod ... 4 it can reach 3, and a raw load can be anything, so both are rejected. Offsets can be symbolic as long as they're provable.

What shape is stack %x %x for a (2, 2) %x? Answer like 2 3.

stack puts one new axis in front, sized by the number of operands.

Two operands of shape (2, 2) give (2, 2, 2).
