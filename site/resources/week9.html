Week 9 study guide

Week 9 makes GPU kernels fast without changing a bit: each thread keeps its own working set in registers, and warps hand 16×16 tile products to the tensor cores. With those two, the week builds a GEMM, a convolution and flash attention. This page recaps the week, collects the rules worth memorizing, and walks the lab one step at a time.

The week in one page

9.1 Registers and register tiles

A thread that makes a 4×4 piece of C does 16 multiply-adds for 8 loads, four times week 8's reuse. Its sums live in an alloc at t·S + e. When every access to an alloc is inside a local loop at that shape, one S throughout, it's per-thread: still shared memory in meaning, but render-cuda may give each thread its own array, which is registers when every e is a literal. A later phase reading another thread's slice keeps it shared.

9.2 Fast GEMMs

A BM×BN tile does BM·BN / (BM + BN) multiply-adds per value loaded, at every level of the memory ladder. The roofline: time is at least the larger of arithmetic time and memory time. Coalesced loads (neighbor threads, neighbor addresses), enough warps per SM, vector loads, double buffering and conflict-free shared memory do the rest.

9.3 Tensor cores

A warp-wide instruction multiplies 16×16 tiles, 4,096 multiply-adds. Float tensor cores don't round like the interpreter, so .uir uses i8 inputs and an i32 accumulator, which are exact. mma C A B lda= ldb= ldc= is an effect like a store. axis=warp is a phase run by whole warps. Tiles start 32-byte aligned, which tile-major storage makes easy.

9.4 Convolutions

A convolution is a GEMM of the im2col matrix (each output pixel's window, as a row) and the filters. Writing im2col out copies inputs up to 9 times, so fast kernels compute it on the fly. The test kernel stages three input rows and 8 filters in shared memory and keeps 8 sums per thread in registers. Its speed is limited elsewhere: measure before optimizing.

9.5 Flash attention

Keep a running max m and sum l, and rescale by exp(m_old - m_new) when the max grows. Then attention streams keys and values through shared memory and never writes the S×S scores. Each thread's query row, sums and running max are per-thread memory. Flash gives the same math as the obvious version, not the same bits.

9.6 Lab

The suite has 53 tests: run tests for i8, mma, warp loops and their rules, r_ tests for the CPU render, c_ tests for CUDA, and four GPU speed tests. Weeks 1 to 8 must stay green.

Mistakes people make

Each of these is a bug that was planted in the reference compiler to prove the suite catches it. The week 9 test guide lists every test with the bugs known to fail it.

  1. Overwriting C instead of adding to it. Caught by mma_adds_to_c.
  2. Mixing up the strides, or reading B by columns. Caught by mma_strides and mma_one_tile.
  3. Saturating a cast to i8, or rendering it unsigned. Caught by i8_cast_wraps and c_i8_kernel.
  4. Launching a warp loop of n as n threads. Caught by the c_ tests with warps.
  5. Putting memory read across threads in registers. Caught by c_shared_not_per_thread.
  6. Leaving per-thread memory in shared memory. The bits stay right. Caught by the speed tests on a GPU.
  7. Letting a store overwrite A before an mma reads it. Caught by r_mma_reads_before_overwrite.
  8. Missing an mma rule. Alignment, bounds, an mma outside a warp loop, or overlapping warp tiles. Caught by err_mma_a_misaligned, err_mma_out_of_bounds, err_mma_in_local_loop and err_warp_tiles_overlap.

Stuck on the lab?

Build in this order, and don't move on until the check passes.

  1. i8. Done when this program's slot 1 is -56 127 -24: 
    %x = buffer 3 dtype=i32 slot=0 data=[200 -129 1000]
%y = buffer 3 dtype=i8 slot=1
%r = range 3
%xv = shrink %x %r shape=[]
%v = load %xv
%c = cast %v dtype=i8
%yv = shrink %y %r shape=[]
%s = store %yv %c
%e = end %s %r
%y1 = after %y %e
  2. mma in run. Execute it, check its rules, and order it like a store into C and a load of A and B. Done when the mma_* and err_mma_* run tests pass.
  3. Warp loops. Where they may be, the block size, and the tile's digits. Done when every run test passes.
  4. The CPU render. Done when the r_ tests pass.
  5. render-cuda. First wmma, then per-thread arrays. Done when every c_ test passes in the emulator, then on a GPU with the speed tests.

Check yourself

Thread t stores acc[4t + e] for e in 0..3 in phase 1, and phase 2 loads acc[4t + 3]. Is acc per-thread?

Whose slice does each access touch?

Both accesses are 4t plus something from 0 to 3, so each thread only touches its own 4 elements.

An mma's A tile starts at element 48 of an i8 buffer. Valid?

The tensor cores load from 32-byte boundaries.

48 bytes isn't a multiple of 32. Tile-major storage puts every tile at a multiple of 256.

A kernel's warp loop has a bound of 4. How many threads must its local loops have?

A warp is 32 threads.

4 · 32 = 128: one block size per kernel.
